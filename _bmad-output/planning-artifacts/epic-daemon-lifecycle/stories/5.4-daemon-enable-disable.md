# Story 5.4 — `chirp daemon enable | disable`: LaunchAgent install/uninstall via `chirpd/launchd.py`

- **Status:** done
- **Epic:** [EPIC-DAEMON-LIFECYCLE](../epic.md)
- **Depends on:** 5.3 (Typer subapp file and command-helper patterns); EPIC-CHIRPD-CORE (`chirpd` console script registered in `pyproject.toml [project.scripts]`)
- **Blocks:** 5.6 (Typer registration); EPIC-INIT-AND-MIGRATION's LaunchAgent-opt-in story (which imports `install_launch_agent()` from this story's `chirpd/launchd.py`)

## User story

As Sam, I want one command — `chirp daemon enable` — that installs a LaunchAgent so the daemon starts at login, survives crashes (launchd restarts on non-zero exit), and stays out of my way the rest of the time. I want one command — `chirp daemon disable` — to fully reverse that, leaving no plist artifacts behind. I want both commands to fail loudly with `launchctl`'s actual error message if something goes wrong, not silently leave my system in a half-configured state.

## Context

This is the LaunchAgent half of the daemon-lifecycle epic. The architecture (§ Daemon Lifecycle Integration with launchd) specifies the plist contents and the install dance:

1. Write `~/Library/LaunchAgents/com.chirp.chirpd.plist` via `plistlib`.
2. Run `launchctl load <plist>`.
3. Verify the agent is loaded via `launchctl list | grep com.chirp.chirpd`.

`disable` reverses this: `launchctl unload <plist>`, then delete the plist file.

The plist's `ProgramArguments` is the absolute path to the `chirpd` console script, resolved via `shutil.which("chirpd")` at the time `enable` is run. If the user later relocates their Python environment (deletes the venv, switches to a new uv install), the plist points at a stale path; the user re-runs `enable` to refresh it. This is intentional — there's no good way to make the plist self-healing without inventing a separate daemon-of-daemons.

**Critical and counterintuitive detail about `KeepAlive`:** the plist uses `<key>KeepAlive</key><dict><key>SuccessfulExit</key><false/></dict>`. This means launchd will restart the daemon when it exits **non-zero** (crash), but **not** when it exits **zero** (intentional). The version-mismatch immediate-exit (per PRD FR14 and the architecture's handshake state machine) is an `exit(0)` — intentional. launchd will NOT respawn the daemon after a version mismatch. The user's next CLI invocation lazy-spawns the new version. This is the right behavior because the post-mismatch daemon is *running the wrong code*; lazy-spawn picks up the new code from PATH.

This story also delivers `chirpd/launchd.py` — a small module with two **reusable** functions (`install_launch_agent()` and `uninstall_launch_agent()`) plus an introspection helper (`is_launch_agent_installed()`). EPIC-INIT-AND-MIGRATION's `chirp init` story will import these directly from `chirpd/launchd.py`. The Typer command bodies in `llm/cli/daemon.py` are thin wrappers — they handle CLI argument parsing and exit codes, but the real work lives in `chirpd/launchd.py`.

## Acceptance criteria

- **AC-1** `chirpd/launchd.py` exists with the following public surface:

  ```python
  LAUNCH_AGENT_LABEL: str = "com.chirp.chirpd"
  LAUNCH_AGENT_PLIST_PATH: Path = Path.home() / "Library" / "LaunchAgents" / f"{LAUNCH_AGENT_LABEL}.plist"
  LAUNCH_AGENT_LOG_PATH: Path = Path.home() / "Library" / "Logs" / "chirp" / "chirpd.log"

  class LaunchAgentError(Exception): ...
  class LaunchAgentAlreadyInstalled(LaunchAgentError): ...
  class LaunchAgentNotInstalled(LaunchAgentError): ...
  class LaunchctlFailed(LaunchAgentError):
      def __init__(self, command: list[str], returncode: int, stderr: str): ...

  def install_launch_agent(*, force: bool = False) -> Path:
      """Resolve chirpd via shutil.which, generate plist, run launchctl load.
      Returns the plist path on success.
      Raises LaunchAgentAlreadyInstalled if a plist is already present and force=False.
      Raises LaunchctlFailed if launchctl reports non-zero.
      """

  def uninstall_launch_agent() -> None:
      """Run launchctl unload, remove the plist file.
      Raises LaunchAgentNotInstalled if no plist is present.
      """

  def is_launch_agent_installed() -> bool:
      """True iff the plist file exists AND launchctl list reports the label."""

  def _build_plist(chirpd_path: Path) -> dict:
      """Plist payload for plistlib.dump. Private but tested directly."""
  ```

  Implements the structural surface for FR43, FR44. The module is importable on non-Darwin (no top-level `launchctl` calls or platform-only imports); functions raise `LaunchAgentError("not supported on non-Darwin")` when called off-platform.

- **AC-2** **Plist contents** (the dict produced by `_build_plist`):

  ```python
  {
      "Label": "com.chirp.chirpd",
      "ProgramArguments": ["<resolved absolute path to chirpd>"],
      "RunAtLoad": True,
      "KeepAlive": {"SuccessfulExit": False},
      "StandardOutPath": str(LAUNCH_AGENT_LOG_PATH),
      "StandardErrorPath": str(LAUNCH_AGENT_LOG_PATH),
      "EnvironmentVariables": {
          "PATH": "<user's PATH at install time>",
          # If HF_HOME is set in the user's environment at install time, propagate it.
          # If not, omit the key entirely.
      },
      "ProcessType": "Background",
  }
  ```

  Notes:
  - `RunAtLoad: True` → starts at login (and on first `launchctl load`).
  - `KeepAlive: {SuccessfulExit: False}` → restart on non-zero exit only. **Documented in the module docstring with the counterintuitive version-mismatch interaction** (the daemon exits 0 on version mismatch, launchd does NOT respawn, the next CLI invocation lazy-spawns the new version).
  - `StandardOutPath` / `StandardErrorPath` point at the same log file the Python logging handler writes to (story 5.1). Belt-and-braces — if the Python handler fails, launchd still captures stderr/stdout.
  - `PATH` is captured at install time from `os.environ["PATH"]`. The LaunchAgent runs with a minimal launchd-default PATH otherwise, which can break `mlx-lm`'s subprocess invocations.
  - `HF_HOME` is propagated only if the user has it set. This matches FR38 (HF cache reuse honors `HF_HOME`).
  - `ProcessType: Background` is the macOS-recommended hint for long-running background processes; affects QoS class.

- **AC-3** **`install_launch_agent(*, force=False)` flow:**
  1. Verify `sys.platform == "darwin"`; raise `LaunchAgentError("LaunchAgent install is macOS-only")` otherwise.
  2. Check `LAUNCH_AGENT_PLIST_PATH.exists()`. If True and `force=False`, raise `LaunchAgentAlreadyInstalled(str(LAUNCH_AGENT_PLIST_PATH))`. The CLI command surfaces this with a clear "already installed; pass --force to reinstall" message.
  3. Resolve `chirpd_path = shutil.which("chirpd")`. If None, raise `LaunchAgentError("chirpd binary not found on PATH — is chirp installed correctly?")`.
  4. Build the plist dict via `_build_plist(Path(chirpd_path))`.
  5. Create `LAUNCH_AGENT_PLIST_PATH.parent` (`~/Library/LaunchAgents/`) if missing.
  6. Write the plist via `plistlib.dump(payload, fp, fmt=plistlib.FMT_XML)`. Atomic write — write to `<path>.tmp`, then `os.replace` to final.
  7. If `force=True` and the plist was already present, also run `launchctl unload <plist>` first (best-effort; ignore non-zero exit since the agent may not actually be loaded).
  8. Run `subprocess.run(["launchctl", "load", "-w", str(LAUNCH_AGENT_PLIST_PATH)], capture_output=True, text=True, timeout=10)`. On non-zero exit, raise `LaunchctlFailed(command=..., returncode=..., stderr=...)`.
  9. Run `launchctl list <label>` (verification probe) and parse: non-zero exit or empty output → raise `LaunchctlFailed`. The `-w` flag on `load` marks the agent as enabled (persists across reboots).
  10. Return `LAUNCH_AGENT_PLIST_PATH`.

  Implements FR43, NFR-R2 (LaunchAgent crash recovery via `KeepAlive`).

- **AC-4** **`uninstall_launch_agent()` flow:**
  1. Verify `sys.platform == "darwin"`; raise `LaunchAgentError("...")`.
  2. Check `LAUNCH_AGENT_PLIST_PATH.exists()`. If False, raise `LaunchAgentNotInstalled(str(LAUNCH_AGENT_PLIST_PATH))`.
  3. Run `subprocess.run(["launchctl", "unload", "-w", str(LAUNCH_AGENT_PLIST_PATH)], capture_output=True, text=True, timeout=10)`. On non-zero exit, raise `LaunchctlFailed` (the plist is still on disk; the user can retry or manually remove).
  4. Remove the plist file via `LAUNCH_AGENT_PLIST_PATH.unlink()`.
  5. Run `launchctl list <label>`; expect non-zero exit (agent should be gone). If zero exit (still loaded), raise `LaunchctlFailed` with a clear message.

  Implements FR44.

- **AC-5** **`is_launch_agent_installed()` flow:**
  - Returns `False` immediately if `sys.platform != "darwin"`.
  - Returns `False` if `LAUNCH_AGENT_PLIST_PATH.exists()` is False.
  - Otherwise runs `launchctl list <label>` (no `grep` — `launchctl list <label>` directly returns the agent's plist as text, or non-zero if absent). Returns True iff exit code 0.
  - Used by `chirp daemon status` (already-implemented story 5.2 may extend its output to mention LaunchAgent state — see "Handoff" below) and by EPIC-INIT-AND-MIGRATION's `chirp init` prompt.

- **AC-6** **CLI command: `chirp daemon enable`** (in `llm/cli/daemon.py`):
  - Signature: `def enable(force: bool = typer.Option(False, "--force", help="Reinstall even if a LaunchAgent is already present."), json_output: bool = typer.Option(False, "--json", help="..."))`.
  - Calls `chirpd.launchd.install_launch_agent(force=force)`.
  - On success: prints `LaunchAgent installed at <plist_path>\nDaemon will auto-start at login.` to stdout. Exit 0.
  - On `LaunchAgentAlreadyInstalled`: prints `LaunchAgent already installed at <plist_path>. Pass --force to reinstall.` to stderr. Exit 1.
  - On `LaunchctlFailed`: prints a clear message including the `launchctl` stderr, e.g.:
    ```
    launchctl load failed (exit 5):
      Load failed: 5: Input/output error
    plist at: ~/Library/LaunchAgents/com.chirp.chirpd.plist
    ```
    Exit 1.
  - On `LaunchAgentError` (generic): prints the exception message; exit 1.
  - Implements FR43.

- **AC-7** **CLI command: `chirp daemon disable`** (in `llm/cli/daemon.py`):
  - Signature: `def disable(json_output: bool = typer.Option(False, "--json", help="..."))`.
  - Calls `chirpd.launchd.uninstall_launch_agent()`.
  - On success: prints `LaunchAgent removed.\nDaemon will no longer auto-start at login.` to stdout. Exit 0.
  - On `LaunchAgentNotInstalled`: prints `LaunchAgent is not installed; nothing to do.` to stderr. Exit 0 (**idempotent** — disable on a clean machine is a no-op, not an error).
  - On `LaunchctlFailed`: same clear-stderr-passthrough as `enable`. Exit 1.
  - Implements FR44.

## Implementation tasks

1. **Create `chirpd/launchd.py`.** Module surface per AC-1. Use the exception hierarchy as the typed error surface; the CLI layer catches and renders. Keep the module pure-Python with no third-party deps; `plistlib` and `subprocess` are stdlib.

2. **Implement `_build_plist`.** Pure function. Easiest to test. Two env-var conditionals (`HF_HOME` propagation, PATH capture) are the only branching logic.

3. **Implement `install_launch_agent`.** Atomic write via `.tmp` + `os.replace`. `subprocess.run` with `capture_output=True, text=True, timeout=10`. On non-zero, construct `LaunchctlFailed(command=..., returncode=..., stderr=...)`. The `-w` flag on `launchctl load` is critical — without it, the agent is loaded but not marked as enabled, and `launchctl list` shows it but a reboot drops it.

4. **Implement `uninstall_launch_agent`.** Note the order: `launchctl unload` first, then delete the plist file. If `unload` fails, the plist stays on disk (matches user expectation — "if something went wrong, my system is still in a state I can inspect"). The verification `launchctl list` afterward catches the "unload returned 0 but the agent is still listed" macOS edge case.

5. **Implement `is_launch_agent_installed`.** Two checks: plist on disk AND `launchctl list <label>` returns 0. Both must be true.

6. **Update `LOGFMT_OPTIONAL_FIELDS`** in `chirpd/logging_setup.py` to include `chirpd_path` (used by the enable log line). Same approach as story 5.3 adding `result`.

7. **Add the CLI commands** to `llm/cli/daemon.py`. ~30 lines each. Use the `try/except LaunchAgent*` pattern to map to user-facing messages and exit codes. JSON output mirrors story 5.3's pattern.

8. **Write the tests.** `tests/chirpd/test_launchd.py` is mostly subprocess mocking + tmp-path plist writes. `tests/llm/test_cli_daemon.py` extension is straightforward — patch the `chirpd.launchd` functions, assert the CLI surfaces them correctly.

9. **Document the version-mismatch + KeepAlive interaction** in the module docstring. This is the single most non-obvious aspect of the design; readers will likely come here looking for "why isn't my daemon respawning?" answers. The docstring is the right place to explain that this is correct.

10. **Manual testing** per AC-15. The unit tests cover the seams; the real macOS verification has to be hand-driven on a real Mac. Track in the PR description.

## Dev notes

- **Why `plistlib` rather than templating an XML string.** Less error-prone (plistlib handles escaping); the macOS plist format is technically version-stable but has subtle quirks; let Apple's reference implementation handle it.
- **Why capture `os.environ["PATH"]` rather than using launchd's default.** launchd's default `PATH` for user agents is something like `/usr/bin:/bin:/usr/sbin:/sbin` — missing Homebrew, missing pyenv shims, missing `uv`'s tool bin. The `chirpd` script may need to invoke other tools (or load Python deps from a location dependent on the user's PATH). Capturing PATH at install time mirrors how the user's interactive shell finds `chirpd` in the first place.
- **Why not use `launchctl bootstrap` instead of `launchctl load`.** `bootstrap` is the macOS 10.10+ replacement for `load`, and is technically "preferred." But `load -w` continues to work reliably across macOS 13-15+, has wider documentation, and matches the `chirpd` install scripts most users have seen in other tools. Revisit if `load` is deprecated in a future macOS release.
- **Why `KeepAlive` is a dict, not a bool.** A bool `KeepAlive: true` means "always restart, including on `exit(0)`," which would defeat the version-mismatch lazy-respawn-by-CLI design. The dict form `{SuccessfulExit: false}` means "restart only if exit is non-zero" — exactly right.
- **Why test the "plist stays on disk if unload fails" branch.** Production failure mode: user runs `chirp daemon disable`, `launchctl unload` fails for some reason, and the user re-runs `disable`. We want the second run to either succeed or report the same error consistently, not silently get into a half-state. Keeping the plist on disk on failure means `is_launch_agent_installed()` still returns True, and the user can debug from there.
- **Why we don't `sudo` anything.** LaunchAgent paths live in `~/Library/LaunchAgents/` — the user's own home directory. No elevated permissions required. (`LaunchDaemons` would need `sudo` — but we're not using those.)
- **Why no system-wide install variant.** Out of scope per the epic's §8. Single-user only.

## Handoff to story 5.6 and to EPIC-INIT-AND-MIGRATION

- **For story 5.6:** `daemon_app` now hosts six commands (`status`, `start`, `stop`, `restart`, `enable`, `disable`). Story 5.5 adds `logs`; 5.6 wires the lot into `chirp/cli.py` as a hidden subgroup.
- **For EPIC-INIT-AND-MIGRATION:** the `chirp init` flow's LaunchAgent-opt-in step imports `install_launch_agent` and `is_launch_agent_installed` directly from `chirpd.launchd`. Do NOT shell out to `chirp daemon enable` from `chirp init` — call the function. The contract is:
  - `is_launch_agent_installed()` → use to skip the prompt if already set up.
