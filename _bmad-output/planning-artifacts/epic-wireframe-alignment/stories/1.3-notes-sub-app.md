# Story 1.3 — Merge `note` into `notes` sub-app (`view` / `edit` / `delete <id>`)

- **Status:** Done
- **Epic:** [EPIC-WF-ALIGN](../epic.md)
- **Depends on:** 1.1, 1.2
- **Blocks:** —

## User story

As a Chirp user, I want `chirp notes` to be the one entry point for listing, viewing, editing, and deleting notes — addressed by a stable note **ID** shown in the list — and I want to tag notes with comma-separated labels so I can filter the list by tag.

## Context

Today `chirp notes` (cli.py:394) lists notes and prints a hint `chirp note [NAME]`, while `chirp note` (cli.py:474) is a separate top-level command that creates/edits one note by name. This story collapses them: bare `chirp notes` lists, and `notes view/edit/delete <id>` act on the stable ID.

The **ID** is a short stable identifier derived from the slug — it does NOT re-number when notes are added or deleted. Use the slug itself (e.g. `standup-notes-2026-04-20`) as the canonical ID. The list view shows a short-form ID column (first 8 chars of a hash of the slug, or simply the slug truncated — implementer's call, but it must be stable across invocations and unambiguous within the current notes set).

Tags are stored as an array in each note's `meta.toml` (`tags = ["meeting", "pricing"]`). `chirp notes --tag <t>` filters the list to notes containing that tag. `--tag` accepts comma-separated values which apply as an AND filter.

## Acceptance criteria

- **AC-1** `chirp notes` with no subcommand shows a table with columns: `id`, `title`, `date`, `length`, `tags`. Rows are sorted newest-first.
- **AC-2** The post-table hint prints:
  ```
  › chirp notes view <id>      · open a note read-only
  › chirp notes edit <id>      · edit a note
  › chirp notes delete <id>    · delete a note
  › chirp notes --tag meeting  · filter by tag
  ```
- **AC-3** `chirp notes view <id>` resolves `<id>` against the slug (full or unambiguous prefix) and opens `ManualNoteEditor` in view (read-only) mode on the `notes.md` inside that slug folder.
- **AC-4** `chirp notes edit <id>` resolves `<id>` the same way and opens the editor in edit mode. On save, `<slug>/notes.md` is rewritten and (if `auto_index`) re-indexed.
- **AC-5** `chirp notes delete <id>` prompts `Delete "<title>"? This removes the entire <slug>/ folder. [y/N]` and, on confirm, `shutil.rmtree(<slug>)` the folder and removes the note from the index/manifest.
- **AC-6** An unknown or ambiguous `<id>` prints `[red]✗ no note matching '<id>'[/red]` (or `[red]✗ '<id>' matches <n> notes — be more specific[/red]` for prefix ambiguity) and exits 1. The literal standalone `chirp note [NAME]` command from the old CLI is gone — string-based creation is no longer a subcommand of `notes`.
- **AC-7** `chirp notes --tag <t>` filters the table to notes whose `meta.toml` `tags` array contains `<t>`. `--tag "a,b"` applies as AND (must contain both). Filter echoes above the table: `Your notes · 3 of 14 · tag: meeting`.
- **AC-8** The `tags` column in the list renders comma-separated tag names, dim-styled. Empty tag lists render as a single `—`.
- **AC-9** `uv run pytest` covers: list hint text, view resolving by full id, view resolving by prefix, unknown id, ambiguous prefix, delete with confirm=yes, delete with confirm=no, `--tag` filter AND semantics.

## Implementation tasks

1. **Restructure as Typer sub-app** in `chirp/cli.py`:
   ```python
   notes_app = typer.Typer(help="Browse, view, edit, or delete your notes")
   app.add_typer(notes_app, name="notes", rich_help_panel=MAIN_PANEL)

   @notes_app.callback(invoke_without_command=True)
   def notes_default(ctx: typer.Context):
       if ctx.invoked_subcommand is None:
           _list_notes()
   ```
2. **Extract `_list_notes()`** — move the current body of `notes_list` (cli.py:394) into a helper that both the callback and a hypothetical future caller can use.
3. **Add `_resolve_note(note_id: str) -> NoteRecord`** — match `note_id` against slugs exactly; if no exact match, match as a unique prefix. Raise `NoteNotFound` on zero matches and `AmbiguousNoteId` on 2+ matches so the commands print consistent errors.
4. **Add three subcommands** under `notes_app`: `view`, `edit`, `delete`. Each takes a single positional `note_id: str`. `view` and `edit` delegate to `ManualNoteEditor` (read_only / editable modes respectively).
5. **Add `--tag` option** to the `notes` callback — `typer.Option(None, "--tag", help="Filter by tag (comma-separated for AND)")`. Split on `,`, strip whitespace, filter `list_notes` by `record.tags` superset match.
6. **Update the post-table hints** to the text in AC-2.
7. **Delete logic** — in `delete`, call `typer.confirm("Delete ...")`, then `shutil.rmtree(record.dir)`, then remove the note from the indexer (reuse whatever `IndexManager` exposes — add a `remove_note(path)` helper if needed).
8. **Extend `NoteRecord`** (from story 1.1) with `tags: list[str]` read from `meta.toml`. Default to `[]` when absent.
9. **Tests** — mock `list_notes` to return a known sequence, drive each subcommand with `typer.testing.CliRunner`.

## Dev notes

- `ManualNoteEditor` at `notes/note_editor.py:60` already accepts `readonly=` — reuse it rather than adding a new flag.
- The ID is the slug itself (e.g. `standup-notes-2026-04-20`). Prefix matching keeps the CLI ergonomic for short unambiguous fragments (`chirp notes view standup` works when there's only one `standup-*`).
- Slug collisions within a day get `-2`/`-3` suffixes from `slugify` (story 1.1), so prefix `standup` may be ambiguous — `AmbiguousNoteId` surfaces that cleanly.
- Tags are authored by the user at `chirp record` time (story 1.6 adds the prompt) and persisted to `meta.toml` as `tags = ["meeting", "pricing"]`.
