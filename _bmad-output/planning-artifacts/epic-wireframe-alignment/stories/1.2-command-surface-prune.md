# Story 1.2 — Command-surface prune to 7 visible commands

- **Status:** Done
- **Epic:** [EPIC-WF-ALIGN](../epic.md)
- **Depends on:** 1.1
- **Blocks:** 1.3

## User story

As a Chirp user opening `chirp --help` for the first time, I want to see exactly the 7 commands the wireframe specifies — `record`, `transcribe`, `notes`, `ask`, `search`, `init`, `about` — under one panel titled "Commands", so that the CLI surface matches the locked design and nothing feels like an escape hatch or half-finished experiment.

## Context

The current CLI defines 17 top-level commands spread across three help panels (`MAIN_PANEL`, `SETUP_PANEL`, `INFO_PANEL` at `chirp/cli.py:34-36`). Several are duplicates or have been folded into other commands since the wireframe was locked. A handful are diagnostics that should remain reachable but not appear in `--help`.

## Acceptance criteria

- **AC-1** `uv run chirp --help` shows exactly these 7 commands, in this order: `record`, `transcribe`, `notes`, `ask`, `search`, `init`, `about`.
- **AC-2** All 7 commands appear under a single panel whose header reads "Commands" (or no panel header — whatever Typer renders when `rich_help_panel` is unset is acceptable if the visual matches the wireframe).
- **AC-2a** The `--help` output renders the A1 chrome verbatim:
  - Tagline directly under `Usage: ...` line: `Chirp · AI notes for your terminal.`
  - Footer line below the Commands panel: `run \`chirp COMMAND --help\` for details`
- **AC-2b** Each surviving command's `help=` string matches A1 exactly:
  - `record` → `"Capture audio to a new note"`
  - `transcribe` → `"Turn audio into text + summary"`
  - `notes` → `"Browse, view, edit notes"`
  - `ask` → `"Chat with your notes"`
  - `search` → `"Keyword search"`
  - `init` → `"First-run setup & model picker"`
  - `about` → `"Show the bird 🐦"`
- **AC-3** The constants `SETUP_PANEL` and `INFO_PANEL` are removed from `chirp/cli.py`. `MAIN_PANEL = "Commands"` remains if still referenced.
- **AC-4** The following commands are **deleted** (source fully removed, no re-export):
  - `generate` (cli.py:854) — functionality folded into transcribe pipeline step 4.
  - `transcribe-and-generate` (cli.py:893) — `transcribe` already does both.
  - `note` (cli.py:474) — becomes `notes edit` in story 1.3.
  - `stats` (cli.py:931) — counts that are still useful move into `about`'s info block.
  - `setup` (cli.py:1132) — BlackHole audio-routing guide moves into `init` Phase 2 (story 1.5).
  - `test` (cli.py:1242) — overlaps with `init --recheck`.
  - `version` (cli.py:1324) — shown at the bottom of `about` frame 3.
- **AC-5** The following commands remain callable but are hidden from `--help` (`hidden=True`):
  - `devices` (cli.py:1054) — debugging audio devices.
  - `config` (cli.py:958) — inspect/edit raw config.
  - `index` (cli.py:921) — maintenance rebuild of Chroma.
- **AC-6** `uv run chirp devices` / `chirp config` / `chirp index` still execute and behave as before (smoke test).
- **AC-7** `uv run chirp generate` and the other deleted command names return Typer's "no such command" error, not a stack trace.
- **AC-8** Any useful count previously in `stats` (total notes, total minutes recorded, index size) is surfaced in `about`'s info block — or explicitly dropped if it adds clutter.
- **AC-8a** `about` frame 3 info block lists the currently configured models, read from `~/.chirp/config.toml`:
  ```
  • llm:   <settings.models.llm>
  • index: <settings.models.embed>
  ```
  Both lines render dim-styled, directly above the existing `made with ♥ by ...` / repo-URL lines. If the config file is missing or a model key is empty, render that line as `<not configured — run chirp init>` and keep the frame width stable.
- **AC-9** `uv run pytest` passes; any test that called a deleted command is removed or rewritten to use the surviving equivalent.
- **AC-10** `uv run ruff check .` reports no unused imports left over from the deletions.

## Implementation tasks

1. **Delete command functions** in `chirp/cli.py`:
   - Remove the 7 command functions and their decorators listed in AC-4.
   - Remove any now-orphaned imports at the top of the file.
2. **Hide diagnostics** — on `devices`, `config`, `index`, pass `hidden=True` to `@app.command(...)`.
3. **Collapse panels** — delete `SETUP_PANEL` and `INFO_PANEL` constants. Either rename `MAIN_PANEL` to `"Commands"` (it already has this value) or drop `rich_help_panel=...` from the remaining decorators entirely. Pick whichever yields the cleaner `--help`.
4. **Migrate `stats`-relevant counts** into `chirp/about.py`'s info block — only the ones that read well in the 3-frame animation. Total notes count (`len(list_notes(notes_root))`) is the obvious keeper.
5. **Add model info lines to `about`** — in `chirp/about.py` frame 3, read `ChirpSettings` and render `• llm: <models.llm>` and `• index: <models.embed>` above the authorship lines. Guard against missing config.
6. **Migrate `version`** — confirm the version string is already shown at the bottom of `about` frame 3; if not, add it.
7. **Remove dead tests** — `rg "def test_.*(stats|setup|test_cmd|version|generate|transcribe_and_generate)" tests/` and clean up.
8. **Update docstrings** in the surviving commands if they reference removed commands (e.g. "see `chirp setup`").
9. **Update the README** if it lists commands — adjust to the 7-command surface.

## Dev notes

- Leaving `devices`/`config`/`index` hidden is intentional — they're useful for debugging and scripts. Typer supports `hidden=True` on `@app.command`.
- The notes-list post-hint text "`chirp note [NAME]`" at `chirp/cli.py:453` is fixed in story 1.3, not here.
- Don't touch the `notes` command body in this story — story 1.3 rewrites it as a sub-app. This story only removes the separate `note` command and its friends.
