# Story 1.4 — Queue-driven `transcribe` with 5-step checklist

- **Status:** Done
- **Epic:** [EPIC-WF-ALIGN](../epic.md)
- **Depends on:** 1.1
- **Blocks:** —

## User story

As a Chirp user who just recorded 3 meetings back-to-back, I want to type `chirp transcribe` and walk away while every untranscribed recording is processed FIFO through a clear 5-step checklist per note, so that I can see exactly which stage the pipeline is on, know when each note finishes, and recover the rest of the queue if one fails.

## Context

The pipeline is 5 stages per note:

```
1. loaded audio              — resolve audio.wav, read duration, show size
2. transcribe (whisper)      — write transcript.txt, show final word count
3. generate notes (qwen · notes-mode) — write notes.md
4. index to chromadb         — embed + upsert chunks
5. save                      — write/update meta.toml; mark complete
```

Each stage renders `✓` / `⠙` / `○`. A header line shows `<n> of <total> · <title>` when batching.

No progress bar, no ETA, and no live-streaming output during transcribe — the checklist is the whole UI. Streaming previews are reserved for `chirp record` (story 1.6).

Queue contract:

- `chirp transcribe` (no arg) — transcribe every untranscribed note, FIFO (oldest audio first).
- `chirp transcribe N` — transcribe the N oldest untranscribed.
- `--force` re-runs all 6 stages on an already-transcribed note (existing flag).

Parallelism decision: strict sequential across notes (one note through all 6 stages before the next starts). Whisper and Ollama both target Metal on Apple silicon, so pipelining buys little and complicates UI + failure recovery.

## Acceptance criteria

- **AC-1** `chirp transcribe` with no argument processes every note where `transcript.txt` is missing or empty, ordered by `list_notes` (FIFO, oldest first).
- **AC-2** `chirp transcribe 2` with 3 untranscribed notes processes the oldest 2 only, prints `1 of 2 · …` / `2 of 2 · …` headers.
- **AC-3** `chirp transcribe --force` on a fully transcribed note re-runs all 5 stages and overwrites `transcript.txt`, `notes.md`, and `meta.toml` fields.
- **AC-4** The 5-step checklist is rendered via `rich.live.Live` in one column. Completed stages show `✓`; in-progress shows `⠙` (animated spinner); pending shows `○`. Text colors match the wireframe (green for done, cyan/yellow for in-progress, dim for pending). **No progress bar, no ETA, no percentage.**
- **AC-5** Stage 1 "loaded audio" prints duration (`mm:ss`) and file size (`MB`).
- **AC-6** Stage 2 "transcribe (whisper)" writes `transcript.txt` (plain UTF-8, no timestamps) and shows the final word count once complete. No streaming preview during transcribe.
- **AC-7** Stage 3 "generate notes (qwen · notes-mode)" writes `notes.md`. No streaming preview — the stage flips from `⠙` to `✓` when the file is written.
- **AC-8** Stage 4 "index to chromadb" embeds the new `notes.md` and upserts chunks into Chroma at `~/.chirp/chroma/`.
- **AC-9** Stage 5 "save" writes/updates `meta.toml` with `indexed_at` (ISO 8601), `whisper_model`, `llm_model`, `duration_s` and flips the stage to `✓`.
- **AC-10** If any stage for note K raises, the error is logged, stages 1–K are left as-is in `meta.toml` (so the user can retry from that point), and the loop moves on to note K+1 (does not abort the batch).
- **AC-11** `BatchProcessor._process_concurrently` is either removed or hidden behind an undocumented `CHIRP_PIPELINE=1` env flag. A `# TODO: pipeline across notes if profiling justifies it` marker is left in `batch_processor.py`.
- **AC-12** `uv run chirp transcribe --help` reflects the new contract: argument `N` (optional int, "process the N oldest untranscribed"); flags `--force`, `--model` (existing). The `--stream/--no-stream` flag is **removed** — streaming is a `chirp record` concern, not a transcribe concern.
- **AC-13** `uv run pytest` includes tests for: FIFO ordering from `list_notes`, N-batch respects N, `--force` re-runs completed notes, failure in stage 3 continues to next note.

## Implementation tasks

1. **Rewrite `transcribe` command** in `chirp/cli.py`:
   - Argument `n: Optional[int]` (no more `note_id`/`input_dir`).
   - Call `BatchProcessor.run_queue(n=n, force=force)`.
   - Drop the `--stream/--no-stream` flag.
2. **`transcriber/batch_processor.py`**
   - Add `run_queue(n, force)`:
     - `records = [r for r in list_notes(notes_root) if force or not r.has_transcript()]`
     - `if n is not None: records = records[:n]`
     - For each record, call `process_one(record)` inside a `Live` context.
   - Add `process_one(record)` that renders the 5-step checklist and walks through each stage.
   - Delete `process_files`, `process_directory`, `_get_output_path`, `_write_metadata_file`, `_filter_files_to_process`, `_process_sequentially`, `_process_concurrently` or adapt to the new contract — the public entry point is `run_queue`.
   - Remove `JSONCompressor` usage; writes `transcript.txt` directly.
   - Do not plumb `on_segment` into transcribe — it is only used by live-record.
3. **Checklist renderer**
   - New class `ChecklistView` in `transcriber/batch_processor.py` (or a new module) that tracks stage states and renders a `rich.table.Table` or `rich.console.Group` for `Live`.
   - Stages as enum: `LOAD_AUDIO`, `TRANSCRIBE`, `GENERATE_NOTES`, `INDEX`, `SAVE`.
4. **Metadata writes**
   - Helper `meta_io.read(path) -> dict` and `meta_io.merge(path, patch)` using `tomllib` + `tomli_w`.
   - Called at end of stage 5 to persist fields.
5. **Indexing hook**
   - Stage 4 calls `IndexManager.add_or_update(notes_md_path)` which handles embed + upsert + BM25 rebuild.
6. **Error handling**
   - Wrap each stage call in try/except; on fail, paint that stage `✗` red, continue to next record. Print a summary line at batch end: `done · 2 ok · 1 failed`.

## Dev notes

- Use `rich.spinner.Spinner("dots")` for the in-progress `⠙` glyph; it matches the wireframe.
- Transcribe is a batch/headless operation — no streaming, no progress bar, no ETA. The checklist `○ → ⠙ → ✓` is the only UI affordance.
- Language is not a stage and not a flag. Whisper will auto-detect; we don't surface it. Multi-language UX is a separate future story.
- The existing `process_concurrently` path is a Whisper-only parallelism (`max_workers` on the audio files). Ruled out for the visible `transcribe` command. Leaving it behind an env flag costs almost nothing and gives an escape hatch if profiling later shows idle GPU.
- The `PopupManager.show_transcription_complete(...)` notification can stay — fire it once at batch end with the ok count.
