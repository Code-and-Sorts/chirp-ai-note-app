# Story 1.8 — `chirp search` keyword rewrite over transcripts + notes

- **Status:** Done
- **Epic:** [EPIC-WF-ALIGN](../epic.md)
- **Depends on:** 1.1 (storage), 1.3 (notes id resolution)
- **Blocks:** —
- **Design source:** Chirp CLI Wireframes — Direction A frames **A7** (main), **A7b** (scoped + flags), **A7c** (empty state). Exact terminal text reproduced in §Design reference below.

## User story

As a Chirp user looking for an exact phrase across my history, I want `chirp search "pricing"` to be a one-shot keyword search over every note's transcript **and** notes file (always both), returning a ranked table plus inline match excerpts (labelled `transcript` for transcript hits and `notes.md:<line>` for notes hits), so that I can find a specific moment without opening notes one-by-one. I also want to filter by recency with `--since 30d`, and get a useful "did you mean…" nudge toward `chirp ask` when there are no hits.

## Context

`chirp search` today is a stale interactive `LiveSearchSession` (`notes_chat/search.py`) that filters note titles by substring. It does not read transcript or notes contents, has no time filter, no scope flag, and does not match the locked Direction-A wireframes (A7 / A7b / A7c).

This story replaces `LiveSearchSession` with a one-shot, ripgrep-style keyword pipeline that:
1. Walks every `<slug>/{transcript.txt,notes.md}` under `notes_root` — both files for every note, always.
2. Runs a literal substring match (case-insensitive) — or a Python regex with `--regex`.
3. Renders exactly the A7 view: header line, per-note table (`#`, title, date, hits), per-note excerpt blocks with `transcript` (transcript hits) / `notes.md:<line>` (notes hits) prefixes, then footer hints.

**Scope choice (deviation from wireframe A7b):** the wireframe shows `--in {notes,transcripts,both}` and `--tag <t>` flags. This story drops both — `chirp search` always scans both files, and tag filtering is left to `chirp notes --tag` (which is already the canonical place for it from story 1.3). This keeps `search` minimal and predictable; the only filter on the search command is recency (`--since`).

`chirp ask` remains the semantic entry point. `chirp search` is intentionally literal — fuzzy/semantic matches are out of scope.

## Pre-requisite changes (resolutions to readiness-review blockers)

These three changes are **part of this story** because each AC depends on them. None of them existed at the time of writing.

> **Deviation from the wireframe:** A7 shows `12:40  …drop the free tier…` for transcript hits, but Chirp's `transcript.txt` is plain text without timestamps and we are intentionally not adding them in this story (it would complicate the transcribe pipeline and its tests for marginal value). Instead, transcript excerpts are prefixed with the literal word `transcript` (dim) and the matched line text. Notes hits keep `notes.md:<line>`.

### PR-1 · `parse_timeframe` must accept `d` and `w`

`utils/time_utils.parse_timeframe` only handles `s/m/h`; `30d` raises. Wireframe A7b uses `--since 30d`.

**Resolution:** extend the suffix table to add `d = 24*60` and `w = 7*24*60` minutes. Reject bare `m` for `--since` (force `30d` / `2w` / `48h`) by adding a thin wrapper `parse_since(text)` that calls `parse_timeframe` then rejects values < 1h with `ValueError("--since must be at least 1h")`. Add unit tests in `tests/utils/test_time_utils.py`.

### PR-2 · `chirp ask` must accept a positional question

A7 footer hint shows `chirp ask "pricing"`. A7c shows `$ chirp ask "did i talk about acquisition strategy?"`. Today `ask` only accepts `--question/-q QUESTION`; a positional form would `ConvertError`.

**Resolution:** add a positional `question: str | None = typer.Argument(None)` to **both** `chirp/cli.py::ask` (the wrapper) and `notes_chat/cli.py::ask` (the actual `@app.command()`). The wrapper forwards positional through; precedence (positional wins when both are given) is resolved inside `notes_chat/cli.py::ask`. The existing `--question/-q` continues to work. This is a minimal ergonomic improvement; everything else about `ask` is unchanged.

### PR-3 · "close keywords" needs a real similarity rule

A7c surfaces three "close keywords" but the original wireframe gave no algorithm. The query tokens by definition aren't in the BM25 vocabulary (otherwise we'd have hits).

**Resolution:** rank candidates by a cheap composite:
1. Keep candidate if `Levenshtein(candidate, query_token) ≤ 2` **or** candidate has a ≥3-char common prefix with any query token, **or** candidate contains any query token as a substring (≥3 chars).
2. Sort by descending document-frequency (number of distinct notes the token appears in).
3. Return up to 3, dedup'd, formatted as the wireframe shows: `· "<token>"   (<N> notes)`.

If `BM25Index` is missing or empty (no `~/.chirp/chroma`/bm25 yet), the close-keywords block is silently dropped — only the `! keyword search is literal…` panel renders. Add `BM25Index.vocabulary() -> dict[str, int]` returning token → distinct-doc count.

## Acceptance criteria

- **AC-1** New CLI: `chirp search QUERY` — `QUERY` is required, positional. Empty/whitespace-only query exits 2 with `[red]search query is required.[/red]`.
- **AC-2** Header (A7):
  ```
  searching <N> notes for "<query>" · keyword (ripgrep over transcripts + notes)
  ```
  where `<N>` = `len([r for r in list_notes(notes_root) if r.transcript or r.notes])`. The `· keyword (…)` clause is dim; `<N>` and the leading `searching … for` are dim; `"<query>"` is bold yellow.
- **AC-3** Scope line, rendered **only when `--since` is set**:
  ```
  scope: last 30 days
  ```
  - Omit the entire scope line when `--since` is unset.
  - The duration text is rendered human-readably from the parsed `--since` value: `30d` → `last 30 days`, `48h` → `last 48 hours`, `2w` → `last 2 weeks`. Singular/plural correct (`last 1 day`).
- **AC-4** Match summary line with bold count + middle-dot separators:
  ```
  3 notes · 7 matches · 0.04s
  ```
  Singular/plural correct (`1 note · 1 match`). Elapsed seconds rounded to 2 decimals; use `time.perf_counter()`.
- **AC-5** Per-note table (A7) columns: `#`, `title`, `date`, `hits`. Use `rich.table.Table` with the same border styling already used by `_list_notes` (`border_style="dim"`, `header_style="yellow bold"`).
  - `#` is the same 1-based newest-first integer that `chirp notes` prints (story 1.3 invariant: `enumerate(reversed(records), start=1)`).
  - `title` cell uses `_resolve_display_title(record)` from `chirp/cli.py`.
  - `date` cell formats `record.created_at.strftime("%b %d").lower()` (matches A7 `apr 16`).
  - `hits` cell colored `accent` (orange-ish — use `style="bright_red"` / Rich's `orange3` if available; falls back to `yellow` if not — pick whichever Rich theme already exposes a non-red orange).
  - Sorted by hit count descending; ties broken by `#` ascending (newer first).
  - Suppress the table entirely when there are zero matches (the no-hits view replaces it).
- **AC-6** Per-note excerpt block, one per matched note, in the same order as the table:
  ```
  › #2 call w/ jamie  · apr 16
    transcript  …drop the free tier, raise pricing from $8 to $12…
    transcript  …team pricing stays per-seat for now…
    notes.md:3  tl;dr: pricing overhaul. drop free, raise pro.
    notes.md:9  □ draft pricing page
  ```
  - Header line: `›` is dim, `#N <title>` is `yellow bold`, `· <date>` is dim. One leading space of indent, two-space indent on excerpt rows (matches A7).
  - **Transcript hits**: prefix is the literal word `transcript` (dim). No timestamps, no line numbers — just the source label and the windowed excerpt. (Deliberately deviates from A7's `12:40` prefix; see the deviation note in §Pre-requisite changes.)
  - **Notes hits**: prefix is `notes.md:<line>` (1-based) and dim.
  - Excerpt body: window centred on the first match, total visible width ≤ 120 chars, `…` (single ellipsis char `…`) added on either side when truncated. The matched substring is `yellow bold`. Multiple matches on the same line are deduped to the first; we still count all of them in the `hits` column.
  - Per-note excerpt cap: at most **5 excerpt rows per note**, ordered by file appearance (transcript first, then notes), to keep terminal output tight.
- **AC-7** Footer hints (A7), dim, two lines, indented by one space:
  ```
   › chirp notes view <#>      · open a result
   › chirp ask "<query>"       · semantic answer instead
  ```
  - `<#>` is the top-ranked match's `#`.
  - `<query>` is the user's exact query, double-quoted. PR-3 makes `chirp ask "<query>"` a real, runnable command.
- **AC-8** `--since DURATION` filters `list_notes` to records whose `created_at` is within the last `DURATION`. Parsed via `parse_since` (PR-1): accepts `30d`, `2w`, `48h`; rejects bare `m`/`s` and durations < 1h. Errors print `[red]invalid --since: <reason>[/red]` and exit 2.
- **AC-9** `--regex` (default off). Treats the query as a Python regex compiled with `re.IGNORECASE`. Invalid pattern → `[red]invalid regex: <reason>[/red]`, exit 2. All matching is case-insensitive in this story (no `--case-sensitive`).
- **AC-10** `--in` and `--tag` are **not** options on `chirp search`. Search always scans both `transcript.txt` and `notes.md` for every note; tag filtering belongs to `chirp notes --tag` (story 1.3) and is intentionally not duplicated here.
- **AC-11** `--json` emits a JSON document and skips the rendered table/excerpts/hints. Schema:
  ```json
  {
    "query": "pricing",
    "since": null,
    "regex": false,
    "duration_seconds": 0.04,
    "total_notes_scanned": 14,
    "matches": [
      {
        "id": 2,
        "slug": "call-w-jamie-2026-04-16",
        "title": "call w/ jamie",
        "date": "2026-04-16",
        "hits": 4,
        "excerpts": [
          {"source": "transcript", "line": 41,
           "text": "...drop the free tier, raise pricing from $8 to $12..."},
          {"source": "notes", "line": 3,
           "text": "tl;dr: pricing overhaul. drop free, raise pro."}
        ]
      }
    ]
  }
  ```
  `--json` always wins over the no-hits TTY view: when there are no matches, `matches` is `[]` and the close-keywords block is **not** included in JSON.
- **AC-12** No-hits path (A7c) renders exactly:
  ```
   searching 14 notes for "acquisition strategy"

   ✗ no exact matches.

   ───────────────────────────────────────────────
   ! keyword search is literal. for fuzzy/semantic
     answers, try chirp ask:

     $ chirp ask "<query>"

   close keywords found across your notes:
     · "growth"     (3 notes)
     · "go-to-market"  (2 notes)
     · "channels"   (4 notes)
  ```
  Implementation rules:
  - The `✗` is `red`; `no exact matches.` is `bright` (use `bold white` on default Rich theme).
  - The horizontal rule is exactly 47 `─` (U+2500) characters, dim — matches A7c.
  - The `!` is `yellow bold`.
  - The example shell line uses `<query>` verbatim (with double quotes) — reusing PR-2's positional `ask`.
  - Close-keywords list per PR-3. Suppress the entire `close keywords found…` heading and rows when there are zero suggestions.
- **AC-13** Performance: a single-process walk over ≤ 200 notes returns in < 200 ms wall-clock on a developer laptop (no automated CI assertion). Excerpt extraction reads each file once; **no `subprocess`/ripgrep dependency** — pure Python, faithful to "ripgrep-style" but without the binary.
- **AC-14** Replace the existing `chirp search` body in `chirp/cli.py:880`. Delete `notes_chat/search.LiveSearchSession` and any tests that exercise its keypress / pty plumbing. No hidden flag preserves the old session.
- **AC-15** `chirp search --help` includes (exact help text not asserted, but presence is):
  ```
  Usage: chirp search [OPTIONS] QUERY

   Keyword search across transcripts and notes.

  Arguments:
    QUERY  Substring (or regex with --regex) to search for.  [required]

  Options:
    --since TEXT  Only notes from the last DURATION (e.g. 30d, 2w, 48h).
    --regex       Treat QUERY as a Python regex.
    --json        Emit JSON and skip the rendered output.
  ```
- **AC-16** `uv run pytest` covers, in `tests/notes_chat/test_search_keyword.py`:
  - happy path (3 seeded notes, expected table rows + excerpt order match A7),
  - `--since 30d` filters out an older note,
  - `--since` rejects unsupported units (`5m`, `30s`) with exit 2,
  - `--regex` accepts a valid pattern, rejects an invalid one with exit 2,
  - `--json` produces a parseable document with the AC-11 schema,
  - no-hits path emits the AC-12 block (close-keywords suppressed when BM25 is empty),
  - empty query exits 2 with the expected error,
  - transcript hits render with the literal `transcript` prefix (no timestamps, no line numbers); notes hits render with `notes.md:<line>`.

## Implementation tasks

3. **PR-3** — `notes_chat/bm25.py::BM25Index`: add `vocabulary() -> dict[str, int]` returning `token → distinct-doc-count`. Pure-python; cache on first call.
4. **New module `notes_chat/search_keyword.py`**:
   - `@dataclass(frozen=True) class SearchOptions` — query, since_minutes (None when unset), regex, json.
   - `def run_search(settings, options) -> dict` — does the walk, returns the AC-11 dict shape.
   - `def render_results(console, options, result) -> None` — A7 TTY render (with optional scope line when `--since` is set).
   - `def render_no_matches(console, options, total_scanned, suggestions) -> None` — A7c TTY render.
   - `def suggest_close_keywords(bm25_path, query) -> list[tuple[str, int]]` — PR-3 logic; returns up to 3.
5. **Excerpt extraction helper** `_extract_matches(path, source, pattern, regex)`:
   - Reads file once, line-by-line (utf-8, errors=`replace`).
   - For each line: scan with compiled regex (`re.IGNORECASE` always); record (line_no, match_start, match_end, line_text) for every hit.
   - For transcript: emit excerpt with `source = "transcript"`; the rendered prefix is the fixed word `transcript` (line number is captured in JSON output but not shown in TTY render).
   - For notes: emit excerpt with `source = "notes"` and `line = line_no`; rendered prefix is `notes.md:<line_no>`.
   - Window centring: produce `text` ≤ 120 visible chars centred on `match_start`; prepend / append `…` when truncated. The matched substring stays intact (don't truncate inside the match).
6. **Replace `chirp search` body** in `chirp/cli.py`:
   - Drop the `LiveSearchSession` import and try/except.
   - Add typer parameters per AC-15 (just `QUERY`, `--since`, `--regex`, `--json`) and dispatch to `run_search` + `render_*`.
7. **Delete `notes_chat/search.py::LiveSearchSession`** and `tests/notes_chat/test_search.py`. Drop `notes_chat/search.py` if nothing else imports it.
8. **Tests** in `tests/notes_chat/test_search_keyword.py` covering AC-16. Use `CliRunner` against a temp `notes_root` seeded with three known fixtures.

## Dev notes

- The wireframe-locked footer hint is now safe to render literally because PR-2 lands `chirp ask "<query>"` as a real command. Don't quietly drop the positional form in PR-2 — the hint depends on it.
- "Ripgrep-style" is the spirit, not a dependency. Pure Python is faster than spawning `rg` for ≤ 200 files and removes a system dep.
- Sort tie-break: by `#` ascending (newer first) keeps the table stable when ties happen.
- `--since` parses through `parse_since` (PR-1) which returns minutes; multiply by 60 for seconds and subtract from `datetime.now()` (NoteRecord.created_at is naive local; do not add tz).
- The wireframe shows `12:40` / `14:02` timestamps before transcript hits. We deliberately diverge: transcript hits render with the literal `transcript` label only. This keeps the transcribe pipeline unchanged and the search renderer simple. Revisit if a future story adds segment-level timestamps to `transcript.txt`.
- Excerpt windowing: when truncating, prefer cutting at a whitespace boundary within ±10 chars of the limit; otherwise hard-cut. The `…` ellipsis is a single char so it doesn't blow the 120-char budget.
- Don't bold matches inside the JSON payload — JSON is for piping, not rendering.
