## User story

As a first-time Chirp user, I want `chirp init` to walk me through four clear phases — verify → install → pick → pull/finalize — including the optional BlackHole audio-routing setup step, and end with a config file, a vector store, and a notes folder all in their wireframe-specified locations, so that my first real `chirp record` works without further setup.

## Context

`chirp/init_flow.py:run_init` already has the 4-phase structure. Two things change in this story:

1. **Phase 2** absorbs the BlackHole audio-routing prompt from the deleted `setup` command (story 1.2). The prompt is macOS-only and offers to open Audio MIDI Setup or skip.
2. **Phase 4** writes `~/.chirp/config.toml` (per story 1.1) instead of `user_config_dir/config.yaml`, creates `~/.chirp/chroma/`, and confirms `~/Documents/chirp/` exists. Print the "your nest is ready" block from the wireframe.

Flags `--recheck` and `--switch-model` already exist and must keep working.

## Acceptance criteria

- **AC-1** `chirp init` runs the 4 phases in order: verify, install, pick, pull/finalize. Each phase prints a header matching the wireframe.
- **AC-2** Phase 2 (install) on macOS, after brew installs complete, prints the BlackHole routing block verbatim from A2:
  ```
  ! BlackHole needs a one-time audio routing step:
    open Audio MIDI Setup and create a
    Multi-Output Device = Speakers + BlackHole 2ch

    (chirp can open it for you)
    › [o] open Audio MIDI Setup   [s] skip, I'll do it
  ```
  `o` runs `open -a "Audio MIDI Setup"` then continues; `s` continues without opening. Any other keypress repeats the prompt. On non-macOS, the block is skipped silently.
- **AC-3** Phase 4 writes `~/.chirp/config.toml` via the TOML writer introduced in story 1.1.
- **AC-4** Phase 4 creates `~/.chirp/chroma/` and ensures `~/Documents/chirp/` exists.
- **AC-5** Phase 4 ends with the A2 "your nest is ready" panel — three confirmation lines for the paths, then a `try:` block with two example commands:
  ```
  ✓ saved config to ~/.chirp/config.toml
  ✓ initialized chromadb at ~/.chirp/chroma/
  ✓ notes dir: ~/Documents/chirp

  your nest is ready. try:
    $ chirp record
    $ chirp ask "what did I decide last week?"
  ```
- **AC-6** `chirp init --recheck` runs only the verify phase and exits 0 (no installs, no writes).
- **AC-7** `chirp init --switch-model` jumps directly to the pick + pull/finalize phases (current behavior — confirm not regressed).
- **AC-8** If Ollama is not running at the end of Phase 2, the current red error message remains: `ollama isn't running. start it with \`brew services start ollama\`, then re-run.` (init_flow.py:502)
- **AC-9** The deleted `setup` command (story 1.2) left no leftover references in help text, README, or CLAUDE.md — verify with `rg "chirp setup"` returning no matches.
- **AC-10** **Re-run (idempotent) behavior** — running `chirp init` a second time must be safe and minimal:
  - Phase 1 (verify) always runs and reports current state.
  - Phase 2 (install) only runs the sub-steps whose Phase 1 check failed. If all tools are present, Phase 2 prints `everything's already installed — skipping.` and skips both the brew calls and the BlackHole prompt.
  - Phase 3 (pick) always offers the user a chance to change models on re-run. When `~/.chirp/config.toml` already exists and its `models.llm` + `models.embed` resolve to installed Ollama tags, the pickers preselect those current values and the phase prints:
    ```
    current models: <llm>, <embed>
    keep these, or pick new? [K/p]
    ```
    `K` (default) skips straight to Phase 4 with no changes. `p` runs the pickers normally. `--switch-model` forces `p`.
  - Phase 4 (pull/finalize):
    - `~/.chirp/config.toml` is **merged**, not overwritten — existing user edits (theme, paths, etc.) are preserved; only `models.*` fields from Phase 3 are updated, and only if Phase 3 ran.
    - `~/.chirp/chroma/` is created if missing, left untouched if present — never wiped.
    - `~/Documents/chirp/` is created if missing, left untouched if present — never wiped.
    - The three confirmation lines use `✓` for freshly created and `·` (dim) for "already existed".
    - The `try:` block always prints.
  - Nothing in `~/Documents/chirp/<slug>/` is ever touched by `init`.
- **AC-11** `uv run pytest` passes; add:
  - A smoke test that monkey-patches the four phase functions and asserts `run_init` calls them in order.
  - A re-run test that runs `run_init` twice in a tmp HOME and asserts the second run: writes no new files, does not prompt for BlackHole, and does not overwrite a hand-edited `config.toml` value.

## Implementation tasks

1. **Extract BlackHole prompt** — move the body of the deleted `setup` command (pre-story-1.2 version at `chirp/cli.py:1132`) into a helper `init_flow._prompt_blackhole_routing(console)` and invoke it from the install phase. Gate it on `if any tool was missing in Phase 1` so re-runs on a healthy box don't re-prompt.
2. **Platform gate** — wrap the prompt in `if sys.platform == "darwin":`.
3. **Phase 2 idempotency** — track which verify checks failed; only run brew for those. If none failed, emit `everything's already installed — skipping.` and return.
4. **Phase 3 keep-or-pick** — read existing `config.toml`; if `models.llm` and `models.embed` both exist AND both are present in `ollama list`, print `current models: <llm>, <embed>` and prompt `keep these, or pick new? [K/p]`. Default `K` skips to Phase 4; `p` runs the pickers with the current values preselected. `--switch-model` forces `p` with no prompt.
5. **Phase 4 merge-not-overwrite** — read existing `config.toml` (if any), layer Phase 3 outputs on top, write back. Never truncate user keys we didn't set.
6. **Finalize output** — use `✓` for paths created this run, `·` (dim) for paths that already existed. Always print the `try:` block.
7. **Verify `--recheck` short-circuit** still works. Current code at `init_flow.py:485-486` returns early; confirm the BlackHole prompt and the idempotency gates are all placed *after* that check.
8. **Tests** — `tests/test_init_flow.py`:
   - `test_run_init_phases_order` — monkeypatch phase functions with recorders.
   - `test_run_init_is_idempotent` — run twice in tmp HOME, assert no new files on second run.
   - `test_run_init_preserves_user_edits` — seed a `config.toml` with a custom key, run init, assert the custom key survives.

## Dev notes

- BlackHole install itself is out of scope — the prompt only opens Audio MIDI Setup (via `open -a "Audio MIDI Setup"`) and points the user at BlackHole docs. The actual `brew install blackhole-2ch` can stay in the Phase 2 install step alongside the other formulae if the user consents.
- `chirp devices` remains (hidden) as an escape hatch for users who skipped routing and want to list devices later — make sure the BlackHole prompt's "skip" branch mentions it.
- The "your nest is ready" copy is in the wireframe; match it exactly. Prefer a `rich.panel.Panel` with border color matching the rest of the init output.
