# Story 4.5 — `chirp models show` / `default` / `remove` / `pull`

- **Status:** Draft
- **Epic:** [EPIC-MODEL-REGISTRY](../epic.md)
- **Depends on:** 4.1 (registry writer + mutation helpers), 4.2 (HF download for `pull`), 4.3 (shared error mapping + `RichProgressCallback`), EPIC-CHIRPD-CORE story 3.6 (`llm.client.model_load` for `pull` auto-warm; daemon-side cache cleanup is not invoked)
- **Blocks:** 4.6

## User story

As a Chirp user, I want four smaller commands to round out the registry surface:

- `chirp models show <alias>` to inspect a single model's resolved config.
- `chirp models default <alias>` to flip the default for the alias's role.
- `chirp models remove <alias> [--purge]` to drop a model, optionally deleting its weights.
- `chirp models pull <alias>` to force-redownload a model when its cache is corrupted or to refresh updated weights.

Each is small individually, but together they fill in the Priya and Sam journeys.

## Context

`add` (4.3) and `list` (4.4) cover the create and read flows. This story adds the update / delete / refresh flows. All four commands share the read-registry → mutate-or-display → optional-write pattern. They reuse the helpers from 4.3 (error mapping, Rich progress callback) and 4.4 (registry + daemon composition for the `show` view).

Each command's contract is small enough to live in this single story; splitting them into four stories would create artificial seams without helping demonstrability. Each command is independently demonstrable end-to-end against a `FakeBackend`-backed daemon and a tmp-registry fixture.

Implements FR27 (`default`), FR28 (`remove`, optionally with `--purge`), FR29 (`pull`), FR30 (`show`).

## Acceptance criteria

### `chirp models show <alias>`

- **AC-1** `@app.command("show")` on the same Typer app. Signature:
  ```
  chirp models show <alias> [--json]
  ```
- **AC-2** Execution:
  1. Read registry. If alias not in `registry.models`, print `Error: Model not registered: <alias>. Run \`chirp models list\` to see what's available.` to stderr, exit code 5.
  2. Resolve cache path: call `huggingface_hub.try_to_load_from_cache` (or equivalent) against the alias's `hf_repo` to find the local snapshot path. `None` if not cached.
  3. Query daemon for loaded state (same non-spawning call as 4.4). Catch `LLMDaemonUnreachable` and treat as "not loaded".
  4. Render: TTY → a Rich `key: value` panel or two-column display with `alias`, `hf_repo`, `role`, `default` (yes/no), `loaded` (yes/no/unknown), `cache_path`, `options` (one row per option key if any). `--json` → a single JSON document with the same keys.
- **AC-3** JSON schema for `show`:
  ```json
  {
    "alias": "gemma-4-4b-it-4bit",
    "hf_repo": "mlx-community/gemma-4-4b-it-4bit",
    "role": "chat",
    "default": true,
    "loaded": true,
    "cache_path": "/Users/.../.cache/huggingface/hub/models--mlx-community--gemma-4-4b-it-4bit/snapshots/<sha>/",
    "options": {"temperature": 0.7},
    "daemon_reachable": true
  }
  ```
  `loaded` is `null` when `daemon_reachable` is `false`. `cache_path` is `null` when not cached locally.

### `chirp models default <alias>`

- **AC-4** `@app.command("default")` on the Typer app. Signature:
  ```
  chirp models default <alias>
  ```
  No `--json` — write commands stay TTY-only by convention.
- **AC-5** Execution:
  1. Read registry. If alias not registered → exit 5 with the same error pattern as `show`.
  2. Look up the alias's `role` from the registry. Call `set_default_for_role(registry, alias)` — this is the helper from story 4.1 that uses the alias's registered role to set `default_chat` or `default_embed`.
  3. Write the registry atomically via `write_registry`.
  4. On success, print to stderr `Set <alias> as default <role>.` and exit 0.
- **AC-6** Setting the default does **not** warm the model. If the user wants to warm it, they re-add or re-pull. Rationale: `default` is a low-friction flip; auto-warming would surprise users who flip defaults frequently for testing.
- **AC-7** Role-mismatch defense: if `registry.models[alias].role` somehow has an invalid literal value (only reachable if a user hand-edited `models.toml` to insert garbage), `set_default_for_role` raises `ValueError`. Surface as `Error: Model <alias> has invalid role; edit ~/Library/Application Support/chirp/models.toml or re-run \`chirp models add\`.` exit 1.

### `chirp models remove <alias> [--purge]`

- **AC-8** `@app.command("remove")` on the Typer app. Signature:
  ```
  chirp models remove <alias> [--purge]
  ```
- **AC-9** Execution:
  1. Read registry. If alias not registered → exit 5 (same pattern).
  2. Capture the alias's `hf_repo` **before** mutation (needed for `--purge`).
  3. Call `remove_model(registry, alias)` (story 4.1's helper, which clears the default if the removed alias was a default).
  4. Write registry atomically. **No daemon notification** — if the daemon has the alias loaded, it will surface a typed error on the next `model.load`/`chat` against that alias; users running `chirp models remove` on a loaded model are explicitly opting into that.
  5. If `--purge`, delete the HF cache directory for the model. Resolve the cache dir via `huggingface_hub`'s cache layout helper (typically `~/.cache/huggingface/hub/models--<org>--<repo>/`), then `shutil.rmtree` it. On failure (path missing, permission denied), print a warning to stderr and continue — the registry mutation already succeeded. The exit code stays 0; the warning names the path.
  6. Print to stderr `Removed <alias>.` (or `Removed <alias> and purged cache (<bytes-or-path>).` with `--purge`) and exit 0.
- **AC-10** `--purge` confirmation: in MVP, **no interactive prompt** (per PRD §Scripting Support → "none of the new commands prompt interactively"). The user typed `--purge` and means it. If they didn't mean it, the model can be re-downloaded with `chirp models add <repo>` from HF.
- **AC-11** Path-safety guard for `--purge`: before `shutil.rmtree`, assert the resolved cache directory path is **inside** the resolved HF hub cache root. Refuse to delete and abort with exit 1 if the path is outside (defensive against `huggingface_hub` returning something unexpected). This is a one-liner check but it earns its keep on safety review.

### `chirp models pull <alias>`

- **AC-12** `@app.command("pull")` on the Typer app. Signature:
  ```
  chirp models pull <alias> [--no-warm]
  ```
  Mirrors `add`'s `--no-warm` flag.
- **AC-13** Execution:
  1. Read registry. If alias not registered → exit 5.
  2. Resolve the registered `hf_repo` from the registry entry.
  3. Call `llm.hf.download_model(hf_repo, progress=RichProgressCallback(...))` — same call as `add` step 4. On `HfRepoNotFound`, `HfNetworkError`, `HfDownloadFailed`, use the shared error-mapping table from 4.3.
  4. **Do not** call `validate_repo` again — the registry's existence is implicit validation that the user has previously confirmed the repo (and `download_model`'s own 404 path will surface fresh `HfRepoNotFound` if the repo has since been deleted from HF).
  5. **Do not** mutate the registry — `pull` is weight-only.
  6. If `--no-warm` not set, call `llm.client.model_load(alias)` (lazy-spawn allowed; same as `add`'s warm step). Warm failure exits 4; download failure already exited 1.
  7. Print to stderr `Pulled <alias> (<bytes-or-cache-hit>).` then `Warmed <alias>.` (or skipped warm note) and exit 0.

### Cross-cutting

- **AC-14** All four commands route registry-write failures through the shared error mapping (`RegistryWriteError → exit 1`). All four route reader failures (`RegistryUnsupportedSchemaVersion → exit 1`) the same way. Code duplication between `show` and `list` is avoided by extracting a tiny `_load_view_state(registry, alias) -> ShowState` helper that 4.4's `list` and this story's `show` both call (or, less elegantly, two near-identical functions — implementer's call).
- **AC-15** Stderr discipline: all four commands use stderr exclusively for user-facing messages **except** `show` in TTY mode (table to stdout) and `show --json` (JSON to stdout). `default`, `remove`, `pull` print nothing to stdout under any condition.

## Implementation tasks

1. **Add the four command handlers to `llm/cli/models.py`.**
   - One `@app.command(...)` decorated function per command (`show`, `set_default` aliased to `default` via Typer's `name="default"` because `default` is a Python keyword, `remove`, `pull`). The Python function name doesn't need to be `default`; the Typer-registered name does.
   - Each handler is short — the heavy lifting is in the helpers from stories 4.1 / 4.2 / 4.3.

2. **Cache-path resolution helper.**
   - Small wrapper in `llm/hf.py` (extends story 4.2's module): `resolved_cache_path(hf_repo: str) -> Path | None`. Uses `huggingface_hub`'s cache discovery (`scan_cache_dir` or `try_to_load_from_cache`). Returns `None` if the repo isn't in the cache.
   - Adding this helper to `llm/hf.py` keeps the convention "all `huggingface_hub` calls live in `llm.hf`". Update story 4.2's contract surface by documenting this addition in 4.2's tests if 4.2 has already landed.

3. **Path-safety guard for `--purge`.**
   - In a `_safe_purge(path: Path) -> None` helper: resolve `path` and the HF hub cache root with `.resolve()`, assert one is a parent of the other (`os.path.commonpath` or `Path.is_relative_to`), call `shutil.rmtree(path, ignore_errors=False)`. Catch `FileNotFoundError` and `PermissionError` and re-raise as a typed warning the caller surfaces. The "refuse if outside" branch raises `ValueError` which the caller maps to exit 1.

4. **Extract the `show`-view composer.**
   - Pure helper `_compose_show_state(alias: str, registry: Registry, loaded_aliases: set[str], cache_path: Path | None, daemon_reachable: bool) -> ShowState`. Returns a dataclass with all the AC-3 fields. Pure → trivially unit-testable; same data the JSON renderer and the Rich renderer both consume.

5. **Write the tests.**
   - All 21+ tests under AC-16. Reuse the `seed_registry` and mocked `llm.client` / `llm.hf` boundaries.
   - For the path-safety test, mock the cache resolver to return `Path("/etc/passwd")` (or another unsafe path); assert the command refuses and exits 1.

6. **Document the smoke verification.**
   - Append the AC-19 sequence to `tests/llm/README.md`.

## Dev notes

- **Why `default` doesn't warm.** PRD doesn't explicitly say either way, but FR27 phrasing ("set the default… via `chirp models default <alias>`") describes a registry-only change. Auto-warming would surprise Priya, who flips defaults frequently. If users want to warm after flipping, `chirp models pull --alias <name>` is the documented way; a future Growth-tier `--warm` flag on `default` is non-breaking to add later.
- **Why `remove` doesn't tell the daemon.** Three reasons. First, the daemon doesn't need to know — its `model.load` lookup re-reads `models.toml` on every op (architecture §Configuration & Persistence). Second, telling the daemon would require a `model.unload` op call which could block on a currently-running chat (NFR-R6: in-flight requests fail cleanly on shutdown, but a `model.unload` is more graceful and currently undefined for "the alias is gone now"). Third, this keeps `remove` zero-dependency on the daemon being up — important for users cleaning up after a daemon crash.
- **Why `--purge` is non-interactive.** PRD §Scripting Support locks "none of the new commands prompt interactively." Confirmation prompts make scripts brittle. The user typed `--purge`; that's their confirmation. Re-downloading is one `chirp models add` away.
- **Path-safety on `--purge`.** A bug in `huggingface_hub`'s cache layout could in principle return a path outside the cache root; `shutil.rmtree` against that path would be catastrophic. The check is two lines of defensive code that costs nothing in the happy path.
- **Why `pull` does not re-validate.** `validate_repo` does a fresh `HfApi.repo_info` call — wasteful when we already have the registered entry. `download_model` itself will surface a `RepositoryNotFoundError` if the repo has been deleted from HF since the user added it, so the user gets a clear error either way without the extra round-trip.
- **`set_default_for_role` semantics:** the alias is the input; the helper looks up the alias's role and sets the correct default field. A user trying to flip the embed default to a chat-role alias would have to manually corrupt the registry first — the helper rejects role-mismatches.
