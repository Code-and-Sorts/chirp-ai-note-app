# Story 4.1 — `models.toml` Pydantic model and atomic write helper

- **Status:** Draft
- **Epic:** [EPIC-MODEL-REGISTRY](../epic.md)
- **Depends on:** EPIC-CHIRPD-CORE story 3.5 (reader contract — the Pydantic schema must be agreed shared between this story's writer and that story's reader)
- **Blocks:** 4.3, 4.4, 4.5, 4.6

## User story

As a Chirp developer, I want a single Pydantic model that describes the `models.toml` file shape, plus an atomic write helper that flushes registry mutations safely, so that every `chirp models` subcommand can mutate the registry without risking a half-written file when the user kills mid-write or when the daemon is reading concurrently.

## Context

The `models.toml` registry is the source of truth for "what models has this user installed and which are the defaults." It lives at `~/Library/Application Support/chirp/models.toml`. CHIRPD-CORE story 3.5 ships `llm.registry.read_registry() -> Registry` (Pydantic model loaded from disk). This story ships the writer half: the Pydantic model itself, the `write_registry(registry: Registry) -> None` atomic writer, and the small set of registry-mutation helpers the CLI subcommands will call (`upsert_model`, `set_default_for_role`, `remove_model`, `alias_for_repo`).

The registry shape locked by PRD §Config Schema:

```toml
schema_version = 1
default_chat = "gemma-4-4b-it-4bit"
default_embed = "bge-small-en-v1.5"

[models."gemma-4-4b-it-4bit"]
hf_repo = "mlx-community/gemma-4-4b-it-4bit"
role = "chat"
options = { temperature = 0.7, top_p = 0.9, max_tokens = 2048 }

[models."bge-small-en-v1.5"]
hf_repo = "mlx-community/bge-small-en-v1.5"
role = "embed"
```

The file is created on first write — there is no separate "initialize empty registry" step. The first command to write (typically `chirp models add`) creates the parent directory if absent and writes the file. Per architecture decision: atomic write via `tomli_w.dumps` to a sibling `.tmp` then `os.replace`. Schema-versioning is alpha-simplified — `schema_version = 1` is written; the reader (CHIRPD-CORE 3.5) rejects unknown versions outright with a typed error.

## Acceptance criteria

- **AC-1** `tomli_w` is added to `[project.dependencies]` in `pyproject.toml` with a minimum pin (the current released version at story-execution time). `huggingface_hub` is **not** added here — that lands in 4.2.
- **AC-2** A new module `llm/registry.py` exists and exports at least:
  - `class ModelEntry(BaseModel)` with fields `hf_repo: str`, `role: Literal["chat", "embed"]`, `options: dict[str, Any] = Field(default_factory=dict)`.
  - `class Registry(BaseModel)` with fields `schema_version: int = 1`, `default_chat: str | None = None`, `default_embed: str | None = None`, `models: dict[str, ModelEntry] = Field(default_factory=dict)`.
  - Module-level constant `CURRENT_SCHEMA_VERSION = 1`.
  - Module-level constant `REGISTRY_PATH = Path("~/Library/Application Support/chirp/models.toml").expanduser()` (overridable via environment variable `CHIRP_REGISTRY_PATH` for testing — routed through the existing settings module per architecture §Configuration Access).
- **AC-3** `write_registry(registry: Registry, *, path: Path | None = None) -> None`:
  1. Resolves the destination path to `path or REGISTRY_PATH`.
  2. Creates the parent directory with `mkdir(parents=True, exist_ok=True)` if it doesn't exist.
  3. Dumps the Pydantic model to a Python dict via `registry.model_dump(exclude_none=True, mode="python")`. The `models` field is a dict-of-dicts at this point.
  4. Renders TOML via `tomli_w.dumps(...)`.
  5. Prepends a header comment block on every write: a fixed string that names the alpha-simplification constraint ("no schema migrations — re-create this file if `chirp models *` rejects it") and a stable URL pointer to the docs. The comment block must round-trip cleanly through `tomllib.loads` (which discards comments — acceptable).
  6. Writes the rendered string to `<path>.tmp` in the same directory (binary mode, UTF-8). `fsync` the file descriptor before close (defensive against power loss; cheap on SSD).
  7. `os.replace(<path>.tmp, <path>)` to atomically swap.
- **AC-4** `write_registry` raises `RegistryWriteError(OSError)` (a new typed exception in `llm/registry.py`) when the directory cannot be created or the tmp file cannot be written. The original `OSError` is chained.
- **AC-5** Mutation helpers, all returning a new `Registry` (immutable-style — never mutate the input in place):
  - `upsert_model(registry: Registry, alias: str, entry: ModelEntry) -> Registry` — inserts or replaces the entry for `alias`. Rejects empty alias or alias containing `/` (raises `ValueError`).
  - `remove_model(registry: Registry, alias: str) -> Registry` — removes the entry. If the removed alias was the role's default, that default is cleared (`None`). Raises `KeyError` if alias not registered.
  - `set_default_for_role(registry: Registry, alias: str) -> Registry` — looks up the alias's role and sets `default_chat` or `default_embed` accordingly. Raises `KeyError` if alias not registered. Raises `ValueError` if the alias's role doesn't match a valid default field (defensive — the literal type already constrains this).
- **AC-6** `alias_for_repo(repo: str) -> str` — pure helper. Strips `<org>/` prefix, lowercases, validates that the result is non-empty and matches `^[a-z0-9._-]+$`; raises `ValueError` with the offending repo string if not. Example: `mlx-community/gemma-4-4b-it-4bit` → `gemma-4-4b-it-4bit`. `BAAI/bge-small-en-v1.5` → `bge-small-en-v1.5`. The slash-strip is the only `<org>` removal; nested slashes are rejected (no HF repo has them, but be defensive).
- **AC-7** Atomic-write resilience: a unit test that simulates a failure between `tomli_w.dumps` and `os.replace` (e.g., by monkey-patching `os.replace` to raise) asserts the pre-existing `models.toml` is **unchanged** and that the `.tmp` file (if it exists on disk) is the only side-effect — the reader on the next `read_registry()` call still parses the old content cleanly.
- **AC-8** Round-trip property: `read_registry(write_registry(reg)) == reg` for any `Registry` whose `models` dict has alias keys passing the AC-6 regex. Verified by a property-style test that hand-builds three `Registry` instances (empty, one chat default, one chat + one embed default) and asserts equality after a round trip.
- **AC-9** Header-comment round-trip: a test writes a registry, reads back the raw TOML text (not just parsed), asserts the header comment block is present and starts with `# chirp models registry — schema_version 1` (or equivalent stable string), and that `tomllib.loads(text)` returns the expected dict (comments are tolerated by `tomllib`, so this is just a parser-doesn't-choke check).
- **AC-10** Unicode + special-char tolerance: writing a `Registry` whose `models.<alias>.options` contains string values with quotes, backslashes, and non-ASCII characters round-trips cleanly through `tomli_w.dumps` + `tomllib.loads`. Per `tomli_w` documentation this is its job; the test is there as a regression guard against `tomli_w` API churn.
- **AC-11** Tests in `tests/llm/test_registry.py`:
  - `test_registry_round_trip_empty` — write empty `Registry()`, read back, fields match defaults.
  - `test_registry_round_trip_single_chat` — one chat model, default set.
  - `test_registry_round_trip_chat_and_embed` — one of each, both defaults set, `options` dict populated.
  - `test_write_creates_parent_dir` — point `REGISTRY_PATH` at a temp dir that doesn't exist yet; assert `write_registry` creates the parent and the file.
  - `test_write_is_atomic_on_replace_failure` — monkey-patch `os.replace` to raise `OSError`; pre-existing file (written by a first successful call) remains unchanged in content and bytes.
  - `test_upsert_model_inserts` and `test_upsert_model_replaces` — both round-trip through `write_registry`.
  - `test_upsert_rejects_empty_or_slashed_alias` — `ValueError` for `""` and for `"mlx-community/gemma"`.
  - `test_remove_model_clears_default` — register a chat model as default, remove it, assert `default_chat is None`.
  - `test_remove_unknown_alias_raises_keyerror`.
  - `test_set_default_for_role_chat` and `test_set_default_for_role_embed`.
  - `test_set_default_for_role_unknown_alias_raises_keyerror`.
  - `test_alias_for_repo_strips_org_and_lowercases` — three positive cases and two negative (empty after strip; nested slash).
  - `test_header_comment_present_and_parseable` — written file contains a comment line starting with `# chirp models registry`; `tomllib.loads` returns the expected dict.
  - `test_unicode_options_round_trip` — option value `"system_prompt" = "you are a助手"` round-trips byte-for-byte through write/read.
- **AC-12** `uv run pytest tests/llm/test_registry.py` passes. `uv run ruff check llm/registry.py tests/llm/test_registry.py` clean. `uv run mypy llm/registry.py` clean.
- **AC-13** Module test coverage for `llm/registry.py` ≥ 95% line coverage. Achievable because the module is pure (no `subprocess`, no network, no MLX).

   - Define `ModelEntry` and `Registry` Pydantic models per AC-2.
   - Define `CURRENT_SCHEMA_VERSION = 1`.
   - Define `REGISTRY_PATH` resolved via the settings module (`config/settings.py`) so the env-var override (`CHIRP_REGISTRY_PATH`) goes through the canonical path. Do **not** read `os.environ` directly per architecture §Configuration Access.

   - Implement `upsert_model`, `remove_model`, `set_default_for_role` as small pure functions over `Registry`. Use `registry.model_copy(update={...})` rather than mutating; the Pydantic model is immutable-by-convention in this module's API contract.
   - Implement `alias_for_repo` with a precompiled regex `_ALIAS_RE = re.compile(r"^[a-z0-9._-]+$")`.

   - Add a `chirp_registry_path() -> Path` helper in `config/settings.py` (or wherever the existing settings live) that returns the resolved path with env-var override applied. `llm/registry.py` calls this helper instead of reading `os.environ` directly.

4. **Write the tests.**
   - All 14 tests under AC-11 in `tests/llm/test_registry.py`. Use `tmp_path` fixtures for `REGISTRY_PATH` overrides. Mock `os.replace` only in the atomicity test.
   - Add a `conftest.py` under `tests/llm/` if one doesn't exist, with a `registry_path` fixture that points at `tmp_path / "models.toml"` and sets `CHIRP_REGISTRY_PATH` (via `monkeypatch.setenv`) for the duration of the test.

5. **Sanity-check against CHIRPD-CORE's reader contract.**
   - Cross-reference: CHIRPD-CORE story 3.5 must export `read_registry(path: Path | None = None) -> Registry` and import the **same** `Registry` Pydantic class from `llm/registry.py`. There is exactly one definition of `Registry` in the codebase. If story 3.5 lands first, this story imports from there (and adds writer-side helpers); if this story lands first, story 3.5 imports from here. Either way, single source of truth.

## Dev notes

- **Why immutable mutation helpers.** Returning a new `Registry` makes test assertions trivial (no "did this function mutate my fixture?") and makes the writer's job clearly transactional ("compute the new state, then atomically replace the file"). The cost is one `model_copy` per mutation — negligible at registry sizes we care about.
- **Why `os.replace` (not `os.rename`).** `os.replace` is the explicit "atomic on POSIX, overwrite-if-exists" function. `os.rename` on Windows raises if the destination exists; on POSIX it's equivalent to `os.replace`. The project is macOS-only per NFR-C2, but `os.replace` is the right verb regardless.
- **Why fsync.** Defensive against power loss between `write` and `os.replace`. On modern SSDs the cost is microseconds. Skipping it would mean a power loss could result in `models.toml.tmp` containing zeros after recovery — followed by a successful `os.replace` that swaps in the zeroed file. Cheap insurance.
- **Why `tomli_w` and not `tomlkit`.** `tomlkit` preserves comments and formatting but is heavier and slower. We control both ends of the write path; we don't need style preservation. The header comment is a single fixed block.
- **`schema_version = 1` semantics.** The reader (CHIRPD-CORE 3.5) raises `RegistryUnsupportedSchemaVersion(...)` on any value ≠ 1. If we ever bump to 2, we'll add a migration step at *that* time — but per alpha simplification the immediate behavior is "user re-creates their registry."
- **Header comment text.** Suggested:
  ```toml
  # chirp models registry — schema_version 1
  # Managed by `chirp models {add,remove,default,pull}`. Hand edits OK; re-run
  # `chirp models list` to sanity-check. Alpha note: no automatic migrations
  # across schema_version changes — delete this file if a future chirp release
  # rejects it, then `chirp models add` to re-register.
  ```
  Final wording is the implementer's call; tests assert only on the stable prefix.

## Testing

- **Unit:** the 14 tests in AC-11; the module is pure and fully covered.
- **Manual:** none required for this story — `chirp models add` (story 4.3) is the first user-visible exercise of the writer path. Worth a one-shot REPL check that `Registry.model_validate(tomllib.loads(write_registry(Registry()) and read back))` returns an equal model.

## Handoff to downstream stories

- **4.3 (`chirp models add`)** consumes `Registry`, `ModelEntry`, `write_registry`, `upsert_model`, `set_default_for_role`, `alias_for_repo`.
- **4.5 (`chirp models default` / `remove` / `pull`)** consumes `write_registry`, `remove_model`, `set_default_for_role`.
- **4.4 (`chirp models list`)** consumes `read_registry` (CHIRPD-CORE 3.5) only — no writes.
- **4.6 (Typer completion)** consumes `read_registry` and a list of `registry.models.keys()`.

The contract surface from this story is the `Registry` Pydantic model, the four mutation helpers, the one alias helper, and `write_registry`. All downstream consumers go through these — no module reaches into `tomli_w.dumps` or `os.replace` directly.
