# Story 2.1 — `audio_capture` module: Swift helper + Python wrapper + packaging

- **Status:** Draft
- **Epic:** [EPIC-AUDIO-CAPTURE](../epic.md)
- **Depends on:** —
- **Blocks:** 2.2, 2.3

## User story

As a Chirp developer, I want a self-contained `audio_capture` module that bundles a Swift `capture_audio` helper, exposes a `with AudioCapture() as cap:` Python context manager, and yields tagged `(source, timestamp_us, np.ndarray)` PCM frames from system audio and microphone simultaneously, so that the rest of the codebase has a single, BlackHole-free way to read live audio on macOS.

## Context

This story builds the foundation. Nothing in the Chirp CLI consumes the new module yet — that's story 2.2's job. The deliverable here is a buildable, importable, testable `audio_capture` package whose contract matches the spec exactly:

```python
from audio_capture import AudioCapture
with AudioCapture() as cap:
    for source, timestamp_us, chunk in cap.frames():
        ...  # 1 = system audio, 2 = microphone; chunk is np.float32, 16 kHz mono
```

Layout:

```
audio_capture/
  __init__.py              # AudioCapture class
  build.py                 # python -m audio_capture.build → swiftc + bundle assembly
  swift/
    capture_audio.swift    # the Swift source
    Info.plist             # NSMicrophoneUsageDescription, NSScreenCaptureUsageDescription
    Makefile               # builds the .app bundle locally
  CaptureAudio.app/        # built artifact (gitignored; shipped as wheel package data)
    Contents/
      Info.plist
      MacOS/
        capture_audio
```

The Swift binary writes the framing protocol on stdout and parseable diagnostics on stderr. The Python wrapper launches it via `subprocess.Popen`, reads stderr in a background thread to surface permission errors, and parses stdout frames lazily as the consumer iterates.

## Acceptance criteria

- **AC-1** A new top-level Python package `audio_capture/` exists and is added to `[tool.hatch.build.targets.wheel]` packages in `pyproject.toml`. `numpy` is already a dep; no new Python deps.
- **AC-2** `audio_capture/swift/capture_audio.swift` implements the spec's two capture engines:
  - System audio via `SCStream` (`SCContentFilter` on default display, `capturesAudio = true`, `excludesCurrentProcessAudio = true`, `sampleRate = 16000`, `channelCount = 1`, dummy 2x2 video).
  - Microphone via `AVAudioEngine` input-node tap (4096-sample buffer, 16 kHz mono float32 tap format).
  - Both callbacks write to stdout through a single shared serial `DispatchQueue` to prevent interleaving.
- **AC-3** Wire format on stdout exactly matches the spec:
  ```
  [source: u8] [timestamp: u64 LE] [length: u32 LE] [pcm: bytes]
  ```
  `source = 0x01` for system audio, `0x02` for microphone. Timestamp is microseconds since a single shared reference captured at startup (`mach_absolute_time` rebased to zero on the first frame). Length is the byte count of the float32 PCM payload that follows.
- **AC-4** Startup sequence on the Swift side:
  1. `signal(SIGPIPE, SIG_IGN)` before any I/O.
  2. `AVCaptureDevice.requestAccess(for: .audio)` — on denial, write `error: microphone_denied\n` to stderr and `exit(1)`.
  3. `SCShareableContent.excludingDesktopWindows(...)` — on failure, write `error: screen_recording_denied\n` to stderr and `exit(1)`.
  4. Write the four diagnostic lines to stderr in order:
     ```
     capture: started
     capture: sample_rate=16000 channels=1 format=float32
     capture: system_audio=enabled
     capture: microphone=enabled device="<name>"
     ```
  5. Start both engines and begin streaming frames on stdout.
- **AC-5** Signal handling on the Swift side: `SIGTERM` and `SIGINT` both stop `SCStream` and `AVAudioEngine` cleanly, then `exit(0)`. A broken-pipe write failure is treated identically to `SIGTERM`.
- **AC-6** `audio_capture/swift/Info.plist` declares `CFBundleIdentifier = com.codeandsorts.chirp.capture-audio`, `CFBundleExecutable = capture_audio`, `NSMicrophoneUsageDescription = "Chirp uses your microphone to transcribe what you say in meetings."`, `NSScreenCaptureUsageDescription = "Chirp uses screen recording permission to capture system audio (e.g. other meeting participants). Pixels are not captured."`
- **AC-7** `audio_capture/swift/Makefile` has a `build` target that:
  1. Creates `CaptureAudio.app/Contents/MacOS/` if missing.
  2. Runs `swiftc capture_audio.swift -framework ScreenCaptureKit -framework CoreMedia -framework AVFoundation -target arm64-apple-macos13 -o CaptureAudio.app/Contents/MacOS/capture_audio`.
  3. Copies `Info.plist` to `CaptureAudio.app/Contents/Info.plist`.
  Also exposes a `clean` target that removes the `.app` bundle.
- **AC-8** `python -m audio_capture.build` is a thin Python wrapper around the Makefile that:
  - Runs `xcrun --find swiftc` first; if it returns non-zero, prints `xcode command-line tools missing — run \`xcode-select --install\`` and exits 1.
  - Shells out to `make -C audio_capture/swift build` and surfaces non-zero exit codes.
  - Prints the resulting binary path on success.
- **AC-9** `audio_capture/__init__.py` exports `AudioCapture` with the spec's signature. `__enter__` launches the bundled binary via `subprocess.Popen([binary_path], stdout=PIPE, stderr=PIPE)`, starts a daemon thread that drains stderr line-by-line, and waits up to 5 seconds for either `capture: started` or an `error: …` line before returning. If `error: microphone_denied` arrives, raise `PermissionError("Chirp needs microphone access. Open System Settings → Privacy & Security → Microphone and grant access to CaptureAudio.app, then try again.")`. If `error: screen_recording_denied`, the same with "Screen Recording".
- **AC-10** `__exit__` sends `SIGTERM`, calls `proc.wait(timeout=5.0)`, then sends `SIGKILL` if still alive. An `atexit` handler does the same as a safety net for callers who forget the context manager.
- **AC-11** `frames()` is an iterator that yields `(source: int, timestamp_us: int, audio: np.ndarray)` tuples until the subprocess exits or its stdout closes. `system_frames()` and `mic_frames()` are convenience iterators that filter by source and yield `(timestamp_us, audio)` only.
- **AC-12** Frame parser is a private `_read_frame()` that returns `None` on EOF or partial reads (treat partial as end-of-stream). Uses `struct.unpack('<Q', ...)` for the 8-byte timestamp and `struct.unpack('<I', ...)` for the 4-byte length. Audio is decoded via `np.frombuffer(data, dtype=np.float32)`.
- **AC-13** Binary path resolution uses `importlib.resources.files("audio_capture") / "CaptureAudio.app" / "Contents" / "MacOS" / "capture_audio"`. If the binary doesn't exist, raise `FileNotFoundError` with the message: `"capture_audio binary not found. Build it with: python -m audio_capture.build"`.
- **AC-14** Tests in `tests/test_audio_capture.py`:
  - `test_read_frame_parses_system_audio` — feed a hand-crafted byte stream into `_read_frame` via a `BytesIO` stand-in for `proc.stdout`; assert returned tuple has `source=1`, the expected timestamp, and the expected float32 array.
  - `test_read_frame_parses_microphone` — same but `source=2`.
  - `test_read_frame_returns_none_on_eof` — empty stream returns `None`.
  - `test_read_frame_returns_none_on_partial_header` — 5 bytes available when 13 expected returns `None`.
  - `test_permission_denied_raises_permission_error` — fake subprocess whose stderr emits `error: microphone_denied\n`; `__enter__` raises `PermissionError` whose message contains "Microphone".
  - `test_missing_binary_raises_file_not_found` — patch the resource resolver to return a non-existent path; `__enter__` raises `FileNotFoundError` whose message contains "python -m audio_capture.build".
  - `test_atexit_kills_lingering_process` — start an `AudioCapture` against a fake long-running subprocess (e.g. `["sleep", "60"]`), trigger the atexit handler manually, assert `proc.poll()` returns a non-`None` exit code within 6 seconds.
  - All subprocess-launching tests are gated `@pytest.mark.skipif(sys.platform != 'darwin', reason="macOS-only")` and the real-binary integration test is also marked `@pytest.mark.integration`.
- **AC-15** `uv run pytest tests/test_audio_capture.py` passes on macOS; on Linux it skips cleanly (no failures, no errors).
- **AC-16** `uv run ruff check .` reports no issues. The Swift source file is excluded from ruff (it lives under `audio_capture/swift/` which ruff already ignores by default for non-`.py` files; verify).

## Implementation tasks

1. **Scaffold the package.**
   - Create `audio_capture/__init__.py`, `audio_capture/build.py`, `audio_capture/swift/{capture_audio.swift,Info.plist,Makefile}`.
   - Add `audio_capture` to `[tool.hatch.build.targets.wheel].packages` in `pyproject.toml`. Add `audio_capture/CaptureAudio.app/**` to `[tool.hatch.build.targets.wheel.force-include]` so the `.app` bundle ships with the wheel.
   - Add `audio_capture/CaptureAudio.app/` to `.gitignore` — the bundle is a build artifact, not source.

2. **Write `capture_audio.swift`.** Use the spec verbatim. Structure:
   - `class CaptureSession: NSObject, SCStreamOutput, SCStreamDelegate` — owns the `SCStream`, the `AVAudioEngine`, the shared serial `DispatchQueue`, and the shared timestamp reference.
   - `func writeFrame(source: UInt8, timestampUs: UInt64, pcm: Data)` — single chokepoint for stdout writes; serialized through the queue. Catches broken-pipe write failures and triggers shutdown.
   - `func stream(_:didOutputSampleBuffer:of:)` — extracts PCM bytes from `CMSampleBuffer.dataBuffer`, computes a rebased microsecond timestamp from the buffer's presentation timestamp, calls `writeFrame(source: 0x01, ...)`.
   - AVAudioEngine input tap → identical extraction path with `source: 0x02` and `AVAudioTime.hostTime` rebased.
   - `main` — perform the 5-step startup sequence; install signal handlers; call `RunLoop.main.run()`.

3. **Write the Info.plist.** Match AC-6 exactly. Use Apple's `<?xml ... ?><!DOCTYPE plist ...>` preamble.

4. **Write the Makefile.** Match AC-7. Default target is `build`. Use `swiftc -O` for release builds.

5. **Write `audio_capture/build.py`.** Subprocess-driven; very small. Reuse the established `_run` pattern from `chirp/init_flow.py:44` if it makes the code clearer.

6. **Write `audio_capture/__init__.py`.** Single class. Spec's `_read_frame` is the parser core. Stderr drainer thread parses lines and stuffs them into a `queue.Queue[str]` so `__enter__` can wait on the startup sentinel without blocking on a closed pipe. Use `subprocess.Popen(..., bufsize=0)` so stdout reads aren't line-buffered (frames are binary).

7. **Write `tests/test_audio_capture.py`.** Mock-heavy except the integration test. Use `unittest.mock.patch` for `subprocess.Popen` so the parser tests stay deterministic. Build the byte stream with `struct.pack('<BQI', source, ts, length) + pcm_bytes` to exercise the same wire format the Swift side writes.

8. **Document the build.** Add a `## Building from source` subsection to `audio_capture/__init__.py`'s module docstring (this is the one acceptable docstring per CLAUDE.md — public API). Tell developers to either `make -C audio_capture/swift build` or `python -m audio_capture.build`. Note the macOS 13+ requirement.

9. **Smoke-test on real hardware.** Run a one-shot script that prints the first 10 frames from each source, with a Zoom call playing in another window:
   ```python
   from audio_capture import AudioCapture
   with AudioCapture() as cap:
       counts = {1: 0, 2: 0}
       for source, ts, chunk in cap.frames():
           counts[source] += 1
           if counts[1] >= 10 and counts[2] >= 10:
               break
       print(counts)
   ```
   Both counts should reach 10 within a few seconds. Note: on first run, expect two macOS permission prompts; subsequent runs go straight through.

## Dev notes

- **Why a `.app` bundle for a CLI helper.** macOS scopes microphone and screen-recording permissions per executable. A bare CLI binary is granted permissions to its parent terminal app (Terminal.app, iTerm, the IDE), which is both confusing and brittle. Wrapping `capture_audio` in a minimal `.app` with proper usage descriptions makes the prompt name "Chirp" (via `CFBundleName`) and ties the grant to the helper itself.
- **Why ScreenCaptureKit, not CoreAudio process taps.** macOS 14.4+ has a private `AudioHardwareCreateProcessAggregateDevice` API that captures specific apps without screen-recording permission. It is undocumented, App-Store-hostile, and breaks across point releases. Apple's first-party answer is ScreenCaptureKit; the spec accepts the screen-recording permission scope as the cost of stability.
- **Why a separate top-level package, not under `recorder/`.** The spec calls this a building block independent of any consumer. A future side project (e.g. a clipboard transcriber) should be able to depend on `audio_capture` without dragging in PyAudio, ChromaDB, Ollama, etc. Top-level placement keeps the contract clean.
- **Why bufsize=0 on Popen.** The default is line-buffered, which is wrong for binary framed stdin/stdout. The Swift side writes raw bytes; we read raw bytes; no newline assumption ever applies.
- **Why an `atexit` net.** A `with` block exits cleanly on exceptions, but a raw `KeyboardInterrupt` mid-iteration of `frames()` followed by a hard kill of the Python process can leave `capture_audio` running. The atexit handler is the safety belt; it's a no-op when `__exit__` already cleaned up.
- **What the timestamps are good for.** Two streams arrive on independent threads; their first-frame timestamps differ by a few hundred microseconds (engine warmup). Consumers that need to align (e.g. a future "speaker labels" feature) can use the timestamps to interleave or to detect a stall in one source. Story 2.2 will use them for the simplest possible offline mix; downstream features can do more.

## Testing

- **Unit:** the `tests/test_audio_capture.py` cases above. All can run on Linux CI by skipping the macOS-gated ones.
- **Manual:** the smoke-test script in implementation task 9. Verify both counts increment on a machine with audio actively playing.
- **Manual permission denial:** in System Settings → Privacy & Security, revoke microphone access for `CaptureAudio.app`, run the smoke script, expect `PermissionError` with the System Settings message. Re-grant, re-run, expect frames.
- **Manual broken-pipe:** run the smoke script, then `kill -9` the Python process while frames are flowing. Verify with `ps aux | grep capture_audio` that no helper survives within 5 seconds (atexit + SIGTERM should reap it; if Python died too fast for atexit, the helper's broken-pipe handler reaps itself on next write).
