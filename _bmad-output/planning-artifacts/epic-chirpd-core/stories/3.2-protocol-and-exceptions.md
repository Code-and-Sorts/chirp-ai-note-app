# Story 3.2 — NDJSON wire protocol, error-code constants, exception taxonomy

- **Status:** Draft
- **Epic:** [EPIC-CHIRPD-CORE](../epic.md)
- **Depends on:** 3.1
- **Blocks:** 3.3, 3.4, 3.5, 3.6, 3.7

## User story

As a chirp developer wiring up both sides of the daemon socket, I want a single shared source of truth for the wire envelope encoding/decoding, the wire-level error codes, and the typed exception hierarchy, so that the daemon (in `chirpd/`) and the client (in `llm/client.py`) never drift on field names, op codes, or error semantics.

## Context

The architecture locks three pure modules that both the daemon and the client import:

- `llm/protocol.py` — NDJSON envelope encode/decode. Wire envelope keys (`id`, `op`, `event`, `error`) are lowercase, no underscores. Op-specific field names are `snake_case`. Lines are JSON objects terminated by `\n`, UTF-8, ≤ 1 MB. (Architecture § Wire Protocol Naming Conventions; FR11.)
- `llm/error_codes.py` — Wire-level error code constants. `SCREAMING_SNAKE_CASE` namespaced by class (`PROTOCOL_*`, `MODEL_*`). The mapping from `code` → exception class lives here as a dictionary; both daemon and client import the constants by name. **This is the single source of truth — no other module declares an error code string literal.** (Architecture § Wire Protocol Naming Conventions, § Enforcement.)
- `llm/exceptions.py` — `LLMError` hierarchy: `LLMTransportError`, `LLMProtocolError`, `LLMModelError`, with concrete subclasses. Every exception carries a `code` attribute pointing to the wire constant. (Architecture § Error & Exception Taxonomy; FR23.)

This story creates only these three modules. They are pure-Python (no IO, no asyncio, no subprocess), so they are exhaustively unit-testable. They are the building blocks every other story imports.

## Acceptance criteria

- **AC-1** `llm/protocol.py` exposes `encode_request(envelope: dict) -> bytes` that returns a UTF-8 byte string ending in `\n`, containing a single JSON object with the request envelope.
- **AC-2** `llm/protocol.py` exposes `encode_event(envelope: dict) -> bytes` with the same contract for daemon-emitted event envelopes.
- **AC-3** `llm/protocol.py` exposes `decode_line(line: bytes) -> dict` that parses a single line of NDJSON. Raises `LLMMalformedResponse` (from `llm/exceptions.py`) on:
  - Non-UTF-8 bytes
  - Invalid JSON
  - JSON that isn't a top-level object
  - Lines exceeding 1 MB (`MAX_LINE_BYTES = 1_048_576`); the limit is a module-level constant
- **AC-4** `llm/protocol.py` validates envelope shape via a small `validate_request(envelope: dict) -> None` helper:
  - Required keys present (`id` for requests other than the initial `hello`; `op` for all requests)
  - `id` matches `^r-[0-9a-f]{12}$` when present (architecture § Request ID Convention) — `llm/protocol.py` exposes a `REQUEST_ID_RE` re-compiled pattern used by both sides
  - `op` is one of the known op constants
  Raises `LLMMalformedResponse` with a specific `code` if any check fails. Implements FR11.
- **AC-5** `llm/protocol.py` exposes module-level op-name constants:
  ```python
  OP_HELLO = "hello"
  OP_HEALTH = "health"
  OP_CHAT = "chat"
  OP_EMBED = "embed"
  OP_CANCEL = "cancel"
  OP_MODEL_LIST = "model.list"
  OP_MODEL_LOAD = "model.load"
  OP_MODEL_UNLOAD = "model.unload"
  OP_MODEL_STATUS = "model.status"
  ```
  And event-name constants:
  ```python
  EVENT_READY = "ready"
  EVENT_LOADING = "loading"
  EVENT_DELTA = "delta"
  EVENT_DONE = "done"
  EVENT_ERROR = "error"
  EVENT_VERSION_MISMATCH = "version_mismatch"
  EVENT_STATUS = "status"
  ```
  All other modules import these constants — no string literals for op/event names anywhere else in the codebase (NFR-M2 enforcement).
- **AC-6** `llm/protocol.py` exposes a `new_request_id() -> str` helper that returns `"r-" + secrets.token_hex(6)`. Used by the client (story 3.4) and by tests. Architecture § Request ID Convention.
- **AC-7** `llm/error_codes.py` declares the wire-level error-code string constants:
  ```python
  PROTOCOL_VERSION_MISMATCH = "PROTOCOL_VERSION_MISMATCH"
  PROTOCOL_MALFORMED = "PROTOCOL_MALFORMED"
  MODEL_NOT_FOUND = "MODEL_NOT_FOUND"
  MODEL_LOAD_FAILED = "MODEL_LOAD_FAILED"
  MODEL_GENERATION_FAILED = "MODEL_GENERATION_FAILED"
  MODEL_CANCELLED = "MODEL_CANCELLED"
  ```
  And a `CODE_TO_EXCEPTION: dict[str, type[LLMError]]` mapping consumed by `llm/client.py` (story 3.4). Architecture § Wire Protocol Naming Conventions.
- **AC-8** `llm/exceptions.py` declares the exception hierarchy exactly as architecture § Error & Exception Taxonomy specifies:
  ```
  LLMError
  ├── LLMTransportError
  │   ├── LLMDaemonUnreachable
  │   ├── LLMConnectionLost
  │   └── LLMDaemonSpawnFailed
  ├── LLMProtocolError
  │   ├── LLMVersionMismatch
  │   └── LLMMalformedResponse
  └── LLMModelError
      ├── LLMModelNotFound
      ├── LLMModelLoadFailed
      ├── LLMGenerationFailed
      └── LLMCancelled
  ```
  Implements FR23 ("client distinguishes model-load failures from transport failures in the exception types it raises").
- **AC-9** Every concrete exception class declares a class-level `code: str | None` attribute pointing to the wire constant from `llm/error_codes.py` (or `None` for client-constructed transport exceptions that never travel the wire). The `__init__` accepts `message: str`, `details: dict | None = None`, and stores both.
- **AC-10** `llm/exceptions.py` and `llm/error_codes.py` together preserve the invariant: `CODE_TO_EXCEPTION[exception_class.code] is exception_class` for every concrete subclass with a non-`None` `code`. A test asserts this round-trip.
- **AC-11** Re-exports: `llm/__init__.py` re-exports the exception hierarchy (`LLMError`, `LLMTransportError`, `LLMProtocolError`, `LLMModelError`, and the concrete subclasses) for ergonomic imports (`from llm import LLMModelError`). Op/event constants are not re-exported — callers import them from `llm.protocol`.
- **AC-12** Unit tests under `tests/llm/`:
  - `tests/llm/test_protocol.py`:
    - Round-trip: `decode_line(encode_request({...})) == {...}` for each `OP_*` constant
    - Round-trip: `decode_line(encode_event({...})) == {...}` for each `EVENT_*` constant
    - Reject non-UTF-8 bytes with `LLMMalformedResponse`
    - Reject invalid JSON with `LLMMalformedResponse`
    - Reject JSON arrays / scalars (must be an object) with `LLMMalformedResponse`
    - Reject lines exceeding `MAX_LINE_BYTES` with `LLMMalformedResponse`
    - `new_request_id()` matches `REQUEST_ID_RE` for 1000 trials
    - `validate_request` accepts every legal `OP_*`; rejects an unknown op
    - `validate_request` accepts a legal `id` (`r-` + 12 hex); rejects malformed ids (uppercase hex, wrong length, missing prefix)
  - `tests/llm/test_exceptions.py`:
    - Every concrete subclass is constructable with `(message, details)` and `(message,)`
    - Every concrete subclass's `code` attribute matches an entry in `error_codes.CODE_TO_EXCEPTION`
    - `LLMError` is the common base; `isinstance(LLMModelLoadFailed("x"), LLMError)` is True
    - `code` round-trip: for every `code, cls in CODE_TO_EXCEPTION.items(): assert cls.code == code`
  - `tests/llm/test_error_codes.py`:
    - All declared codes are non-empty strings matching `^[A-Z][A-Z_]*$` (SCREAMING_SNAKE_CASE)
    - `CODE_TO_EXCEPTION` contains exactly the codes declared as module-level constants (no orphans, no missing entries)
- **AC-13** `tests/conftest.py` (or `tests/llm/conftest.py` if scoped) introduces no fixtures yet — this story stays pure-module.
- **AC-14** Coverage on `llm/protocol.py`, `llm/error_codes.py`, `llm/exceptions.py` ≥ 95% (the modules are small and entirely unit-testable; NFR-M1 target of ≥ 90% on new modules is exceeded trivially here).
- **AC-15** `make check` and `make test` pass.

## Implementation tasks

1. **Write `llm/error_codes.py` first.** It has no dependencies on the rest of the codebase. Declare the six wire constants and the `CODE_TO_EXCEPTION` dict (forward-reference the exception classes lazily inside the dict construction at the bottom of the file, or move the dict to `llm/exceptions.py` and re-export — implementer's choice; the constants must live in `error_codes.py`).

2. **Write `llm/exceptions.py`.** Match the hierarchy in AC-8 exactly. Each concrete subclass declares its `code` class attribute. Base class signature:
   ```python
   class LLMError(Exception):
       code: ClassVar[str | None] = None

       def __init__(self, message: str, details: dict[str, Any] | None = None) -> None:
           super().__init__(message)
           self.message = message
           self.details = details or {}
   ```

3. **Write `llm/protocol.py`.**
   - Module-level `MAX_LINE_BYTES = 1_048_576`, `REQUEST_ID_RE = re.compile(r"^r-[0-9a-f]{12}$")`, the `OP_*` and `EVENT_*` constants, and a private `_KNOWN_OPS: frozenset[str]`.
   - `new_request_id()` uses `secrets.token_hex(6)` per architecture § Request ID Convention.
   - `encode_request` / `encode_event`: `json.dumps(envelope, separators=(",", ":")) + "\n"`, encoded as UTF-8 bytes. Reject envelopes that would exceed `MAX_LINE_BYTES` after encoding with `LLMMalformedResponse`.
   - `decode_line`: catch `UnicodeDecodeError`, `json.JSONDecodeError`, length violation, non-object root — raise `LLMMalformedResponse` with a `code=PROTOCOL_MALFORMED` and an informative `message`.
   - `validate_request`: check shape, op-name, optional `id` format. Raise `LLMMalformedResponse` on violation.

4. **Wire up `llm/__init__.py`.** Re-export the exception classes per AC-11.

5. **Write the three test files under `tests/llm/`.** Per AC-12.

6. **Run gates.**
   - `make check` (ruff, mypy, format, spell, validate).
   - `make test`.
   - `pytest --cov=llm tests/llm` — verify coverage ≥ 95% on the three modules.

## Dev notes

- Architecture § Enforcement is explicit: error codes must live in exactly one place. Resist the urge to type a code string literal anywhere else, including in test files — import the constant.
- The `code` attribute on exceptions exists so tests can assert against the constant (architecture § Exception Construction). Match strings only via `error_codes.MODEL_LOAD_FAILED`, never `"MODEL_LOAD_FAILED"`.
- Mypy strictness on `code: ClassVar[str | None]`: the base class declares it `None`; concrete subclasses with a wire code redeclare as `ClassVar[str]` to narrow the type.
- The 1 MB line size limit is a defense against a runaway daemon emitting a malformed gigantic event; chat deltas in normal operation are tens to hundreds of bytes.
- `new_request_id()` lives in `llm/protocol.py` (not in `llm/client.py`) so tests for the protocol can generate ids without importing the client.
