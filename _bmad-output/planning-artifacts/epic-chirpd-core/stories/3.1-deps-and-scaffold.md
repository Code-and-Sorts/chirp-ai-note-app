# Story 3.1 — Add MLX dependencies; scaffold `chirpd/` and `llm/` packages; declare `chirpd` console script

- **Status:** review
- **Epic:** [EPIC-CHIRPD-CORE](../epic.md)
- **Depends on:** —
- **Blocks:** 3.2, 3.3, 3.4, 3.5, 3.6, 3.7

## Prerequisites

- Apple Silicon Mac (M1 / M2 / M3 / M4). Intel hosts will install but cannot run the daemon — that is the next story's defensive guard. This story's `make dev-install` will succeed on either arch because `mlx-lm` declares an `arm64` wheel and pip will skip-install the wheels-not-available case if necessary; we don't gate it here.
- `uv` toolchain working (`make dev-install` baseline already green per AGENTS.md).
- macOS 13+ runtime (matches the existing project floor).

## User story

As a chirp developer, I want `mlx-lm` and `huggingface_hub` declared as project dependencies and the empty package skeletons for `chirpd/` and `llm/` checked in, so that every subsequent story in this epic can import its modules without each story re-litigating the dependency surface or the package layout.

## Context

Nothing in `chirpd/` or `llm/` exists today. The PRD locks the dependency direction (FR55: `mlx-lm` and `huggingface_hub` added; Ollama client deferred to EPIC-INIT-AND-MIGRATION) and OQ5 locks the pin granularity (exact pin for `mlx-lm` pre-1.0). The architecture locks the package layout (sibling top-level packages: `chirpd/` and `llm/`).

This story is enabling-only — no FR is delivered by it. Its demonstration is that subsequent stories can import the new packages and that `chirpd --help` runs (even if it does nothing useful yet).

The Ollama Python client **stays** in `pyproject.toml`. It remains in active use by `notes/note_generator.py`, `notes_chat/prompting.py`, `notes_chat/retrieval.py`, and `notes_chat/index.py`. Removing it before those call sites are migrated would break the build.

## Acceptance criteria

- **AC-1** `pyproject.toml` `[project] dependencies` adds `mlx-lm == X.Y.Z` (exact pin per OQ5 — author records the chosen `X.Y.Z` in the commit message and in the story's Dev notes after `uv add` selects a CI-green version) and `huggingface_hub >= Z.Z.Z` (minimum pin compatible with the chosen `mlx-lm`).
- **AC-2** `pyproject.toml` `[project.scripts]` adds the line `chirpd = "chirpd.__main__:main"` per architecture § Daemon Entrypoint. The console script is installed by `make dev-install` and resolves on PATH afterwards.
- **AC-3** `pyproject.toml` `[tool.hatch.build.targets.wheel] packages` (or the equivalent build-backend config) includes both `chirpd` and `llm` so that the wheel ships both packages.
- **AC-4** The Ollama Python client dependency line is **left in place** in `pyproject.toml`. Removing it is out of scope for this epic per §8 of the epic doc.
- **AC-5** A new top-level package `chirpd/` exists with:
  - `chirpd/__init__.py` (empty or containing only `__version__` re-exported from the package's `chirp` neighbor — implementer's choice, but no other code)
  - `chirpd/__main__.py` containing a callable `main()` that prints `chirpd <version>` and exits 0 (a placeholder; story 3.3 replaces it with the real daemon startup)
- **AC-6** A new top-level package `llm/` exists with:
  - `llm/__init__.py` (empty)
  - No other files in this story — they are created by 3.2 and 3.4
- **AC-7** `make dev-install` completes successfully against the new `pyproject.toml`. `uv pip list` shows `mlx-lm`, `huggingface_hub`, and `ollama` (the last unchanged) installed.
- **AC-8** `which chirpd` resolves to the installed console script path inside the venv. `chirpd` (with no args) runs and exits 0, printing the package's version string.
- **AC-9** `python -c "import chirpd; import llm; print('ok')"` prints `ok` and exits 0.
- **AC-10** `python -c "import mlx_lm; import huggingface_hub; print('ok')"` prints `ok` and exits 0 on an Apple Silicon Mac. On Intel, this command may fail at import time on `mlx_lm` — that is acceptable and not an AC of this story (the defensive arch check lives in story 3.3).
- **AC-11** `make check` and `make test` pass (NFR-M2). No new tests are required by this story; the gate is "existing suite still green with the new dependencies installed."
- **AC-12** Mypy passes against `chirpd/` and `llm/` (NFR-M3). The packages are empty enough that this is trivially satisfied.

## Implementation tasks

1. **Resolve the `mlx-lm` version pin.**
   - `uv add 'mlx-lm'` to find the current installable version. Verify the chosen version imports cleanly on the developer machine: `python -c "import mlx_lm; print(mlx_lm.__version__)"`.
   - Convert the dependency line in `pyproject.toml` to an exact pin: `"mlx-lm == X.Y.Z"`.
   - Record the chosen `X.Y.Z` in the commit message body and in this story's Dev notes after merge.

2. **Resolve the `huggingface_hub` minimum pin.**
   - Check `mlx-lm`'s transitive requirement: `uv pip show mlx-lm | grep -i hugging`.
   - Pin `huggingface_hub >= <that minimum>` directly in `pyproject.toml` (we depend on it explicitly for `snapshot_download` + `HfApi` in later stories).

3. **Declare the `chirpd` console script.**
   - Add `chirpd = "chirpd.__main__:main"` under `[project.scripts]` in `pyproject.toml`.
   - Verify it resolves after re-installing: `make dev-install && which chirpd`.

4. **Scaffold `chirpd/`.**
   - Create `chirpd/__init__.py` (empty for now; story 3.3 may add a logger handle here).
   - Create `chirpd/__main__.py` with a placeholder `main()`:
     ```python
     def main() -> int:
         from importlib.metadata import version

         print(f"chirpd {version('chirp')}")
         return 0


     if __name__ == "__main__":
         raise SystemExit(main())
     ```
   - This placeholder is replaced wholesale by story 3.3. It exists here only to satisfy AC-8 (the console script must be executable).

5. **Scaffold `llm/`.**
   - Create `llm/__init__.py` (empty).
   - Do **not** create `llm/protocol.py`, `llm/client.py`, `llm/exceptions.py`, `llm/error_codes.py`, or `llm/registry.py` — those are owned by later stories (3.2, 3.4, 3.5) and creating empty stubs invites forward references.

6. **Update wheel packaging.**
   - In `pyproject.toml`'s `[tool.hatch.build.targets.wheel].packages` (or equivalent for the active build backend), add `chirpd` and `llm`.
   - Verify the wheel ships both: `uv build && unzip -l dist/*.whl | grep -E '(chirpd|llm)/'`.

7. **Run the gates.**
   - `make dev-install` succeeds.
   - `make check` succeeds (ruff, mypy, format, spell, validate).
   - `make test` succeeds (existing suite, unchanged behavior).

8. **Manual smoke (one-liners):**
   - `chirpd` → prints `chirpd <version>` and exits 0.
   - `python -m chirpd` → same output via the module form.
   - `python -c "import chirpd, llm, mlx_lm, huggingface_hub"` → silent exit 0 on Apple Silicon.

## Dev Agent Record

### Implementation notes (2026-05-16)

- **`mlx-lm` chosen version:** `0.31.3` (current installable; OQ5 exact pin recorded here per task 1).
- **`huggingface_hub` minimum pin:** `>= 1.5.0` (transitive floor declared by `transformers==5.8.1` from the `mlx-lm` chain; uv resolves to `1.9.1` today and will float upward as `transformers` loosens). The story's "minimum compatible with the chosen mlx-lm" rubric is satisfied.
- **Placeholder version lookup uses `version("chirp-notes-ai")`,** not `version("chirp")` as written in the story snippet — `chirp-notes-ai` is the actual distribution name in `pyproject.toml`, and `chirp/about.py` already uses the same string. Downstream stories 3.3/3.4 that mention `version("chirp")` should be read the same way; flagging here so they can be updated when picked up.
- **Test-suite regression introduced by the new deps:** `mlx-lm` pulls in `transformers==5.8.1`, whose lazy `__dir__` triggers a `NameError: PILImageResampling` deep in `transformers/models/gemma4/image_processing_pil_gemma4.py` when `freezegun` walks every imported module's attributes. The trigger is benign — `freezegun` only needs `__dir__` for cache invalidation. Resolved by extending `freezegun.configure(extend_ignore_list=["transformers"])` in `tests/conftest.py`. Without this, `tests/test_time_ranges.py::TestParseTimeRange::test_yesterday` fails as soon as anything else in the session has imported `faster_whisper` (which transitively imports `transformers`). Full suite stayed at 788 passing.
- **Mypy scope for `chirpd/` and `llm/`:** AC-12 verified by running `uv run mypy chirpd llm` directly (passes — both packages are empty enough to be trivial). The packages are not added to `[tool.mypy] files` in `pyproject.toml` yet; that registration belongs to story 3.2 when the first real module lands and there's something to actually type-check inside `make check`.
