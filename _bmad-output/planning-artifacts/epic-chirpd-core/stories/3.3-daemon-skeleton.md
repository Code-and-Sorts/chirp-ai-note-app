# Story 3.3 — Daemon skeleton: startup, flock, Apple-Silicon check, asyncio socket listener, `hello` + `health` ops, logfmt logging

- **Status:** Done
- **Epic:** [EPIC-CHIRPD-CORE](../epic.md)
- **Depends on:** 3.2
- **Blocks:** 3.4, 3.5, 3.6, 3.7

## Prerequisites

- Apple Silicon Mac at runtime (the daemon defensively checks this at startup; non-Apple-Silicon hosts will see the daemon exit with a clear message — implementing FR54 catches this earlier at `chirp init`, but that's EPIC-INIT-AND-MIGRATION).

## User story

As a chirp developer, I want a runnable `chirpd` process that creates its socket and lockfile, enforces single-instance, accepts NDJSON connections, answers `hello` (with version handshake) and `health` requests, and writes logfmt logs to a rotating file, so that the next stories have a real daemon to build inference handlers on top of and the client library has a real handshake partner.

## Context

This story produces the runnable daemon shell. It implements the daemon-side half of the version handshake state machine (architecture § State Machine — Version Handshake & Drain), the single-instance enforcement (architecture § Single-Instance Enforcement), the socket listener (architecture § IPC Protocol), the logging facade (architecture § Logging Discipline), and the two simplest ops (`hello` and `health`). Inference ops are added in story 3.6; model.* ops in story 3.5.

This story produces the manual smoke test that closes the loop with the client story (3.4): start the daemon, send a `hello` from a script, observe `ready` or `version_mismatch`.

The version-handshake exit path is **alpha-simplified** per FR14 and architecture § State Machine: on mismatch, emit `version_mismatch` on the offending connection and `exit(0)` immediately. **No `Draining` state, no 10 s deadline, no "reject new connections during drain" branch.** Tasks for other in-flight connections raise on next `await` as the loop tears down — the client sees this as `LLMConnectionLost` (handled in story 3.4).

## Acceptance criteria

- **AC-1 (Apple Silicon defensive check):** `chirpd/__main__.py` `main()` checks `platform.machine() == "arm64"` before doing anything else. On mismatch, prints `chirpd requires Apple Silicon (arm64); detected: <machine>` to stderr and returns exit code `2`. Implements the defensive half of architecture § Gap Analysis → Apple Silicon enforcement points. The user-facing fail-fast in `chirp init` is FR54, owned by EPIC-INIT-AND-MIGRATION.
- **AC-2 (runtime directories):** `chirpd/__main__.py` `main()` creates `~/Library/Application Support/chirp/` and `~/Library/Logs/chirp/` if missing (mode `0700`). The socket file lives in the former; logs in the latter. Implements the on-disk layout from architecture § Runtime File Layout.
- **AC-3 (flock single-instance):** Before starting the asyncio loop, `chirpd/lifecycle.py` acquires `fcntl.flock(LOCK_EX | LOCK_NB)` on `~/Library/Application Support/chirp/chirpd.lock`. On `BlockingIOError`, logs `level=info component=chirpd msg="another chirpd already running; exiting"` and returns exit code `0`. The lockfile handle is held for the lifetime of the process. Implements FR12 and NFR-R4.
- **AC-4 (socket setup):** `chirpd/server.py` exposes an `async def serve(socket_path: Path, dispatcher: Dispatcher) -> None` coroutine that:
  1. Removes any stale socket file at `socket_path` (left behind by a previous unclean exit). Uses `os.unlink` and ignores `FileNotFoundError`.
  2. Creates the unix-domain server via `await asyncio.start_unix_server(handler, path=str(socket_path))`.
  3. Calls `os.chmod(socket_path, 0o600)` immediately after bind to satisfy NFR-S2.
  4. Calls `await server.serve_forever()`.
  Implements NFR-S1 (unix-domain only, no TCP), NFR-S2 (mode `0600`).
- **AC-5 (per-connection handler):** Per architecture § IPC Protocol → Connection lifecycle, the connection handler in `chirpd/server.py`:
  1. Reads one line (≤ 1 MB) terminated by `\n`. On EOF or oversized line: log + close.
  2. Decodes via `llm.protocol.decode_line`. On `LLMMalformedResponse`: emit `{event: "error", code: "PROTOCOL_MALFORMED", message: ...}` and close.
  3. Validates the envelope via `llm.protocol.validate_request`. Same error handling.
  4. The first message **must** be `op == "hello"`. If the first message is any other op, emit `error` (code `PROTOCOL_MALFORMED`) and close.
  5. Routes `hello` to the handshake handler; subsequent messages on the same connection (per architecture: one request per connection, but the connection lifecycle is `hello → ready → request → events`) route through `Dispatcher.dispatch(envelope, writer)`.
  6. On client-close (connection reset, EOF mid-request): treat as cancel-and-close (cancel plumbing added in story 3.6).
- **AC-6 (`hello` op — version handshake):** Per architecture § State Machine — Version Handshake & Drain and FR13/FR14:
  1. `hello` request payload: `{"id": "r-...", "op": "hello", "client_version": "X.Y.Z"}`.
  2. Daemon reads its own version from `importlib.metadata.version("chirp")`.
  3. If `client_version == daemon_version`: emit `{"id": "r-...", "event": "ready", "daemon_version": "X.Y.Z"}`. Connection stays open for the next request.
  4. If `client_version != daemon_version`: emit `{"id": "r-...", "event": "version_mismatch", "daemon_version": "X.Y.Z"}`, log a `level=info` line, then **schedule daemon exit**:
     - Stop the asyncio server (`server.close()` + `await server.wait_closed()`).
     - Return cleanly so `main()` exits with code `0`.
     - Any other in-flight connections see their next `await write(...)` raise; their tasks complete with an exception that's caught at the request handler boundary.
- **AC-7 (`health` op):** Per FR15. Request: `{"id": "r-...", "op": "health"}`. Response: a single `{"id": "r-...", "event": "ready", "status": "ok", "uptime_seconds": <float>, "version": "X.Y.Z"}` event, followed by `{"id": "r-...", "event": "done"}`. The `health` op never raises; it's the smoke test for `chirp init` (FR51 reads it; that's EPIC-INIT-AND-MIGRATION).
- **AC-8 (dispatcher seam):** `chirpd/dispatcher.py` exposes a `Dispatcher` class with `async def dispatch(self, envelope: dict, writer: asyncio.StreamWriter) -> None`. In this story, `Dispatcher` knows only `hello` and `health`. Story 3.5 extends it with `model.*` ops; story 3.6 with `chat` / `embed` / `cancel`. Dispatcher is constructed at process start and held by the server handler closure.
- **AC-9 (request handler exception boundary):** The dispatcher's `dispatch` method catches every unexpected exception, converts it to `{event: "error", code: "MODEL_GENERATION_FAILED", message: str(e), details: {"exception_type": type(e).__name__}}`, and writes it to the connection. Per architecture § Exception Construction → "The handler does not let exceptions propagate out of `handle_request` and crash the connection silently." For this story, no inference path exists yet — but the boundary is in place so stories 3.5/3.6 can rely on it.
- **AC-10 (logging setup — logfmt + rotating file):** `chirpd/logging_setup.py` exposes a `configure_logging() -> None` function that:
  1. Creates `~/Library/Logs/chirp/` if missing.
  2. Installs a `logging.handlers.RotatingFileHandler` at `~/Library/Logs/chirp/chirpd.log` with `maxBytes=10_485_760` (10 MB) and `backupCount=1` (≥ 1 prior generation; NFR-O2).
  3. Attaches a custom `Formatter` whose `format(record)` emits a logfmt line:
     - Required keys every line: `ts=<RFC3339 UTC with milliseconds> level=<info|warning|error> component=<chirpd|chirpd.server|...> msg="<short>"`.
     - Optional keys (`req_id`, `op`, `model`, `duration_ms`, `err_code`, `err_type`) when present on the `LogRecord` via `extra={...}`.
     - Quoting: values with spaces or special chars are double-quoted with backslash escaping. Implementer writes a small `_quote(value)` helper.
  4. Sets the root logger to `INFO`.
  Architecture § Logging Discipline.
- **AC-11 (log redaction discipline):** The logging setup does not log message content. The test in AC-15 (smoke test) verifies no prompt / message / note text appears in `chirpd.log`. This is enforced by code review and convention — story 3.6 (which is the first story that handles user content) is responsible for not passing user text into log calls. NFR-S5.
- **AC-12 (graceful signal handling):** `chirpd/__main__.py` installs `signal.SIGTERM` and `signal.SIGINT` handlers that stop the asyncio server and exit cleanly (code `0`). Implements the daemon side of NFR-R6 (alpha-simplified — no drain).
- **AC-13 (`__main__.py` wires it up):** Replaces the placeholder from story 3.1. New shape:
  ```python
  def main() -> int:
      if platform.machine() != "arm64":
          print(f"chirpd requires Apple Silicon ...", file=sys.stderr)
          return 2

      configure_logging()
      ensure_runtime_dirs()
      lock_handle = acquire_single_instance_lock()
      if lock_handle is None:
          return 0  # another chirpd is running

      dispatcher = Dispatcher()
      try:
          asyncio.run(serve(SOCKET_PATH, dispatcher))
      except KeyboardInterrupt:
          pass
      finally:
          # close lock file; socket cleanup handled by serve()
          ...
      return 0
  ```
  `SOCKET_PATH` reads from `CHIRP_DAEMON_SOCKET` env var first, falling back to `~/Library/Application Support/chirp/chirpd.sock` (PRD §Config Schema → environment variable overrides).

## Implementation tasks

1. **Module skeletons.** Create `chirpd/server.py`, `chirpd/dispatcher.py`, `chirpd/lifecycle.py`, `chirpd/logging_setup.py`. Replace the placeholder `chirpd/__main__.py` from story 3.1.

2. **`chirpd/logging_setup.py` first.** Pure code, no asyncio. Implement `configure_logging()`, a custom `Formatter`, and the `_quote` helper. Test before moving on.

3. **`chirpd/lifecycle.py`.** Implement `ensure_runtime_dirs()`, `acquire_single_instance_lock(lock_path)` returning a file handle or `None`, and a `release_lock(handle)`. The lock handle stays open for process lifetime — closing it releases the flock.

4. **`chirpd/dispatcher.py`.** Class `Dispatcher` with `async def dispatch(self, envelope: dict, writer: asyncio.StreamWriter) -> None`. Branch on `envelope["op"]`:
   - `op == OP_HEALTH`: write `ready` event + `done` event.
   - `op == OP_HELLO`: not handled here — `hello` is special-cased in `server.py` because mismatch needs to stop the server.
   - Anything else: write `error` event with code `PROTOCOL_MALFORMED` (in this story; later stories add real branches). Wrap the whole body in `try/except Exception` per architecture § Exception Construction.

5. **`chirpd/server.py`.** Implement `async def serve(socket_path, dispatcher)` per AC-4. The per-connection handler implements AC-5 + AC-6. The `hello` handler is in `server.py` (not the dispatcher) because version-mismatch needs access to the asyncio server object to shut it down. Expose `async def shutdown_server(server)` helper.

6. **`chirpd/__main__.py`.** Full implementation per AC-13. Install signal handlers. Read socket path from `CHIRP_DAEMON_SOCKET` env var first.

7. **Tests under `tests/chirpd/`.** Per AC-14. Use `asyncio.start_unix_server` in-process for integration tests — no subprocess. `pytest-asyncio` is presumably already in the test deps; if not, add it.

8. **Manual smoke test (record in the PR description):**
   ```bash
   # Terminal A
   uv run chirpd
   # logs to ~/Library/Logs/chirp/chirpd.log; socket at ~/Library/Application Support/chirp/chirpd.sock

   # Terminal B — version-match path
   python -c '
   import asyncio, json
   async def main():
       r, w = await asyncio.open_unix_connection(
           str(Path.home() / "Library/Application Support/chirp/chirpd.sock"))
       from importlib.metadata import version
       w.write(json.dumps({"id":"r-aaaaaaaaaaaa","op":"hello","client_version":version("chirp")}).encode()+b"\n")
       await w.drain()
       print(await r.readline())
       w.write(b\'{"id":"r-bbbbbbbbbbbb","op":"health"}\n\')
       await w.drain()
       print(await r.readline()); print(await r.readline())
       w.close()
   asyncio.run(main())'
   # → prints `ready` then `ready` + `done`

   # Terminal B — version-mismatch path
   # (modify the script to send client_version="0.0.0-bogus"; observe `version_mismatch`)
   # Terminal A's daemon process exits within 1 second.

   # Verify no network sockets
   lsof -i -P -n -p $(pgrep chirpd) || echo "no network sockets — pass"

   # Verify socket mode
   stat -f "%Lp" ~/Library/Application\ Support/chirp/chirpd.sock
   # → 600
   ```

9. **Run gates.** `make check` and `make test`.

## Dev notes

- The `hello` op handler is structurally awkward — it lives in `server.py` rather than `dispatcher.py` because mismatch needs to call `server.close()`. An alternative is to pass the `asyncio.Server` into the dispatcher; the architecture doesn't prescribe one. Keeping `hello` in `server.py` is the smaller diff and reflects that handshake is connection-level concern, not op-level.
- `importlib.metadata.version("chirp")` reads the installed package version. In an editable install it reads from `pyproject.toml`. In a wheel it reads from the wheel metadata. Both work — verify on the smoke test.
- The socket-cleanup-on-startup behavior (`os.unlink` if stale file exists) is necessary because Unix sockets don't auto-clean on process death. Architecture § Single-Instance Enforcement assumes the flock is the source of truth — if the flock is free, any stale socket is safe to unlink.
- The `RotatingFileHandler` ships with stdlib; no new dependency.
- Logfmt is human-greppable. After the manual smoke test, `tail -f ~/Library/Logs/chirp/chirpd.log` shows the connection events.
- The version-mismatch + immediate-exit path is hard to test cleanly without flakiness. The in-process integration test in AC-14 uses `asyncio.wait_for(serve_task, timeout=1.0)` to bound the wait; if the daemon hasn't returned within 1 s, the test fails — that's exactly the NFR-R5 budget.
