# Story 3.5 — Model lifecycle: state machine, registry reader, `model.load` / `model.unload` / `model.list` / `model.status`, idle-unload scheduler

- **Status:** Draft
- **Epic:** [EPIC-CHIRPD-CORE](../epic.md)
- **Depends on:** 3.4
- **Blocks:** 3.6, 3.7

## User story

As a chirp client, I want the daemon to track which models are loaded, lazily load a model by alias on demand, unload chat-role models after an idle period, keep embed-role models pinned, and answer `model.list` / `model.status` so I can see the current state, so that the inference ops added in the next story have a real lifecycle to drive and the eventual `chirp daemon status` command (EPIC-DAEMON-LIFECYCLE) has data to render.

## Context

This story adds:

1. **`llm/registry.py` (read-only side):** a `read_registry()` function that parses `~/Library/Application Support/chirp/models.toml` via Pydantic. The writer side (`chirp models add` and friends) is EPIC-MODEL-REGISTRY; this story delivers only the reader because the daemon needs to resolve aliases. Architecture § Configuration & Persistence; FR37 (read), FR38, FR35, FR36.
2. **`chirpd/state.py`:** the `LoadedModel` dataclass and a `DaemonState` container that tracks all loaded models, per-model `asyncio.Lock`s, and per-model idle-unload tasks. Architecture § Model Lifecycle State Machine.
3. **`chirpd/dispatcher.py`** extension: handlers for `model.list`, `model.load`, `model.unload`, `model.status`. Implements FR4, FR5, FR6, FR7, FR9, FR10.
4. **Idle-unload scheduler logic** in `chirpd/state.py`: scheduled per-model after each chat op completes (FR5), skipped for embed-role models (FR6), respects `keep_alive` overrides (FR7). Architecture § Model Lifecycle State Machine → Idle-unload scheduler.
5. **`llm/client.py`** extensions: real implementations of `model_list()`, `model_load()`, `model_unload()`, `model_status()` (replacing the `NotImplementedError` stubs from 3.4).

Inference (`chat`, `embed`, `cancel`) still doesn't work after this story — it lands in story 3.6. But the **lifecycle** the inference handlers will plug into is in place and testable via `FakeBackend`. The architecture's `LLMBackend` protocol is defined in this story (in `chirpd/backend.py`) and used by the load/unload paths; the inference methods on `MLXBackend` are stubbed and filled in by 3.6.

## Acceptance criteria

### Registry reader (`llm/registry.py`)

- **AC-1 (Pydantic model for `models.toml`):** Defines two classes:
  ```python
  class RegistryEntry(BaseModel):
      hf_repo: str
      role: Literal["chat", "embed"]
      options: dict[str, Any] = Field(default_factory=dict)

  class Registry(BaseModel):
      schema_version: int
      default_chat: str | None = None
      default_embed: str | None = None
      models: dict[str, RegistryEntry]
  ```
  Implements FR37 schema (reader side).
- **AC-2 (`read_registry(path: Path | None = None) -> Registry`):** Reads `models.toml`. Path defaults to `~/Library/Application Support/chirp/models.toml`. On `FileNotFoundError`: returns an empty `Registry(schema_version=1, models={})` rather than raising — the daemon must be runnable before any model is registered. On TOML parse error: raises `LLMMalformedResponse` (chosen because it's the closest existing exception class for "registry file is malformed").
- **AC-3 (alpha schema-version gate):** Per architecture § Model Registry Read/Write and PRD §Alpha-stage simplifications: the reader accepts only `schema_version == 1`. On any other value, raises `LLMModelNotFound("models.toml schema_version {v} not supported; re-init your registry with `chirp models init` (coming in EPIC-MODEL-REGISTRY)")`. No migration pipeline. Architecture § Configuration & Persistence; PRD § Open Questions → Alpha-stage simplifications.
- **AC-4 (alias resolution helper):** `resolve_alias(registry: Registry, identifier: str, role: Literal["chat", "embed"]) -> RegistryEntry` returns the matching entry. Resolution rules per FR35 + FR36:
  1. `identifier == "default"`: look up `registry.default_chat` or `registry.default_embed` per the `role` argument; raise `LLMModelNotFound` if no default is set for that role.
  2. `identifier` exists in `registry.models`: return that entry.
  3. `identifier` contains a `/` (e.g., `mlx-community/gemma-4-4b-it-4bit`): synthesize an ad-hoc entry with `hf_repo=identifier`, `role=role`, `options={}`. Used for one-off model testing per FR36.
  4. Otherwise: raise `LLMModelNotFound(f"unknown model alias '{identifier}'")`.

### Daemon state (`chirpd/state.py`)

- **AC-5 (`LoadedModel` dataclass):** Per architecture § Model Lifecycle State Machine:
  ```python
  @dataclass
  class LoadedModel:
      alias: str
      role: Literal["chat", "embed"]
      handle: Any                 # backend-specific model+tokenizer object
      last_used: datetime
      idle_unload_task: asyncio.Task | None  # only set for chat models
      lock: asyncio.Lock          # mutex for load/unload/op on this model
      loaded_at: datetime
  ```
  The dataclass lives in `chirpd/state.py`.
- **AC-6 (`DaemonState` container):**
  ```python
  class DaemonState:
      def __init__(self, backend: LLMBackend, registry: Registry, idle_timeout_s: float): ...
      async def load(self, identifier: str, role: Literal["chat", "embed"]) -> LoadedModel: ...
      async def unload(self, alias: str) -> None: ...
      def list_models(self) -> list[dict]: ...  # for model.list op
      def status(self) -> dict: ...             # for model.status op
      def get(self, alias: str) -> LoadedModel | None: ...
  ```
  - `load(...)` resolves the identifier via `resolve_alias`, acquires the per-model lock, and (if not already loaded) calls `backend.load(...)`. Idempotent: calling `load` on an already-loaded model updates `last_used` and reschedules the idle-unload timer (chat only). Implements FR5, FR9.
  - `unload(...)` acquires the per-model lock, calls `backend.unload(handle)`, cancels any pending idle-unload task, removes the entry. Implements FR10.
  - `list_models()` returns per-model summary dicts: `{alias, role, hf_repo, loaded, last_used_seconds_ago}` for **registered** models. Includes both loaded and registered-but-unloaded models. Drives FR4 (`model.list`) and `chirp models list` later.
  - `status()` returns a richer dict for `model.status`: per loaded model, `{alias, role, loaded_at, last_used, idle_countdown_seconds, rss_bytes}`. Plus process-wide `pid`, `uptime_seconds`, `daemon_version`. Implements FR4 / NFR-O3.
  - `get(alias)` returns the `LoadedModel` if loaded, else `None`.
- **AC-7 (idle-unload scheduler):** Per architecture § Model Lifecycle State Machine → Idle-unload scheduler. When a chat op completes (story 3.6 will call this hook), `DaemonState` exposes `schedule_idle_unload(model: LoadedModel, keep_alive: int | None) -> None`:
  - `keep_alive is None`: schedule a fresh `idle_unload_task` that sleeps `idle_timeout_s` then unloads.
  - `keep_alive == -1`: cancel any existing task; do not schedule. Pinned. FR7.
  - `keep_alive == 0`: cancel any existing task; schedule an immediate unload coroutine. FR7.
  - `keep_alive > 0`: schedule with that timeout (seconds).
  - Embed-role models never get scheduled regardless of `keep_alive`. FR6.
  - Idle-unload task stored on the `LoadedModel` instance (per architecture's anti-pattern note: "always assign to a stored variable").
  - The scheduler re-checks `last_used` inside the task before unloading (architecture § Model Lifecycle State Machine): if `last_used` advanced during the sleep (a new request arrived and reset the timer), skip the unload — that case is impossible because the new request's `schedule_idle_unload` call would have cancelled this task, but defensive belt-and-suspenders is cheap.
- **AC-8 (RSS reporting):** `DaemonState.status()` reads process RSS via `psutil.Process(os.getpid()).memory_info().rss`. `psutil` is added as a project dependency in this story (NFR-M4 hygiene — declare explicitly in `pyproject.toml`). NFR-O3.
- **AC-9 (idle-timeout config source):** The `idle_timeout_s` is read from (in precedence order): `os.environ.get("CHIRP_MODEL_IDLE_TIMEOUT")` → `config.settings.get_settings().llm.idle_timeout_seconds` → default `300.0` (matches Ollama and FR5). The `[llm]` section in `config/settings.py` is added in this story.

### Backend protocol (`chirpd/backend.py`)

- **AC-10 (`LLMBackend` Protocol):** Per architecture § Testing Patterns:
  ```python
  class LLMBackend(Protocol):
      async def load(self, repo: str, role: Literal["chat", "embed"]) -> Any: ...
      async def unload(self, handle: Any) -> None: ...
      # The two below are stubbed here; real impls land in story 3.6:
      async def stream_generate(self, handle, messages, options, should_stop): ...
      async def embed(self, handle, inputs): ...
  ```
- **AC-11 (`MLXBackend` class — load/unload only in this story):**
  - `async def load(self, repo: str, role) -> dict`: resolves the local path via `huggingface_hub.snapshot_download(repo, local_files_only=True)` wrapped in `asyncio.to_thread` (architecture § Async Patterns; § Gap Analysis → HF-cache-lookup refinement). On `LocalEntryNotFoundError`: raises `LLMModelLoadFailed(f"weights not in HF cache for '{repo}'; run `chirp models pull <alias>` to download", details={...})` per NFR-R7. On success: calls `mlx_lm.load(local_path)` in `asyncio.to_thread`, returns the model handle. Implements FR38 and the HF-cache-lookup refinement.
  - `async def unload(self, handle) -> None`: drops the reference, triggers Python GC (a `del handle; gc.collect()` may be needed to release MLX-allocated memory promptly per NFR-P5; verify in manual testing).
  - `stream_generate` and `embed` raise `NotImplementedError` in this story; story 3.6 fills them in.
- **AC-12 (`FakeBackend` class):**
  - In-process test double exposing the same Protocol.
  - `load(repo, role)` returns a deterministic fake handle (e.g., `{"repo": repo, "role": role, "loaded": True}`) after a configurable delay (default 0).
  - `unload(handle)` clears the handle dict.
  - `stream_generate` and `embed` yield scripted token sequences and vectors respectively (filled in by story 3.6's tests; in this story they raise `NotImplementedError`).
  - Lives in `chirpd/backend.py` next to `MLXBackend`. **Not** a test helper — production code uses the protocol, and `FakeBackend` is the unit-test implementation. Architecture § Testing Patterns.

### Dispatcher ops

- **AC-13 (`model.load`):** Per FR9. Request: `{"id": "...", "op": "model.load", "model": "<alias-or-default-or-org/repo>", "role": "chat|embed"}` (role defaults to `"chat"` if omitted). Daemon:
  1. Emits `{"event": "loading", "model": "<alias>"}` immediately.
  2. Calls `state.load(model, role)`. On failure, emits `error` with the exception's `code` and message.
  3. On success, emits `{"event": "ready", "model": "<alias>", "role": "<role>"}` followed by `{"event": "done"}`.
- **AC-14 (`model.unload`):** Per FR10. Request: `{"id": "...", "op": "model.unload", "model": "<alias>"}`. Daemon calls `state.unload(alias)` and emits `done`. If the model wasn't loaded, emits `done` with no error (idempotent).
- **AC-15 (`model.list`):** Per FR4 (the registry-state half of it). Returns one `{"event": "status", "models": [...]}` then `done`. The `models` list comes from `DaemonState.list_models()`.
- **AC-16 (`model.status`):** Per FR4. Returns one `{"event": "status", ...}` with the rich payload from `DaemonState.status()` (per-model loaded state, RSS, idle-countdown, daemon uptime), then `done`.
- **AC-17 (dispatcher wiring):** `Dispatcher.__init__` now accepts a `DaemonState` instance. The `dispatch` method's op-branching grows new arms for `model.list`, `model.load`, `model.unload`, `model.status`. The existing `health` and `hello` paths remain unchanged. The `error`-event boundary from story 3.3 AC-9 still wraps the entire dispatch body.

### Client extensions

- **AC-18 (`LLMClient.model_list`):**
  ```python
  async def model_list(self) -> list[dict]:
      envelope = {"id": new_request_id(), "op": OP_MODEL_LIST}
      events = [event async for event in self._request(envelope)]
      status_event = next(e for e in events if e["event"] == EVENT_STATUS)
      return status_event["models"]
  ```
- **AC-19 (`LLMClient.model_load`):**
  ```python
  async def model_load(self, model: str, role: Literal["chat", "embed"] = "chat") -> None:
      envelope = {"id": new_request_id(), "op": OP_MODEL_LOAD, "model": model, "role": role}
      async for event in self._request(envelope):
          if event["event"] == EVENT_ERROR:
              # _request raises before yielding — defensive
              return
  ```
- **AC-20 (`LLMClient.model_unload`):** Same shape as `model_load` but with `OP_MODEL_UNLOAD`.
- **AC-21 (`LLMClient.model_status`):** Returns the rich dict from `DaemonState.status()`.
- **AC-22 (sync wrappers):** `model_list_sync`, `model_load_sync`, `model_unload_sync`, `model_status_sync` — each one `asyncio.run`s the async form. Convenience for sync call sites.

## Dev notes

- The `MLXBackend.load` path performs a HuggingFace cache lookup with `local_files_only=True` per architecture § Gap Analysis → HF-cache-lookup refinement. This means `huggingface_hub` is imported by the daemon, but its network APIs (`HfApi.download`, etc.) are never called from `chirpd/`. The download side lives in `llm/hf.py` and is invoked from the CLI (story owned by EPIC-MODEL-REGISTRY).
- The idle-unload scheduler is the trickiest piece. Walk through the state machine: model loaded → chat op completes → `schedule_idle_unload(model, keep_alive)` is called → if a task already exists, cancel it; schedule a new one. The "re-check `last_used` after sleep" defense from architecture is cheap belt-and-suspenders; the cancellation discipline is the real correctness.
- Reading `models.toml` happens **on every `model.load`/`model.list`/`model.status`** per architecture § Configuration & Persistence (no hot-reload; daemon doesn't watch the file). The CLI writes atomically via `os.replace` (EPIC-MODEL-REGISTRY). Race: the daemon could see either old or new state, never a partial file.
- `LoadedModel.lock` is acquired around the inference call (story 3.6) **and** around load/unload. Holding the lock spans the inference because `mlx_lm.stream_generate` is in `asyncio.to_thread` — the event loop is not blocked, just the per-model serialization is enforced. Architecture § Async Patterns.
- `gc.collect()` after `del handle` — verify experimentally that MLX-allocated GPU memory is reclaimed promptly. If not, add a `model.flush()` or equivalent and document. NFR-P5 is the relevant budget.
- The `_sync` wrappers exist for ergonomic call sites; the `notes_chat/cli.py` cutover in story 3.7 picks one form based on what fits the existing sync flow.
