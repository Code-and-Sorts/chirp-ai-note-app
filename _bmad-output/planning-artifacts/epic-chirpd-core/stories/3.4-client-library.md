# Story 3.4 — Client library: connect, lazy-spawn, version-mismatch handling, exception mapping

- **Status:** Draft
- **Epic:** [EPIC-CHIRPD-CORE](../epic.md)
- **Depends on:** 3.3
- **Blocks:** 3.5, 3.6, 3.7

## User story

As a chirp module author (in `notes_chat`, `notes`, or any other chirp surface), I want a small `llm.client` library that hides the unix-socket transport, lazy-spawns `chirpd` when no daemon is running, transparently survives a version-mismatch by respawning and retrying once, and raises a typed exception hierarchy that distinguishes transport failures from model failures, so that call sites read like a normal Python function call against a well-defined contract.

## Context

This story creates the client-side counterpart to story 3.3's daemon. The daemon already implements the `hello` and `health` ops; the client must:

1. Auto-discover the socket path (env override > config > built-in default). Architecture § Configuration & Persistence.
2. Open a unix-socket connection. On `FileNotFoundError` or `ConnectionRefusedError`, lazy-spawn `chirpd` via `subprocess.Popen` and poll the socket until it accepts (≤ 3 s — NFR-P6). Architecture § Single-Instance Enforcement → Lazy-spawn race scenario; FR19.
3. Send `hello` with the client's version. On `ready`: connection is usable. On `version_mismatch`: close, wait for the daemon to exit (the daemon does this immediately per architecture § State Machine), lazy-spawn a fresh daemon, send `hello` again, retry the original request exactly once. Architecture § State Machine — Version Handshake & Drain; FR13, FR14, FR20.
4. Issue a single request per connection (architecture § IPC Protocol → Connection lifecycle).
5. Map wire `error` events to the typed exception hierarchy from story 3.2.

The client surface this story delivers is enough to power story 3.5's tests (`client.health()` already works after this story; `client.model_list()` and `client.model_load()` are real after 3.5; `client.chat()` / `client.embed()` are real after 3.6).

## Acceptance criteria

- **AC-1 (socket-path discovery):** `llm/client.py` exposes a `resolve_socket_path() -> Path` helper that returns, in precedence order:
  1. `os.environ.get("CHIRP_DAEMON_SOCKET")` if set
  2. The `[llm].daemon_socket` value from `~/.chirp/config.toml` if present (read via the existing `config.settings.get_settings()` or equivalent)
  3. Built-in default `~/Library/Application Support/chirp/chirpd.sock`
  Implements FR18; PRD §Config Schema → environment variable overrides.
- **AC-2 (LLMClient class):** `llm/client.py` exposes class `LLMClient` with:
  - `__init__(self, socket_path: Path | None = None, spawn_timeout_s: float = 3.0, retry_on_version_mismatch: bool = True)`. `socket_path` defaults via `resolve_socket_path()`. The spawn timeout is bounded by NFR-P6 (3 s).
  - Public async methods (subset implemented in this story): `async def health(self) -> dict`. Returns the `ready` event payload from the daemon's `health` op.
  - The other methods (`model_list`, `model_load`, `model_unload`, `model_status`, `chat`, `embed`, `cancel`) are stubbed with `raise NotImplementedError` and filled in by stories 3.5 / 3.6 — but the constructor and the connect/retry plumbing must be complete.
  - A synchronous wrapper for the sync call-site case: `def health_sync(self) -> dict` runs `asyncio.run(self.health())`. Reusable wrapper helpers (`_sync(coro)`) live in `llm/client.py`; sync wrappers for the other ops land with their async counterparts in later stories.
- **AC-3 (lazy-spawn):** When `LLMClient` connects and the socket file does not exist (or `ConnectionRefusedError` on connect), the client:
  1. Spawns `chirpd` via `subprocess.Popen(["chirpd"], start_new_session=True, stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)`. The `start_new_session=True` detaches it so the parent CLI can exit without taking the daemon with it.
  2. Polls `self.socket_path` for a connect-accepting socket: try `await asyncio.open_unix_connection(...)` every 50 ms (architecture's recommended cadence) up to `spawn_timeout_s` seconds (default 3.0 per NFR-P6).
  3. On success: proceed with the `hello` handshake.
  4. On timeout: raise `LLMDaemonSpawnFailed("chirpd did not accept connections within {spawn_timeout_s}s")`.
  Implements FR19, NFR-P6.
- **AC-4 (`hello` handshake on every connect):** Per FR13. After connecting, the client:
  1. Reads its own version from `importlib.metadata.version("chirp")`.
  2. Sends `{"id": new_request_id(), "op": "hello", "client_version": "X.Y.Z"}`.
  3. Reads one event line. Cases:
     - `{"event": "ready", ...}`: handshake complete.
     - `{"event": "version_mismatch", "daemon_version": "Y.Y.Y"}`: see AC-5.
     - Anything else: raise `LLMMalformedResponse` with code `PROTOCOL_MALFORMED`.
- **AC-5 (version-mismatch one-shot retry):** Per architecture § State Machine — Version Handshake & Drain and FR20. On `version_mismatch`:
  1. Close the current connection.
  2. Poll the socket path until it no longer accepts connections (daemon is exiting). Timeout: 1 s. Architecture § State Machine.
  3. Lazy-spawn a fresh daemon (same logic as AC-3, same timeout). Poll until accepting.
  4. Reconnect and send `hello` again.
  5. If the second `hello` also returns `version_mismatch`: raise `LLMVersionMismatch` (this should not happen in normal operation; defensive).
  6. If the second `hello` succeeds: replay the **original** request the caller was making. The retry is exactly once. Subsequent failures surface to the caller. Implements NFR-R5 (user-observed pause ≤ 2 s on M2).
  7. If `retry_on_version_mismatch=False` was passed to `LLMClient.__init__`, skip the retry path entirely and raise `LLMVersionMismatch` immediately on first mismatch. Used by tests and by the daemon-control CLI in EPIC-DAEMON-LIFECYCLE.
- **AC-6 (request method):** Internal `async def _request(self, envelope: dict) -> AsyncIterator[dict]` that:
  1. Opens a fresh connection (one request per connection per architecture).
  2. Performs the handshake (AC-4 / AC-5).
  3. Sends the envelope.
  4. Reads events line-by-line until an `event` in `{"done", "error", "version_mismatch"}` arrives.
  5. Yields each event dict to the caller.
  6. On `error` event: maps `code` → exception class via `llm.error_codes.CODE_TO_EXCEPTION`, raises with `message` and `details` from the event.
  7. On `version_mismatch` mid-stream: triggers the retry path (rare; would happen only if the daemon was restarted between handshake and request — defensive).
  8. On socket EOF or `BrokenPipeError` mid-stream: raises `LLMConnectionLost` (code attribute `None` — client-constructed).
  Implements FR21 (streaming + non-streaming both flow through this iterator), FR22 (batched embed is one envelope in, list of vectors out), FR23 (exception types distinguish model vs transport failures).
- **AC-7 (`health` method):** `async def health(self) -> dict`:
  - Builds envelope `{"id": new_request_id(), "op": "health"}`.
  - Iterates `_request(envelope)` and collects the events.
  - Returns the final `ready` event payload (with `status`, `uptime_seconds`, `version` keys per story 3.3 AC-7).
  - Closes the connection cleanly.
- **AC-8 (error mapping):** When the daemon emits `{event: "error", code: "MODEL_LOAD_FAILED", message: "...", details: {...}}`, the client raises `LLMModelLoadFailed("...", details={...})`. Same for every code in `llm.error_codes.CODE_TO_EXCEPTION`. Test coverage: one test case per declared wire code. FR23.
- **AC-9 (transport exceptions):**
  - `LLMDaemonUnreachable` raised when the socket exists but `ConnectionRefusedError` after both initial connect and retry-after-spawn.
  - `LLMConnectionLost` raised on `BrokenPipeError`, `ConnectionResetError`, or unexpected EOF mid-stream.
  - `LLMDaemonSpawnFailed` raised when `subprocess.Popen` fails (rare — `FileNotFoundError` on `chirpd`) or when polling times out per AC-3.
- **AC-10 (no leaked subprocesses or sockets):** Every code path that opens a connection closes it (try/finally or async context manager). Every spawn that fails has its `Popen` reaped (`proc.wait()` on the failure branch). Tests assert no orphan processes after a battery of failing requests.
- **AC-11 (tests under `tests/llm/`):**
  - `tests/llm/test_client.py`:
    - `test_health_against_in_process_daemon` — spawn `chirpd.server.serve()` in-process via `asyncio.start_unix_server`, connect via `LLMClient` with `socket_path=<temp>`, call `health()`, assert the returned dict has `status="ok"` and a `version` key.
    - `test_resolve_socket_path_env_overrides_default` — set `CHIRP_DAEMON_SOCKET=/tmp/foo.sock`; assert `resolve_socket_path() == Path("/tmp/foo.sock")`.
    - `test_resolve_socket_path_config_overrides_default` — patch `get_settings()` to return a `[llm].daemon_socket` value; assert it wins over the built-in default.
    - `test_resolve_socket_path_default` — neither env nor config set; assert default path.
    - `test_lazy_spawn_when_socket_missing` — point at a non-existent socket; monkeypatch `subprocess.Popen` to spawn a fake daemon (a small Python script that mimics `hello → ready → health → ready + done`); assert the client recovers and `health()` succeeds. Mark `@pytest.mark.integration` for visibility, but it does not require the real `chirpd` binary.
    - `test_lazy_spawn_timeout_raises_daemon_spawn_failed` — point at a non-existent socket; monkeypatch `Popen` to spawn `sleep 10` (something that never accepts on the socket); assert `LLMDaemonSpawnFailed` after `spawn_timeout_s` (use `spawn_timeout_s=0.5` for test speed).
    - `test_version_mismatch_triggers_respawn_and_retry` — fake-daemon scaffold that responds `version_mismatch` on the first hello, exits, and a *second* fake daemon (spawned by the client's lazy-spawn during retry) responds `ready` on the next hello. Assert the second daemon's `health()` succeeds. NFR-R5 user-pause budget: assert overall time ≤ 2.0 s.
    - `test_version_mismatch_retry_disabled_raises` — same setup with `retry_on_version_mismatch=False`; assert `LLMVersionMismatch` raised on first mismatch.
    - `test_error_event_maps_to_typed_exception` — fake daemon that emits `{event: "error", code: "MODEL_LOAD_FAILED", ...}`; assert `LLMModelLoadFailed` raised with matching message + details. Parametrize over every code in `CODE_TO_EXCEPTION`.
    - `test_connection_lost_raises_typed_exception` — fake daemon that accepts the hello, then closes mid-stream after the first event; assert `LLMConnectionLost`.
    - `test_malformed_response_raises_typed_exception` — fake daemon that emits a non-JSON line after `ready`; assert `LLMMalformedResponse`.
    - `test_health_works_against_real_chirpd_in_process` — start `chirpd.server.serve()` in-process (real code, not a fake); assert `health_sync()` succeeds and returns a dict with `status="ok"`.
  - `tests/llm/conftest.py`:
    - `temp_socket_path` fixture: yields a temp socket path inside the test's tmp dir.
    - `in_process_daemon` fixture: starts `chirpd.server.serve()` as an asyncio task against the temp socket; cleans up on teardown.
    - `fake_daemon_factory` fixture: returns a helper that runs a small async handler against the temp socket with scripted responses. Useful for the version-mismatch and error-mapping tests.

## Implementation tasks

1. **`llm/client.py` skeleton.**
   - Constants: `DEFAULT_SOCKET_PATH = Path.home() / "Library" / "Application Support" / "chirp" / "chirpd.sock"`, `DEFAULT_SPAWN_TIMEOUT_S = 3.0`, `VERSION_MISMATCH_RESPAWN_WAIT_S = 1.0`.
   - `def resolve_socket_path() -> Path`: env → config → default.
   - Class `LLMClient` with `__init__` and stubs for the unimplemented ops.

2. **Connection + handshake helpers (private).**
   - `async def _open_connection(self) -> tuple[asyncio.StreamReader, asyncio.StreamWriter]`: connects with lazy-spawn fallback (per AC-3). Returns the reader/writer pair after a successful `hello → ready` handshake. Internally handles the version-mismatch retry per AC-5.
   - `async def _spawn_daemon(self) -> None`: `subprocess.Popen` + poll until accepting.
   - `async def _wait_for_socket_gone(self, timeout_s: float) -> None`: polls until connect fails; used during version-mismatch teardown.
   - `async def _do_hello(self, reader, writer) -> dict`: sends hello, reads one event, returns it or raises.

3. **`async def _request(self, envelope)` iterator.** Per AC-6. The iterator owns the connection lifetime — open at `__aiter__`, close in a finally. Caller iterates events; the iterator translates `error` events into raised exceptions via `CODE_TO_EXCEPTION`.

4. **`health()` method.** Per AC-7. Simple loop over `_request` collecting events.

5. **Sync wrappers.** `def health_sync(self) -> dict`: `asyncio.run(self.health())`. Reusable helper `_run_sync(coro)` for the methods that come in later stories.

6. **Tests under `tests/llm/`.** Per AC-11. The `fake_daemon_factory` fixture is reusable across many tests — invest in it. A fake-daemon scaffold could be ~80 lines using `asyncio.start_unix_server` with a scripted handler.

7. **Integration test against real `chirpd.server.serve()`.** Start the real daemon code in an asyncio task (no subprocess) against a temp socket. Assert `health()` works. This is the integration boundary architecture § Testing Patterns calls out.

8. **Run gates.** `make check`, `make test`, coverage ≥ 90% on `llm/client.py`.

## Dev notes

- The "one request per connection" contract means every `LLMClient` method opens a fresh socket. Cheap on a unix socket, simplifies cancel/error semantics, and is what architecture § IPC Protocol locks.
- The handshake happens on **every** connection — including the in-process integration tests. That means the in-process daemon test must also pass a matching client version. `importlib.metadata.version("chirp")` returns the same string for both sides, so they match naturally; deliberately-mismatched tests monkeypatch the value the client sends.
- `start_new_session=True` on `subprocess.Popen` detaches the daemon from the CLI's process group. Without it, a Ctrl+C in the parent CLI would also kill the daemon.
- The fake-daemon scaffold in tests is the same shape used for `test_error_event_maps_to_typed_exception` and `test_version_mismatch_triggers_respawn_and_retry`. Build it once and reuse via a fixture.
- The version-mismatch retry path is the most complex code in this story. Walk through it in the PR description: connect → hello → version_mismatch → close → wait_for_socket_gone → spawn → poll → connect → hello → ready → original_request. The unit test in AC-11 walks through this; the integration test in story 3.7 walks through the real `chirpd` binary.
- `LLMConnectionLost` is client-constructed (no wire code). It maps to `MODEL_GENERATION_FAILED` with cause `daemon_shutdown` on the daemon side (NFR-R6), but the client surfaces it as a transport error because — from the caller's perspective — the daemon disappeared.
- The interactive sync wrapper convention: every async method gets a `*_sync` companion. Story 3.7 (the `chirp ask` cutover) decides whether to call the async or sync form based on what `notes_chat/cli.py` already does.
