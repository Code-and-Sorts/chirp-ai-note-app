## User story

As a Chirp maintainer, I want the `ollama` Python client to no longer be listed as a runtime dependency in `pyproject.toml` so that `pip install chirp-notes-ai` no longer pulls in the unused library, the dependency-surface check is honest about what we actually ship, and contributors don't accidentally re-introduce `import ollama` thinking the dep is still around.

## Context

`pyproject.toml` currently declares `"ollama>=0.1.0"` in `[project] dependencies` (line 19). It is the only Ollama-related dep declared by chirp. The `uv.lock` file has corresponding entries.

After EPIC-INTEGRATION-CUTOVER, no production or test code imports `ollama`. Leaving the dep declared has two costs: (a) `pip install chirp-notes-ai` still pulls and installs the package, bloating the install footprint for no purpose; (b) the dependency declaration is a documentation lie — the README and AGENTS.md (after story 7.5) will say chirp does not use Ollama, while the manifest disagrees.

This story is a small but final cleanup: edit the dep line out, refresh the lockfile, prune Ollama-mentioning Makefile targets, and run the test suite to confirm nothing breaks.

**`mlx-lm` and `huggingface_hub` are NOT touched here.** They are added by EPIC-CHIRPD-CORE story 3.1. This story only handles the removal half of FR55.

**`make verify-deps`** is the existing repo-supported smoke check (AGENTS.md). It currently runs `chirp init --recheck`. After story 7.1, that flow no longer references Ollama. After this story, the `Makefile` target itself has its Ollama mentions removed (the post-install hints `Install Ollama: make setup-ollama`, the `setup-ollama` target itself, the smoke-import comment `Notes chat may need Ollama running`).

Files to touch:

- **`pyproject.toml`** — remove line 19 (`"ollama>=0.1.0",`).
- **`uv.lock`** — regenerated by `uv lock`. Should drop the `ollama` package entry and any transitive deps unique to it.
- **`Makefile`** — prune the Ollama-mentioning lines listed below.
- **`tests/`** — verify nothing was left behind that requires the package.

## Dev notes

- **Why this is its own story, not bundled with the integration cutover.** Removing the dep is a single-line edit, but its safety depends on the integration cutover being **complete and merged**. If it were bundled with the last cutover PR, the PR's "did the integration cutover land cleanly" gate would be tangled with "did the deps clean up properly" — making rollback harder. As a standalone story it lands as a small, easy-to-revert change.
- **Why the lockfile diff lands in the same commit.** Splitting `pyproject.toml` and `uv.lock` across two commits leaves a transient state where the manifest says "no ollama" but the lockfile still pins it. Reviewers and CI on the intermediate commit would see drift. One commit avoids that.
- **Why we re-run `make verify-deps` here.** AGENTS.md says `make verify-deps` is one of the three repo-supported smoke checks. It's the last place an Ollama reference could leak into user-visible output. We verify it's clean before claiming the migration is done.
- **Don't bump unrelated deps in this commit.** `uv lock` may surface other updates available; resist the temptation to absorb them. Keep this commit scoped to the `ollama` removal so a future bisect over "the day we dropped ollama" is unambiguous.
- **Why the `setup-ollama` Makefile target is deleted (not replaced).** Its post-MVP replacement (`chirp models add`) is a chirp subcommand, not a Make target. Documenting it in `make help` would duplicate `chirp --help`. Better to delete and let `chirp --help` be the single source.
- **What if `make verify-deps` was already pruned earlier (e.g. story 1.5)?** Verify with `grep -n "ollama" Makefile`. If empty, AC-4 is a no-op for the Makefile portion — note this in the PR description.
- **Watch out for `httpx` / `requests` transitive deps.** The `ollama` Python client pulls in `httpx`. Other chirp modules (`notes_chat/index.py` historically used `requests`) may have their own HTTP deps. Don't assume removing `ollama` removes `httpx` — check the `uv.lock` diff and confirm with `uv pip list` that the surviving deps are intentional.
- **Coordinate with `verify-deps` history.** Earlier work (EPIC-WF-ALIGN, EPIC-AUDIO-CAPTURE) may have already trimmed parts of the Ollama Make-target wording. The lines noted in AC-4 are validated against current `main` on `story/2.3-blackhole-removal`. If those line numbers have shifted by the time this story runs, re-locate the strings via `grep -n -i "ollama" Makefile`.
