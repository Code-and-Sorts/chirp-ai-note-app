## User story

As a new Chirp user who reads the README before installing, I want zero references to Ollama anywhere in the docs — no "install Ollama" prerequisite, no "Generate notes with Ollama" feature bullet, no `ollama serve` instruction — so my mental model of chirp matches what `chirp init` actually does. The README should tell me to run `chirp models add` and `chirp ask`, not to install a third-party daemon.

As a contributor reading AGENTS.md, I want fixture-isolation guidance that talks about chirpd/MLX rather than Ollama, so I know which test seams matter today.

As an operator running `uv run chirp --help`, `uv run chirp config --help`, and `uv run chirp config --list`, I want zero "ollama" strings in the output — including the long-since-stale `--ollama-url` option and `Ollama URL: ...` line — so the CLI's self-documentation matches reality.

## Dev notes

- **Why this story lands after 7.4.** Story 7.4 removed the dep from `pyproject.toml`; this story verifies the docs say what the manifest says. Inverting the order would leave the docs in a transient state — "no Ollama" — while the manifest still ships it. The sequencing in the epic header is explicit about this.
- **Why the README's manual-setup block becomes shorter.** The whole point of the migration: from 5 steps (pip + brew install ollama + ollama serve + ollama pull + chirp init) down to 2-3 (pip + `chirp models add` + `chirp init`). The new manual-setup block should reflect this. Don't pad it with redundant explanation.
- **Why we recommend a specific model in the README (OQ1).** Epic decision 11 picks `mlx-community/gemma-4-4b-it-4bit` to match the PRD and story 7.1's `RECOMMENDED_CHAT_REPO` constant. If the team later decides to be model-agnostic in docs, that's a follow-up — keep the README aligned with the init prompt for now.
- **Why `--ollama-url` is removed wholesale, not deprecated with a warning.** Chirp is in alpha (PRD §Alpha-stage simplifications). No backwards compat. A user passing `--ollama-url` was using it to point at a non-default Ollama; that workflow is gone, the flag has no meaning, and a deprecation warning would be cruel-and-unusual to anyone scripting against `chirp config`.
- **Why we don't add a NEWS.md / CHANGELOG entry in this story.** If the project has one, the migration would be noted there; check `.docs/` for a CHANGELOG. If absent, don't introduce one in this story — that's project-policy work, not docs-sweep work.
- **Caution with greps.** `ollama` appears in commit history (`git log`), in `_bmad-output/` (planning docs including this very epic), and in any history/changelog directory. Exclude those from the verification grep, but **don't delete history files** — they're records of the migration.
- **Validate against live `chirp --help`.** AGENTS.md's "Claude-Specific Reminders" explicitly calls this out: "Validate doc updates against live CLI help before finishing." The AC-5 command list is the embodiment of that rule.
- **What if `chirp models --help` or `chirp daemon --help` aren't yet built into the CLI?** EPIC-MODEL-REGISTRY and EPIC-DAEMON-LIFECYCLE deliver them. This story depends on those (transitively, via 7.1's dependencies). If at story-execution time those subcommands aren't yet wired into `chirp/cli.py` via `app.add_typer(...)`, that's a wiring miss in the upstream epics — file an issue, don't paper over it here.
