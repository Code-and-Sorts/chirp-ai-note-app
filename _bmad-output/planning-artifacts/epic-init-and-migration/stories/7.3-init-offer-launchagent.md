## User story

As a Chirp user finishing first-run setup, I want `chirp init` to ask me — once, with a clear default — whether I'd like the chirpd daemon to start automatically at login, so my first morning `chirp ask` is warm instead of paying the cold-start lazy-spawn cost. If I say no, I want the question never to come back unless I explicitly ask for it.

As a user who just wants to try chirp without persistent background services, I want the default answer to be **no** so I'm not surprised by a new login agent registered in my system.

## Context

PRD FR52: "`chirp init` offers (but does not require) LaunchAgent installation, recording the user's choice for future runs." Architecture §Daemon Lifecycle Integration with launchd describes the install path (write `~/Library/LaunchAgents/com.chirp.chirpd.plist`, run `launchctl load`). EPIC-DAEMON-LIFECYCLE owns the implementation of that path; this story consumes it.

**The prompt is a single yes/no**, defaulting to **no** (epic decision 5). Rationale: a new login agent is a system-modifying action the user should opt into deliberately. Users who say yes get the auto-start convenience; users who say no get a fully-functional chirp that lazy-spawns the daemon on demand (per FR19).

**The prompt runs once per machine**, not on every `chirp init`. We persist the user's choice in `~/.chirp/config.toml` under a new `[init]` section with a `launch_agent_prompted_at` ISO timestamp. Subsequent `chirp init` runs check this field and skip the prompt unless `--recheck` is the active flag — `--recheck` should re-show the prompt if the LaunchAgent is currently not installed (so the user can revisit the decision after their first day with chirp).

**Detection of "is the LaunchAgent already installed"** uses `chirpd.launchd.is_launch_agent_installed()` (defined in EPIC-DAEMON-LIFECYCLE; presumed to return `True` when `~/Library/LaunchAgents/com.chirp.chirpd.plist` exists). When installed, the prompt is skipped regardless of the persisted flag — there's nothing to ask.

**The install path** uses `chirpd.launchd.install_launch_agent()` directly (or whatever the EPIC-DAEMON-LIFECYCLE story 5.x function is named). We prefer direct function calls over shelling to `chirp daemon enable` — same Python process, no startup cost, cleaner exception propagation. Both work; if EPIC-DAEMON-LIFECYCLE only exposes the subcommand and not a callable, this story falls back to subprocess invocation of `chirp daemon enable`.

**Prompt placement** in the new flow (from story 7.1): the prompt runs inside `_finalize_paths` (after the path summary, before the "your nest is ready" panel) on full `chirp init`, and inside `run_init`'s `--recheck` branch (after the verify table, after the migration plan if any) on `chirp init --recheck`. It does not run on `--switch-model`.

**Failure mode:** if `install_launch_agent()` raises (e.g., `launchctl load` fails), surface the error inline, mark the persisted flag with the attempted-at timestamp anyway (the user has been asked; they shouldn't be re-asked just because of a transient failure), and continue. The user can re-attempt via `chirp daemon enable` later.

Files to touch:

- **`chirp/init_flow.py`** — add `_offer_launch_agent(settings, console, force_prompt=False)`. Wire into `_finalize_paths` and `run_init` (`--recheck` branch).
- **`config/settings.py`** — add an `init` sub-config to `ChirpSettings` with a `launch_agent_prompted_at: datetime | None` field, default `None`.
- **`tests/test_init_flow.py`** — add tests for the four prompt-decision branches and the persistence behavior.

## Acceptance criteria

- **AC-1 — Single yes/no prompt with default no.** When the prompt fires, exactly one prompt is shown:
  ```
   chirp can start the daemon automatically at login so your first
   `chirp ask` of the day is warm. Otherwise, the daemon starts
   on-demand the first time you use chirp each session.

   Install LaunchAgent? [y/N]
  ```
  Default is `no` (capital `N`). Empty input or any non-affirmative input maps to no. Affirmative is `y`/`yes` (case-insensitive). Implements **FR52**.

- **AC-2 — Yes path installs the LaunchAgent.** On affirmative input, call `chirpd.launchd.install_launch_agent()` (or, fallback, `subprocess.run(["chirp", "daemon", "enable"], check=False)`). On success, print `[green]✓ LaunchAgent installed[/green]`. On failure, print `[red]✗ LaunchAgent install failed: {error}[/red]` along with the hint `[dim]you can retry later with 'chirp daemon enable'[/dim]`. Either way, persist the prompt timestamp (AC-4) so the user is not re-asked.

- **AC-3 — No path is silent.** On negative input (default `N`), no LaunchAgent is installed and no service is started. Print a single `[dim]· launch agent skipped (re-run with --recheck to revisit)[/dim]` line so the user has a breadcrumb. Persist the prompt timestamp (AC-4).

- **AC-4 — Persistence in `~/.chirp/config.toml`.** Add `[init] launch_agent_prompted_at = "<ISO-8601-UTC>"` to the config on either yes or no answer. The merge logic from `_merge_config` (story 1.5) is reused — existing keys are not clobbered. The `ChirpSettings` Pydantic model gains a new `InitConfig` submodel with a `launch_agent_prompted_at: datetime | None = None` field.

- **AC-5 — Prompt suppressed when already asked.** When `settings.init.launch_agent_prompted_at` is set and the current flag is **not** `--recheck`, the prompt does not run and no install attempt is made. The path summary in `_finalize_paths` still prints the "your nest is ready" panel.

- **AC-6 — `--recheck` revisits the prompt only when the agent is not installed.** When `--recheck` is the flag: if `chirpd.launchd.is_launch_agent_installed()` returns `False`, prompt regardless of `launch_agent_prompted_at` state (the user is revisiting). If it returns `True`, do not prompt — there's nothing to ask. Either way, the verify table and migration plan (story 7.2) have already printed before this prompt fires.

- **AC-7 — Prompt never runs on `--switch-model`.** `chirp init --switch-model` goes straight to the model-switching flow from story 7.1 and exits without touching the LaunchAgent prompt or the persistence field.

- **AC-8 — Prompt never runs when the agent is already installed.** If `chirpd.launchd.is_launch_agent_installed()` returns `True` at any prompt site, the prompt is skipped silently (no "already installed" line — too noisy). The persistence field is updated to the current timestamp if it was previously `None`, so a user who installed via `chirp daemon enable` and then runs `chirp init` doesn't get asked.

- **AC-9 — No prompt outside Apple Silicon Macs.** The Apple-Silicon gate from story 7.1 prevents this code from running on Intel — `_offer_launch_agent` is only reachable after the gate passes. Defensive: the function additionally short-circuits with no prompt and no error on non-Darwin (`platform.system() != "Darwin"`), since LaunchAgent is a macOS concept.

- **AC-10 — Tests in `tests/test_init_flow.py`.** Add the following tests, all of which mock `chirpd.launchd.is_launch_agent_installed`, `chirpd.launchd.install_launch_agent`, and the prompt-input function:
  - `test_launch_agent_prompt_default_no_skips_install` — prompt input is empty string; assert `install_launch_agent` is not called, `launch_agent_prompted_at` is set in the written config, and the "skipped" breadcrumb appears in output.
  - `test_launch_agent_prompt_yes_installs` — prompt input is `"y"`; assert `install_launch_agent` is called exactly once, the success line appears, and `launch_agent_prompted_at` is set.
  - `test_launch_agent_prompt_install_failure_persists_anyway` — prompt input is `"y"`, `install_launch_agent` raises `RuntimeError("launchctl load failed")`; assert the error line appears with the recovery hint, AND `launch_agent_prompted_at` is still set (the user was asked; don't re-ask on transient failure).
  - `test_launch_agent_prompt_suppressed_when_already_asked` — `launch_agent_prompted_at` is preset to a past timestamp, agent not installed, flag is `chirp init` (no `--recheck`); assert the prompt input function is never called and `install_launch_agent` is not invoked.
  - `test_launch_agent_prompt_recheck_revisits_when_not_installed` — `launch_agent_prompted_at` preset, agent not installed, flag is `--recheck`; assert the prompt input function IS called.
  - `test_launch_agent_prompt_skipped_when_agent_already_installed` — `is_launch_agent_installed` returns True; assert prompt input function is never called, no install attempt, no error.
  - `test_launch_agent_prompt_not_run_on_switch_model` — `--switch-model` flag with empty registry; assert prompt input function is never called.

- **AC-11 — Quality gates.** `make check` and `make test` pass. Coverage on `_offer_launch_agent` ≥ 90% line.

- **AC-12 — Manual fresh-box.** On a clean Apple Silicon Mac after stories 7.1/7.2 have landed: run `chirp init`, answer the LaunchAgent prompt with the default (Enter / `N`); confirm no `~/Library/LaunchAgents/com.chirp.chirpd.plist` exists and `launch_agent_prompted_at` is in `~/.chirp/config.toml`. Re-run `chirp init` — no prompt re-fires. Run `chirp init --recheck` — prompt re-fires (agent not installed). Answer `y` this time — `launchctl list | grep com.chirp.chirpd` shows the agent. Re-run `chirp init --recheck` — no prompt (agent installed).

## Implementation tasks

1. **Add `InitConfig` to `config/settings.py`.** New Pydantic submodel:
   ```python
   class InitConfig(BaseModel):
       launch_agent_prompted_at: datetime | None = None
   ```
   Add `init: InitConfig = Field(default_factory=InitConfig)` to `ChirpSettings`. Confirm the existing `_merge_config` writer round-trips the new field correctly (it serializes datetimes as ISO strings).

2. **Add `_offer_launch_agent(settings, console, force_prompt=False)`.** Function lives in `chirp/init_flow.py`. Logic:
   ```
   if platform.system() != "Darwin": return
   if is_launch_agent_installed():
       # nothing to ask; mark as prompted if not already
       if settings.init.launch_agent_prompted_at is None:
           _persist_prompt_timestamp(settings)
       return
   if not force_prompt and settings.init.launch_agent_prompted_at is not None:
       return
   answer = _confirm(console, "Install LaunchAgent?", default=False)
   if answer:
       try:
           install_launch_agent()
           console.print("[green]✓ LaunchAgent installed[/green]")
       except Exception as exc:
           console.print(f"[red]✗ LaunchAgent install failed: {exc}[/red]")
           console.print("[dim]you can retry later with 'chirp daemon enable'[/dim]")
   else:
       console.print("[dim]· launch agent skipped (re-run with --recheck to revisit)[/dim]")
   _persist_prompt_timestamp(settings)
   ```
   The `_confirm` helper already exists in `init_flow.py` (line 301) with a `default: bool` parameter.

3. **Add `_persist_prompt_timestamp(settings)`.** Helper that sets `settings.init.launch_agent_prompted_at = datetime.now(UTC)` and writes the updated config to disk via the existing `_merge_config` mechanism (or its equivalent that handles the `[init]` section). Make sure the writer doesn't clobber user-set keys in other sections.

4. **Wire into `run_init`.** Two call sites:
   - **Full init flow:** inside `_finalize_paths` (or just before it returns), after the path summary prints and before the "your nest is ready" panel. Pass `force_prompt=False`.
   - **Recheck branch:** in `run_init`'s `if recheck:` block, after the verify table and after the story 7.2 migration plan (if any), before `return 0`. Pass `force_prompt=True`.
   - **Switch-model branch:** do not call `_offer_launch_agent` at all.

5. **Import `chirpd.launchd` lazily.** Inside `_offer_launch_agent`, do `from chirpd.launchd import install_launch_agent, is_launch_agent_installed` rather than at module top. Reasons: (a) keeps `chirp init` from blowing up on import if `chirpd` is partially broken, (b) the launchd module is macOS-only — importing it on Linux during tests would error.

6. **Tests.** Implement the seven cases in AC-10. Use `unittest.mock.patch` for `chirpd.launchd.*` functions and `chirp.init_flow._confirm` (or whatever helper does the actual input read). Use a tmp `HOME` so `~/.chirp/config.toml` writes don't pollute the dev's real config. Assert the persisted timestamp via reading the tmp config back through `ChirpSettings`.

7. **Coverage check.** Run `make test-coverage` (or equivalent) to confirm `_offer_launch_agent` line coverage is ≥ 90%.

8. **Manual verification per AC-12.** Sequence: clean state → `init` → no → re-`init` → no prompt → `init --recheck` → prompt re-fires → yes → installed → `init --recheck` → no prompt.

## Dev notes

- **Why default no.** PRD users are split between "try chirp once" (don't want a login agent) and "long-term daily users" (want auto-start). Default-no means the curious user isn't surprised. The daily user can flip with `chirp daemon enable` or by running `chirp init --recheck` and answering yes.
- **Why persist the prompted-at timestamp.** Without persistence, every `chirp init` re-prompts the user, which conflicts with PRD's "init is idempotent" expectation (story 1.5 of EPIC-WF-ALIGN). Persisting the question lets `init` stay quiet on re-runs while `--recheck` remains the explicit revisit door.
- **Why `--recheck` re-prompts when the agent isn't installed.** Devon (migration) and Maya (try-then-decide) may want to revisit. `--recheck` is the universal "ask me again" flag — it already re-runs verify and (story 7.2) re-prints the migration plan. Adding "re-prompt for LaunchAgent" fits the pattern.
- **Why we persist the timestamp even on install failure.** Asking the user "Install LaunchAgent?" and then re-asking on the next `init` because `launchctl load` flaked is annoying. The user answered the question; the failure is a separate concern they can address via `chirp daemon logs` and `chirp daemon enable`.
- **Why we prefer the direct function call over `subprocess.run(["chirp", "daemon", "enable"])`.** Subprocess hop costs Python startup (~250 ms), forks a new process for no reason, and complicates error propagation (`launchctl` errors would need to be parsed from captured stderr instead of propagated as a typed Python exception). If EPIC-DAEMON-LIFECYCLE's `chirp daemon enable` is a thin wrapper around `chirpd.launchd.install_launch_agent`, call the underlying function.
- **Why the prompt block is short (3 lines + 1 question line).** UX research from comparable tools (Homebrew, `pyenv`, language version managers) shows that long prompts at the end of a setup flow are skipped or ignored. Three lines of explanation + one yes/no is the sweet spot for "users will read this."
- **Defensive non-Darwin guard.** Even though the Apple-Silicon gate from story 7.1 prevents Intel Macs from reaching this code, contributors running CI on Linux might end up here in tests. The `platform.system() != "Darwin"` short-circuit means tests can run on Linux without LaunchAgent code paths firing.
- **No "uninstall LaunchAgent" prompt.** Users who want to remove the agent run `chirp daemon disable`. `init`'s job is opt-in setup, not lifecycle management.
