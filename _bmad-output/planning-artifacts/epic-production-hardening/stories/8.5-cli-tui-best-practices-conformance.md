## User story

As a user who scripts `chirp`, I want data on stdout and diagnostics on stderr, a `--json` flag on the surfaces I pipe (`notes`, `ask`, `search`), and a `chirp --version` I can grep — so `chirp notes --json | jq` and `chirp --version` work in a pipeline without Rich chrome, hint lines, or table borders contaminating the data stream.

As a user who hits Ctrl-C at a `record` prompt, I want it to bail — not silently start a recording. Today, Ctrl-C at the **title** prompt aborts, but Ctrl-C at the **tags** prompt is swallowed and treated as "skip", so the recording starts anyway. Escape should mean escape everywhere in a prompt sequence.

As a non-vim user editing a note with `chirp notes edit N`, I want a visible keybinding hint and a `:help`/`?` screen so I'm not trapped in a modal editor with no clue how to save or quit — and, at minimum, an opt-in escape hatch to `$EDITOR`/`$VISUAL` so I can use the editor I already know.

As a `NO_COLOR` user (or anyone piping to a file), I want chirp to honor `NO_COLOR`/`FORCE_COLOR` and a `--no-color`/`--plain` flag, and I do not want the note renderer's `force_terminal=True` to paint ANSI escapes into my redirected output.

## Context

**The patterns already exist — propagate them.** The newer `llm/cli` subsystem (`chirp models …`, `chirp daemon …`) was built to clig.dev conventions; the older first-party commands (`record`, `transcribe`, `notes`, `ask`, `search`, the note editor) predate them. This story back-ports the established `llm/cli` patterns to those commands rather than inventing anything new.

- **stdout/stderr split is already solved in `llm/cli/_console.py:16-17`:**
  ```python
  console = Console(stderr=True)   # diagnostics, progress, hints, errors
  stdout_console = Console()       # data / rendered artifacts
  ```
  Its module docstring (`_console.py:1-10`) is the canonical rationale. `daemon.py` and `models.py` follow it (`daemon.py:69` imports both; tables → `stdout_console`, status/errors → `console`). But the older commands use a single `Console()`: `chirp/cli.py:59`, `notes_chat/cli.py:20`, `notes_chat/interactive.py:20`, and the renderers in `notes_chat/search_keyword.py` (which receive whatever `console` the caller passes — today the shared stdout one). Result: in `search`, the preamble + table + footer hints all land on stdout (`search_keyword.py:102-166`); in `notes`, the table + four `›` hint lines all land on stdout (`chirp/cli.py:659-664`); errors like `chirp/cli.py:710` print to stdout.

- **`--json` discipline is already solved in `daemon.py`/`models.py`:** `daemon.py:252-254` defines `_should_use_json(json_flag) -> json_flag or not stdout_console.is_terminal` (auto-JSON when piped), and JSON is written **raw** via `sys.stdout`/`stream.write` (`daemon.py:249`, `models.py:251`, `models.py:425`) — never through a Rich console. `chirp search` has `--json` (`chirp/cli.py:923-925`) but emits it via `console.print(emit_json(result))` (`chirp/cli.py:968`) on the shared Rich console, which risks reflow/markup mangling. `chirp notes` (the most scriptable list surface) and `chirp ask` have no `--json` at all.

- **Version is computed but not exposed:** `chirp/about.py:57-59` already does `pkg_version("chirp-notes-ai")` (falling back to `"dev"`), and renders it inside the 3-phase animation (`about.py:158`, `about.py:201`). But there is no top-level `@app.callback` in `chirp/cli.py` (verified — the app is created at `chirp/cli.py:47-58` with no callback), so `chirp --version`/`-V` does not exist, and `about` has no `--plain` non-animated mode.

- **AGENTS.md is binding here.** AGENTS.md §Documentation: "Keep command examples aligned with live `chirp --help` output and with `config/settings.py`." CLAUDE.md §Claude-Specific Reminders: "Validate doc updates against live CLI help before finishing." Every AC below that changes a flag or help surface includes a live-CLI verification command, and several include pipe-to-`cat`/non-TTY checks. CLAUDE.md §Current CLI Surface fixes the contract: visible commands are `record`, `transcribe`, `notes`, `ask`, `search`, `init`, `about`; hidden maintenance commands are `config`, `devices`, `index`, `daemon`. This story must not change which commands are visible.

**What's already good and must NOT regress:**
- The `chirp ask` interactive REPL's double-Ctrl-C-to-quit / single-Ctrl-C-clears-line model (`notes_chat/interactive.py:43-55`) and its `/help` slash screen (`interactive.py:162-166`) are correct. Don't touch the REPL interrupt semantics.
- `recorder/live_dashboard.py` already restores termios in `_raw_mode`'s `finally` (`live_dashboard.py:82-89`) and self-heals row count from `console.height` on every render (`_estimate_visible_lines`, `live_dashboard.py:327-342`), so it adapts to resize. The gap is the `record` waveform Live (`chirp/cli.py:344-360`), not the dashboard.

Files in scope: `chirp/cli.py`, `chirp/about.py`, `notes_chat/cli.py`, `notes_chat/interactive.py`, `notes_chat/search_keyword.py`, `notes/note_editor.py`, `utils/popup_manager.py`, and the wiring of `llm/cli/_console.py` (or an equivalent shared console seam) into the older commands. A new shared glyph/voice module is in scope for finding 9.

## Acceptance criteria

- **AC-1 — stdout/stderr discipline back-ported (HIGH).** Across `record`, `transcribe`, `notes` (list/view/edit/delete), `ask`, and `search`, **data** goes to stdout and **diagnostics** (progress, status, hints, errors, prompts) go to stderr, mirroring `llm/cli/_console.py:16-17`.
  - `chirp notes` (`chirp/cli.py:_list_notes`): the table is data → stdout; the "Your notes · N total" preamble, the four `›` hint lines (`chirp/cli.py:661-664`), and the "No notes found" message go to stderr.
  - `chirp search`: the per-note table and excerpt blocks are data → stdout; the header line, optional `scope:` line, match-summary, footer hints, and the no-matches/close-keywords panel go to stderr (the `search_keyword.py` renderers already take a `console` param at `search_keyword.py:97`/`171` — pass the right console for each part, or split the renderer).
  - Error paths print to stderr: `chirp/cli.py:710`/`714`, `chirp/cli.py:366`/`370`/`379`/`382`/`385`/`389`, `notes_chat/cli.py:130`/`160`/`193`/`198`/`204`/`210`/`214`.
  - **Verify (non-TTY split):**
    ```
    uv run chirp notes 1>/tmp/out 2>/tmp/err   # /tmp/out has only the table rows; hints land in /tmp/err
    uv run chirp search "pricing" 2>/dev/null  # only the table + excerpts reach the terminal; header/hints suppressed
    ```
  - **Regression guard:** existing tests assert hint lines on stdout (`tests/test_cli_commands.py:54,61,67,76-79`). Under Click 8.3 / Typer 0.24 (this repo), `CliRunner` separates `result.stdout` from `result.stderr` by default — those assertions must move to `result.stderr` when the hints move. Do not break them silently.

- **AC-2 — `--json` for `notes` and `ask`; raw, TTY-aware emission everywhere (HIGH).**
  - `chirp notes --json` emits a JSON array of notes (at minimum: `id` (the 1-based newest-first index `chirp notes` prints — same invariant as `chirp/cli.py:641` and story 1.3), `slug`, `title`, `date`, `tags`, and the notes-file path). With `--json`, no table and no hints render.
  - `chirp ask --json` (one-shot, with a question) emits a JSON object `{ "question": ..., "answer": ..., "sources": [...] }`. Streaming/markdown rendering is suppressed under `--json`. (Interactive mode is unaffected — `--json` only applies to the one-shot path.)
  - All JSON is written **raw** to `sys.stdout` (`sys.stdout.write(json.dumps(...) + "\n")`), NOT through a Rich console — match `daemon.py:249`/`models.py:251`. Fix `chirp search`'s existing `console.print(emit_json(result))` (`chirp/cli.py:968`) to write raw too.
  - Adopt the auto-JSON-when-piped helper from `daemon.py:252-254` (`json_flag or not stdout_console.is_terminal`) for these three commands, OR (decide once and document) keep JSON strictly opt-in via the flag. If auto-on-pipe is chosen, the human-readable render path stays the default on a TTY.
  - **Verify:**
    ```
    uv run chirp notes --json | jq '.[0].id'          # parseable; no Rich borders
    uv run chirp ask --json "what did we decide?" | jq '.answer'
    uv run chirp search --json "pricing" | jq '.matches | length'
    ```

- **AC-3 — `chirp --version` / `-V` (HIGH).** Add a top-level `@app.callback` to the Typer app (`chirp/cli.py:47-58`) with a `--version`/`-V` eager option that prints the version and exits 0. Reuse `chirp/about.py:_installed_version()` (or lift its `pkg_version("chirp-notes-ai")` + `PackageNotFoundError → "dev"` logic into a shared helper) so the value matches what `about` shows. Output is a single plain line to **stdout** (e.g. `chirp 0.0.1a0`), suitable for `chirp --version | …`.
  - Add `chirp about --plain` (or `--no-animate`): renders the same final info panel `about` shows (version, notes count, models, notes root — see `about.py:_info_lines`, `about.py:104-115`) without the 3-phase animation (`about.py:160-214`), for non-TTY / scripted use.
  - **Verify:** `uv run chirp --version` prints one line and exits 0; `uv run chirp -V` is identical; `uv run chirp --help` lists `--version`; `uv run chirp about --plain | cat` prints static text with no spinner frames.

- **AC-4 — uniform Ctrl-C/EOF prompt-escape in `record` (HIGH).** All three `record` prompts abort the command on Ctrl-C/EOF. Today only `_prompt_title` aborts (`chirp/cli.py:71-73`, `raise typer.Exit(1)`); `_prompt_timeframe` (`chirp/cli.py:89-91`) and `_prompt_tags` (`chirp/cli.py:105-107`) catch `(EOFError, KeyboardInterrupt)` and `return None`/`return []`, so Ctrl-C at the tags prompt silently proceeds to start a recording.
  - Make `_prompt_timeframe` and `_prompt_tags` re-raise the same abort as `_prompt_title` (print a newline, then `raise typer.Exit(1)`) on Ctrl-C/EOF. "Press ⏎ to skip" remains the only way to skip an optional prompt — Enter on an empty line still returns `None`/`[]`.
  - **Verify (manual):** run `chirp record`, reach the tags prompt, press Ctrl-C → command exits without starting a recording, leaves no `<slug>/` folder. Repeat at the timeframe prompt. (Skip with Enter still works.)

- **AC-5 — `NO_COLOR`/`FORCE_COLOR` + `--no-color`/`--plain` contract; fix editor `force_terminal` (MED).** There are zero `NO_COLOR`/`FORCE_COLOR`/`no-color` references in production code today (verified — only test-name matches in `tests/test_note_editor_extra.py`).
  - Honor `NO_COLOR` (any non-empty value disables color) and `FORCE_COLOR` per the de-facto contract; Rich's `Console` already reads these when constructed without an overriding `force_terminal`/`no_color`, so the fix is to **stop overriding them**, plus a `--no-color` (alias `--plain`) global option on the top-level callback that forces color off for the run.
  - Fix `notes/note_editor.py:636-638` — `Console(width=text_width, color_system="standard", force_terminal=True)` overrides `NO_COLOR` for the markdown render-cache path. This is an internal cell-measurement console (its output is re-emitted through curses), so confirm whether `force_terminal=True` is load-bearing for width measurement; if it is, gate color on the `NO_COLOR` env / `--no-color` flag while keeping the width measurement, rather than forcing terminal mode unconditionally.
  - **Verify:** `NO_COLOR=1 uv run chirp notes | cat -v` shows no `^[[` escape sequences; `uv run chirp --no-color search "x" | cat -v` likewise; `uv run chirp notes | cat -v` (piped, no flag) also has no escapes (Rich auto-detects non-TTY).

- **AC-6 — unified exit-code table (MED).** Centralize exit-code constants (e.g. a small `chirp/exit_codes.py` or constants in `chirp/exceptions.py`) and a documented table, then apply them uniformly. Today the scheme is partial and scattered: `notes_chat/cli.py` uses 2 = no documents (`cli.py:129`), 3 = daemon unreachable (`cli.py:196`), 5 = model not found (`cli.py:202`), 4 = model load failed (`cli.py:205`), 1 = everything else; `models.py` reuses 2/4/5; `transcribe` uses 2 for usage errors (`chirp/cli.py:472,478,484`); `init` uses a bespoke 7 (`EXIT_NOT_APPLE_SILICON`, `chirp/init_flow.py:45`); but `record` collapses every runtime error to `typer.Exit(1)` (`chirp/cli.py:380-390`).
  - Define and document: `0` success; `1` generic runtime error; `2` usage error (bad args/flags — Click's own convention); `3` daemon unreachable; `4` model load failed; `5` model not found; `7` not-Apple-Silicon (keep `init`'s existing value). Reserve a slot for "interrupted" if useful, or keep Ctrl-C as 1 (current behavior — `notes_chat/cli.py:207-208`).
  - Apply the constants at every existing `typer.Exit(...)` site so the numbers come from one place; do not silently renumber existing codes (3/4/5/7 are observable contracts).
  - Document the table in this story and in the relevant help/README surface per AGENTS.md.

- **AC-7 — SIGTERM/SIGWINCH handling + terminal restore (MED).** `record` sets cbreak via `termios`/`tty` and restores it in a `finally` (`chirp/cli.py:312-360`) — correct for SIGINT/normal exit — but there is no SIGTERM handler, so `kill <pid>` during a recording leaves the TTY in cbreak with the Rich `Live` cursor hidden.
  - Install a SIGTERM handler (scoped to the recording, restored on exit) that restores `termios` and shows the cursor on both the `record` waveform TUI and any path that enters cbreak. `recorder/live_dashboard.py` (`_raw_mode`, `live_dashboard.py:70-89`) already restores in `finally` but should also be SIGTERM-safe.
  - Make the `record` waveform view resize-safe: the dashboard recomputes from `console.height` each render (`live_dashboard.py:327-342`), but the `record` Live (`chirp/cli.py:344-360`) does not — handle SIGWINCH (or recompute width/height each tick) so a resize during a `record` waveform doesn't corrupt the view.
  - **Verify (manual):** start `chirp record`, `kill <pid>` from another shell → the terminal is left usable (cooked mode, cursor visible), no need to `reset`. Resize the window mid-record → waveform reflows without garbage.

- **AC-8 — note editor in-app help + `$EDITOR`/`$VISUAL` (MED).** `notes/note_editor.py` is a modal vim-like editor (`i` / `Esc` / `:wq` / `:q!`) with no persistent keybinding hint (the status line at `note_editor.py:247-259` shows only mode/line/col/dirty/message) and no help screen — an unknown `:` command just sets `"Unknown command: …"` (`note_editor.py:397`).
  - Add a persistent one-line keybinding hint to the status/footer area (e.g. `i insert · Esc normal · :wq save · :q! quit · :help`).
  - Add a `:help` command and a `?` key (in normal/view mode) that shows a help overlay listing modes and commands. Make the unknown-command message point at it (`… type :help`).
  - Respect `$EDITOR`/`$VISUAL`: add at minimum an opt-in escape hatch (e.g. `chirp notes edit N --editor` or a `:edit-external` command, or honor `$VISUAL`/`$EDITOR` when set) that hands the `notes.md` path to the external editor and re-reads on exit. Today `notes edit` always uses the built-in editor and ignores both env vars (verified — zero `EDITOR`/`VISUAL` references in the codebase). DECISION LOCKED 2026-06-15: keep the built-in modal editor as the default; the in-app help/hint above ships in this story, and the `$EDITOR`/`$VISUAL` handoff lands as an opt-in escape hatch (acceptable as a fast-follow if it slips this story). Do not change the default editor.
  - **Verify (manual):** open `chirp notes edit 1`, confirm the hint is visible, type `:help` and `?` and confirm the overlay; if the external hatch ships, `EDITOR=nano chirp notes edit 1 --editor` opens nano and saves back.

## Dev notes

- **clig.dev principles this story enforces:** "Send output to stdout… send messages to stderr" (AC-1); "If your program outputs data, support `--json`" and "don't print escape codes if output is piped / honor `NO_COLOR`" (AC-2, AC-5); "have a `--version`" (AC-3); "catch the signals" and "restore the terminal" / be "responsive" to resize (AC-4, AC-7); "make it easy to discover" — in-app help (AC-8); consistency of output and conventions (AC-6, AC-9). The point of the story is that `llm/cli` already meets these; we are propagating them, not designing them.
- **Don't regress the chat REPL.** `notes_chat/interactive.py:43-55` implements single-Ctrl-C-clears / double-Ctrl-C-quits with a 2s window and a self-clearing hint. That's deliberate REPL UX, distinct from the one-shot prompt-escape in AC-4. AC-4 is about the `record` *setup prompts* (`_prompt_*`), not the chat loop. Leave the REPL alone.
- **Don't regress `live_dashboard`.** It already restores termios (`:82-89`) and self-heals height (`:327-342`). AC-7's resize work targets the `record` waveform Live (`chirp/cli.py:344-360`), which lacks the dashboard's per-render height recompute. Don't reimplement what the dashboard already does — make the waveform borrow the same approach.
- **Alpha back-compat tradeoff.** Chirp is `0.0.1a0` (`pyproject.toml:7`) with no back-compat owed (PRD §Alpha-stage simplifications; story 7.5 dev notes removed `--ollama-url` wholesale on the same reasoning). The `--question/-q` "kept for backwards compatibility" option (AC-11) and `add_completion=False`'s stranded completer (AC-9) are both candidates for deletion rather than careful preservation. Prefer the simpler end state, but get the decision recorded (open questions below) rather than guessing.
- **What NOT to do:**
  - Don't change the visible 7-command surface or un-hide `config`/`devices`/`index`/`daemon` (CLAUDE.md §Current CLI Surface). Adding `--json`/`--version`/`--no-color`/`--plain` options is fine; adding new top-level commands is not.
  - Don't renumber the existing observable exit codes 3/4/5/7 (AC-6) — they're a contract; centralize them, don't change them.
  - Don't route raw JSON through a Rich console (the exact bug AC-2 fixes at `chirp/cli.py:968`). `json.dumps` → `sys.stdout.write`.
  - Don't add timestamps to `transcript.txt` or otherwise expand scope into the search/transcribe pipelines — those are out of scope (story 1.8 deviation note stands).
  - Don't build a heavy theming system for AC-5/AC-9 — `NO_COLOR` honoring is mostly *removing* `force_terminal` overrides; glyph consistency is a small constants module.
- **Finding accuracy corrections (verified against source 2026-06-14):**
  - Finding 9 attributes `✅`/`❌` emoji to "`devices`/`init`". Verified: the emoji are in the **`devices`** command (`chirp/cli.py:1171-1191`); **`init`** (`chirp/init_flow.py:270-277`) uses the text glyphs `✓`/`✗`/`—`. So `init` is on the *correct* side of the glyph split — the fix is to bring `devices` in line with `init`/`search`, not the reverse.
  - Finding 6 says usage(2)-vs-runtime separation "is partial." Verified more precisely: `transcribe` already uses `Exit(2)` for usage errors (`chirp/cli.py:472,478,484`) and `search` uses `Exit(2)` for bad query/`--since`/`--regex` (`chirp/cli.py:940,948,955`); the gap is `record` (everything → `Exit(1)`, `:380-389`) and the absence of a documented, centralized table — not that 2-vs-runtime is wholly missing.
  - Finding 1 cites `search_keyword.py` as using a single `Console()`: verified the module has **no** module-level console — its renderers receive `console` as a parameter (`:97`,`:171`), so the contamination originates at the `chirp search` call site passing the shared stdout console (`chirp/cli.py:972,977`). The fix lives at the call site / renderer split, not a module global.
