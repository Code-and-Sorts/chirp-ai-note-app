## User story

As a **chirp user who hand-edits `~/.chirp/config.toml`**, I want a typo in a single field (e.g. `warning_minutes = "soon"`) to degrade gracefully — a clear warning telling me which field is bad and where the file lives, then defaults for that field — instead of a raw `pydantic.ValidationError` traceback that bricks *every* `chirp` command (record, transcribe, notes, ask, search, init, about) at settings-load time.

As a **contributor opening a PR**, I want CI to *enforce* the coverage bar it already measures, so my change cannot silently drop total coverage (currently 83%) — and I want both the main-branch and PR workflows to measure the *same* package set so coverage numbers mean the same thing on both paths.

As a **maintainer**, I do not want Renovate to auto-merge an exact-pin bump of the ML deps (`mlx-lm`, `mlx-embeddings`) — the only deps whose real code path is `# pragma: no cover` — on a green check that never exercised real inference, silently shipping broken `chirp ask` / note-generation.

## Acceptance criteria

- **AC-1 — A malformed config *value* cannot brick the CLI.** Given a `config.toml` with a bad type on a known field (canonical case: `[monitoring]\nwarning_minutes = "soon"`), `ChirpSettings.load_from_file` must **not** raise. It returns a usable `ChirpSettings` and emits a clear warning **to STDERR** that (a) names the offending field/section, (b) states the value was ignored and a default used, and (c) prints the config file path. Implementation: catch `pydantic.ValidationError` in `load_from_file` (`config/settings.py:179-182`). Prefer **per-field** recovery — drop only the invalid field(s) and re-validate, preserving every valid field — over a wholesale fall-back to all-defaults. Use `ValidationError.errors()` to identify offending `loc` paths and warn per field. STDERR (not STDOUT) keeps the warning out of `--json`/piped output (consistent with story 8.5's stream-separation work). The existing `init`-coercion validator (`config/settings.py:145-153`) stays; this AC is the general case around it.

- **AC-2 — A bad type on a nested field degrades to that field's default, not all-defaults.** Given `[notes_chat]\nk = "ten"` plus a valid custom `directories.notes_root`, the loaded settings keep the custom `notes_root` and use the default `k = 10`. (Verifies per-field recovery, not a blanket reset that would silently discard the user's other valid overrides.)

- **AC-3 — `schema_version` stamp + warn-on-unknown-keys.** Add a `schema_version: int` field to `ChirpSettings` (default = current `SUPPORTED_CONFIG_SCHEMA_VERSION = 1`), written by `save_to_file` and read by `load_from_file`, mirroring the `llm/registry.py:26,49,75-86` pattern. Behavior (alpha-simplified, **no migration pipeline**):
  - On load, if the file has **no** `schema_version`, treat it as v1 and proceed (back-compat for existing configs), optionally restamping on next save.
  - On load, if `schema_version` is present but **unknown** (≠ supported), warn to STDERR pointing the user at the config path and how to reset (delete the file / re-run `chirp init`), then continue with best-effort defaults — do **not** hard-crash the CLI (config is not the registry; bricking every command is exactly the failure mode AC-1 forbids).
  - Warn to STDERR on **unknown top-level keys** (pydantic-ignored today) so a renamed/typo'd section is visible instead of silently dropped. Implementation hint: `model_config = ConfigDict(extra="ignore")` is the default; compare parsed-TOML top-level keys against the model's known field names and warn on the difference.

- **AC-4 — A coverage floor exists and fails CI on regression.** `--cov-fail-under` is enforced on the gating path(s). Single source of truth: `pyproject.toml [tool.coverage.report] fail_under = <floor>`. With the floor set, a run whose total coverage drops below it must exit non-zero. **Floor value (OQ1):** set at or just below the verified current TOTAL of **83%** — recommend **`fail_under = 80`** as the conservative initial floor (absorbs normal run-to-run variance from the `# pragma: no cover` MLX paths and platform-skipped audio tests), to be ratcheted toward 83%+ after 8.5 lands. Do not set it *above* current coverage (that breaks `main` on day one). [Source: prd.md:567 NFR-M1 "Coverage on touched existing modules does not regress"; prd.md:93,:106; architecture.md:54.]

- **AC-5 — Both gating workflows measure the same package set.** `.github/workflows/main-build.yml:24` is changed from the hand-listed `--cov=chirp --cov=config --cov=recorder --cov=transcriber --cov=notes --cov=utils` to the **full pyproject `source` set** — preferably bare `--cov` (which reads `pyproject.toml:143-149`), matching `shared-build-and-test.yaml:157`. After the change, both workflows report coverage over all 10 packages (`audio_capture, chirp, chirpd, config, llm, notes, notes_chat, recorder, transcriber, utils`). The floor (AC-4) applies to this aligned set.

- **AC-6 — The coverage floor is honored locally too.** `Makefile` `test-coverage` (`Makefile:70-71`) produces a build that fails when below the floor (it will, automatically, once `fail_under` is in `pyproject.toml` — confirm with a comment or an explicit `--cov-fail-under` for discoverability). `make ci` (`Makefile:123`) runs the test step **with coverage** so local CI parity actually checks the floor (today `make ci` → `test` runs no coverage).

## Dev notes

- **Alpha-appropriate scope — do NOT over-build config migration.** Architecture.md is explicit: "No migration pipeline in MVP — chirp is alpha and the user re-creates the registry across breaking schema changes." [Source: architecture.md:527, :318]. A `schema_version` *stamp* + warn-on-unknown-version/keys is the entire ask. **Difference from the registry:** the registry *rejects* an unknown version with a typed error (`llm/registry.py:75-86`) because a malformed registry is recoverable via `chirp models add`. The **config** must NOT hard-crash on an unknown version — bricking every command is the exact AC-1 failure mode. So: registry = reject-and-raise; config = warn-and-continue-with-defaults. Don't copy the raise.
- **Per-field recovery > all-defaults.** AC-2 exists to stop a lazy implementation that catches `ValidationError` and returns `cls()` — that silently discards a user's *valid* `notes_root`, `index_dir`, etc. just because one field had a typo. Use `ValidationError.errors()[*]["loc"]` to surgically drop only the bad fields. If iterative drop-and-revalidate is too fiddly, an acceptable middle ground is per-section recovery (drop the offending table, keep the rest) — but never blanket-reset.
- **STDERR, not STDOUT.** `config/settings.py:169` currently uses `console = Console()` (stdout) for the "creating default config" message. The *warning* path must go to stderr (`Console(stderr=True)`) so it never pollutes `--json` / piped output. This dovetails with story 8.5's stdout/stderr split — keep them consistent.
- **Why `fail_under = 80` and not 83 (OQ1).** Current TOTAL is 83% but the MLX `# pragma: no cover` paths (`chirpd/backend.py:51,77,109,166,228,276`) and platform-skipped audio tests introduce run-to-run/platform variance; a floor *at* 83 risks flaky red on `main`. 80 is a safe initial floor that still catches real regressions, with an explicit ratchet plan: bump to 83 after 8.5 lands and `chirp/cli.py` rises from 55%. Pick the final number with the maintainer (OQ1).
- **Why align the `--cov` sets (AC-5).** Two gates measuring different package sets means "coverage" is ambiguous — a regression in `chirpd`/`llm`/`notes_chat`/`audio_capture` is invisible on the `main` push gate (`main-build.yml:24` omits all four) but visible on the PR gate. The floor is meaningless if the two paths disagree on what's counted. Bare `--cov` reads `pyproject.toml:143-149` and is the single source of truth.
- **Codecov is not the floor.** `main-build.yml:43` `fail_ci_if_error: false` means Codecov can't gate even if configured to. The enforcement is pytest-cov's `--cov-fail-under` (offline, deterministic, no external service). Don't try to make Codecov block; keep it informational.
- **mypy: staged, never big-bang.** NFR-M3 (prd.md:569) wants type discipline on *new public APIs*, not a strict flip across 10 packages with `ignore_missing_imports = false` (MLX/chromadb/silero have no stubs — that flip would drown the gate in `import-untyped` noise).
