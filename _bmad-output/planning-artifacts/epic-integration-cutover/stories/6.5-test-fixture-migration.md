# Story 6.5 — Migrate `tests/notes/` and `tests/notes_chat/` fixtures from Ollama mocks to `FakeBackend` / mocked `llm.client`

- **Status:** Draft
- **Epic:** [EPIC-INTEGRATION-CUTOVER](../epic.md)
- **Depends on:** 6.2, 6.3, 6.4 (all three cutover stories merged; production code no longer touches Ollama in these modules)
- **Blocks:** 6.6 (regression run) — only loosely; 6.6 does not depend on test fixtures, but landing 6.5 first keeps the suite tidy for the regression-run commit. May overlap or land after 6.6 if scheduling demands.

## Prerequisites

- Stories 6.2, 6.3, and 6.4 are merged. Production code in `notes/` and `notes_chat/` no longer calls Ollama directly; every LLM-touching call site now imports `llm.client`.
- The transitional test fixtures left in place by 6.2 / 6.3 / 6.4 (either mocking `client.chat` / `client.embed` directly at the call site, or leaving residual `requests.post` mocks for tests that haven't been touched) are still functional and the suite is green.

## User story

As a chirp maintainer, I want every test under `tests/notes/` and `tests/notes_chat/` that previously stubbed the Ollama HTTP API to use either the architecture's `FakeBackend` (via an in-process daemon-under-test) or a mocked `llm.client` at the call-site boundary, so that the test suite reflects the new client surface, mirrors the architecture's stated testing pattern, and is free of dead Ollama-shaped fixtures that would silently rot.

## Context

Architecture §Testing Patterns is explicit:

> **Backend abstraction for unit tests.** The daemon's inference layer sits behind a `LLMBackend` protocol […]. **Unit tests use `FakeBackend`.** No `mlx-lm` import required to run the daemon's unit tests. […] **Integration tests use an in-process socket.** Start the daemon in the same Python process via `asyncio.start_unix_server(...)` against a temp socket; connect from the test with `chirp.llm.client(socket_path=...)`.

The architecture also has an explicit anti-pattern:

> **Mock the MLX module in unit tests** — don't. Use `FakeBackend` at the `LLMBackend` protocol boundary instead.

For `tests/notes/` and `tests/notes_chat/`, two test-shaping decisions matter:

1. **Where to mock.** Either mock `llm.client.chat` / `llm.client.embed` at the call site inside `notes/` or `notes_chat/` (so tests are pure-Python with no socket), **or** stand up an in-process `chirpd` instance with a `FakeBackend` and let tests speak the wire protocol. Per the epic's locked decision 10: pick the simpler option per test — don't over-engineer.

2. **What to retire.** The old fixture shape (mocking `requests.post` at module level, asserting on JSON request bodies, returning canned Ollama response shapes) is dead code after 6.2 / 6.3 / 6.4. This story retires those fixtures.

In practice, for `tests/notes/` and `tests/notes_chat/`, **mocking `llm.client` at the call-site boundary is the simpler option** for almost every test. The in-process daemon pattern is heavier: it requires socket setup, lifecycle management, and async coordination — useful when testing the protocol or the daemon itself (covered by `tests/chirpd/` and `tests/llm/` under EPIC-CHIRPD-CORE), not for testing prompt assembly or retrieval logic. This story therefore standardizes on the **mocked-client** pattern across `tests/notes/` and `tests/notes_chat/`, with one or two designated integration tests using the in-process daemon to exercise the full wire path.

## Acceptance criteria

- **AC-1** No test in `tests/notes/` or `tests/notes_chat/` patches `requests.post`, `requests.get`, or any other `requests.*` call to simulate Ollama. `rg -n "requests\.(post|get|put|delete)" tests/notes/ tests/notes_chat/` returns zero matches.
- **AC-2** No test in `tests/notes/` or `tests/notes_chat/` references `ollama_url`, `/api/generate`, `/api/embeddings`, or fabricates Ollama-shaped response JSON (`{"response": "...", "done": true}` for generation, `{"embedding": [...]}` for embeddings). `rg -n "ollama|/api/generate|/api/embeddings" tests/notes/ tests/notes_chat/` returns zero matches.
- **AC-3** A shared fixture module `tests/notes_chat/conftest.py` (extended if it exists; created if not) provides reusable test doubles:
  - `fake_client_chat(*, deltas: list[str], on_complete: Optional[Callable] = None)` — returns a callable that mimics `llm.client.chat(stream=True)`, yielding objects with a `.text` attribute. Use a small dataclass or `types.SimpleNamespace` to model the delta.
  - `fake_client_chat_nonstream(*, text: str)` — mimics `llm.client.chat(stream=False)`, returning an object with a `.text` attribute.
  - `fake_client_embed(*, vectors: list[list[float]])` — mimics `llm.client.embed(inputs=[...])`. Asserts the input-to-output ordering of the returned vectors matches the input order if `len(inputs) > 1`.
  - `raise_llm_error(error_cls: type[LLMError], message: str = "test error")` — returns a callable that raises the given typed exception when invoked. Useful for asserting error-path behavior without committing to a specific transport / protocol / model failure mode in every test.
  - These helpers take advantage of `monkeypatch.setattr` to install themselves at the import point inside the module under test (e.g., `notes_chat.retrieval.client.embed`).
- **AC-4** Every test in `tests/notes/test_note_generator*.py` that previously asserted on the Ollama HTTP call now asserts on the `client.chat` call via the AC-3 fixtures. Specifically:
  - The transitional fixtures from story 6.2 are replaced (or kept, if they already follow the AC-3 pattern) with calls to `fake_client_chat` / `fake_client_chat_nonstream`.
  - Tests for the `_call_llm` helper / `_generate_structured_notes` flow use `fake_client_chat` and assert: prompt content, model resolution (`"default"`), options dict shape, joined-token return value.
  - At least one test asserts behavior on `LLMModelError` (using `raise_llm_error`).
- **AC-5** Every test in `tests/notes_chat/test_retrieval*.py` and `tests/notes_chat/test_*embed*.py` that previously asserted on the Ollama embeddings HTTP call now uses `fake_client_embed`. Specifically:
  - `_get_query_embedding` tests use `fake_client_embed(vectors=[[0.1, 0.2, ...]])` and assert the function returns the first vector.
  - At least one test exercises the 3-element ordering case from story 6.3's AC-11, now in canonical fixture form.
  - At least one test asserts `_get_query_embedding` returns `None` on `LLMError` using `raise_llm_error`.
- **AC-6** Tests for the interactive chat path (`tests/notes_chat/test_interactive*.py` and `tests/notes_chat/test_prompting_stream.py`) use `fake_client_chat` (streaming variant). The cancel-on-Ctrl-C test from story 6.4 (`test_interactive_cancel.py`) is refactored to use the shared fixture if it isn't already.
- **AC-7** **At least one integration test** in `tests/notes_chat/test_integration_inprocess_daemon.py` (new file) stands up an in-process daemon-under-test with `FakeBackend` per architecture §Testing Patterns and exercises one end-to-end flow:
  - Connect from the test with `llm.client(socket_path=tmp_socket)`.
  - Issue a `chat` request with a single user-message containing a known prompt.
  - Receive the scripted token sequence from `FakeBackend` over the socket.
  - Assert the final joined text matches the expected scripted output.
  - This test is marked `@pytest.mark.integration` so it can be excluded from the fast `make test` slice if needed; current convention is that integration tests run as part of `make test` unless explicitly skipped.
- **AC-8** Any helper-function-only tests in `tests/notes_chat/test_prompting*.py` covering helpers in `notes_chat/prompting.py` that **remain on Ollama** for the duration of this epic (per story 6.4 AC-5's deferred-cleanup list) are flagged with a `# TODO(EPIC-INIT-AND-MIGRATION): remove when prompting.py is fully migrated` comment. Their fixtures continue to use whatever mocking they currently do — this story does not migrate them. The TODO comment makes the deferred work discoverable later.
- **AC-9** Coverage on `notes/note_generator.py`, `notes_chat/retrieval.py`, `notes_chat/index.py`, `notes_chat/cli.py`, `notes_chat/interactive.py`, and the migrated portion of `notes_chat/prompting.py` is **≥** the pre-cutover baseline (NFR-M1). The fixture migration must not silently shed test coverage. The coverage report from `make test-coverage` is compared against the pre-cutover baseline captured before story 6.2 merged.
- **AC-10** `mlx_lm.*` is never mocked or imported anywhere in the test files this story touches (anti-pattern per architecture §Anti-Patterns to Avoid). `rg -n "mlx_lm" tests/notes/ tests/notes_chat/` returns zero matches.

## Dev notes

- **Why mock at the call-site boundary, not in-process daemon, for ~all tests.** The architecture explicitly allows both patterns and tells us to "pick the simpler option per test." For tests in `tests/notes/` and `tests/notes_chat/`, the unit under test is the chirp module (`notes.note_generator`, `notes_chat.retrieval`, etc.), not the wire protocol or daemon behavior. Mocking `llm.client` at the chirp-module's import point is one line per test; standing up an in-process daemon is a setup-teardown fixture with async coordination. The latter pays off when there's something interesting to test about the wire (e.g., the protocol's error handling, FR23 error mapping) — that's `tests/llm/` and `tests/chirpd/` territory, owned by EPIC-CHIRPD-CORE.
- **Why one integration test in this epic.** AC-7's in-process daemon test exists so we have at least one end-to-end smoke covering the full call path from a `notes_chat`/`notes` module through `llm.client` through the daemon to `FakeBackend` and back. It's not exhaustive — the daemon's own tests in EPIC-CHIRPD-CORE cover the protocol — but it catches integration regressions that pure unit tests would miss (e.g., a future client-side refactor that changes how `chat(stream=True)` is consumed).
- **Why the shared fixtures live in `tests/notes_chat/conftest.py`.** Both `tests/notes/` and `tests/notes_chat/` use them, but `notes_chat/` is where the streaming + cancellation tests live and is the more natural home. `tests/notes/` imports the fixtures by declaring them in a parameter; pytest discovers them across the `conftest.py` chain automatically.
- **Why a `_FakeDelta` rather than a `MagicMock`.** Tests that assert `delta.text` against a plain `MagicMock` silently pass on any attribute access — even ones the production code shouldn't be touching. A dataclass with one field locks the contract: production code that probes other attributes fails loudly during the test.
- **Why a conventions test.** Without it, a future developer adding a "let me just patch `requests.post` real quick" test would silently re-introduce the dead-fixture shape. The conventions test costs ~15 lines and prevents drift.
- **Why coverage cannot regress.** PRD NFR-M1 says "Coverage on touched existing modules does not regress." This story is the first one in the epic that explicitly touches the test surface in a way that could shed coverage (the cutover stories preserved tests as-is with transitional mocks). Comparing the per-file coverage report against the pre-6.2 baseline is the gate.
- **What about `tests/notes_chat/test_prompting.py`?** If it exists and exercises helpers like `generate_conversational_response` or `orchestrate_search` (which remain on Ollama for the duration of this epic per the epic doc's call-site inventory), those tests stay as-is with a TODO comment. They will be retired by EPIC-INIT-AND-MIGRATION when the helpers themselves are removed or migrated.
- **What about `tests/notes/test_note_generator.py` (general)?** Audit-time discovery may turn up tests that don't touch the LLM call at all (e.g., tests for `_strip_front_matter`, `_apply_front_matter`, `_parse_xml_response`). Leave those untouched. The migration is targeted at LLM-touching tests only.
- **`make test-coverage` baseline capture.** If story 6.2 didn't capture a baseline coverage report before merging, the implementer can re-create it by checking out the commit immediately preceding 6.2's merge, running `make test-coverage`, saving the output, then returning to `HEAD`. The baseline is for comparison, not committed.
